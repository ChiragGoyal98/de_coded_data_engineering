SDK patterns for production-grade AI integrations

Integrating Large Language Models (LLMs) into an application often starts with a simple script that sends a prompt and receives a response. However, moving from a hobbyist project to a production-grade system requires a more structured approach. A Software Development Kit (SDK) provides the tools needed to interact with these models efficiently, but simply installing the library is not enough. To build reliable AI features, developers must adopt specific patterns that handle the unpredictability of remote APIs while maintaining clean and maintainable code.

Why it matters

When you move from a "playground" environment to a live application, the stakes change. Production-grade code must be resilient against external failures and easy for a team to manage.

  • Stability: LLM APIs can be flaky. Without proper retry patterns, a single network hiccup can crash your user's experience.
  • Scalability: Poorly structured API calls can lead to "rate limit" errors where the provider blocks your requests because you sent too many at once.
  • Security: Hardcoding API keys is a common beginner mistake that leads to compromised accounts and high bills.
  • Predictability: LLMs are non-deterministic. Using SDK patterns like structured output ensures your code knows exactly what to expect from the model.

Step-by-step walkthrough

Building a production-grade integration involves wrapping the vendor's SDK in a way that protects your application. Follow these steps to set up a robust pattern.

1. The Singleton Client Pattern

Avoid creating a new instance of the AI client every time you want to send a prompt. Instead, initialize the client once and reuse it across your application. This manages connections more efficiently.

2. Environment Configuration

Never pass your API key directly into the client constructor. Use environment variables (like a .env file) to store keys. The SDK should pull these during the initialization phase.

3. Implementing Resiliency (Retries and Timeouts)

Production APIs will eventually time out or return a 500 error. Most modern SDKs (like OpenAI or Anthropic) have built-in retry logic, but you should explicitly configure it to define how many times to try and how long to wait between attempts (exponential backoff).

4. Wrapper Functions for Logic

Don't leak the SDK details into your business logic. Create a wrapper function that takes simple inputs and returns a clean result.


import os
from openai import OpenAI
from dotenv import load_dotenv

# Load keys from .env file
load_dotenv()

# Singleton pattern: Initialize the client once
client = OpenAI(
    api_key=os.getenv("OPENAI_API_KEY"),
    max_retries=3, # Production-grade resiliency
    timeout=20.0   # Prevent the app from hanging forever
)

def get_ai_summary(text_input):
    try:
        response = client.chat.completions.create(
            model="gpt-3.5-turbo",
            messages=[{"role": "user", "content": f"Summarize: {text_input}"}]
        )
        return response.choices[0].message.content
    except Exception as e:
        # Proper error handling for production logs
        print(f"Logging error for monitoring: {e}")
        return "Service temporarily unavailable."

5. Structured Output

To make the AI's response useful for your code, ask the SDK to return JSON or use a tool like Pydantic. This ensures that the "summary" isn't just a string of text, but a data object your app can actually use.

Common mistakes

  • Exposing Keys to the Frontend: Never call an LLM SDK directly from a browser or mobile app. This exposes your API key to the world. Always call the SDK from a secure backend server.
  • Ignoring Token Limits: Every LLM has a "context window." Beginners often forget to truncate or manage the size of the input text, leading to "context length exceeded" errors in production.
  • Lack of Logging: If an AI response is "weird," you need to know what prompt caused it. Always log the inputs and outputs (while being careful not to log sensitive user data).
  • Hardcoding Model Versions: Providers frequently deprecate old models. Use a configuration file to store the model name (e.g., gpt-4o) so you can update it without changing your code.

One practice task

Set up a Python environment and create a script that uses a .env file to store an API key. Write a function that attempts to call an LLM API but includes a try/except block specifically designed to catch a "Rate Limit" error. If the rate limit is hit, have the function print "Please wait a moment" instead of crashing the program.
