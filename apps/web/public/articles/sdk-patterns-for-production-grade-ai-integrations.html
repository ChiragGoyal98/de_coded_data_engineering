SDK patterns for production-grade AI integrations

Integrating Large Language Models (LLMs) into a software product often starts with a simple API call. However, moving from a prototype to a production-grade application requires more than just sending a prompt and receiving a string. Production systems must be resilient, observable, and easy to maintain. Software Development Kit (SDK) patterns provide the structural blueprint needed to handle the unpredictable nature of external AI services while ensuring your application remains stable for end-users.

Why it matters

When you use an LLM API in production, you are relying on a third-party service that can fail, slow down, or return unexpected data formats. Relying on "naked" API calls scattered throughout your codebase leads to several risks:

  • Fragility: If the provider changes their response structure or goes down, your entire app crashes.
  • Security: Hardcoding API keys or configuration settings leads to vulnerabilities.
  • Cost and Performance: Without centralized control, you might make redundant calls or fail to implement necessary timeouts.
  • Debugging: It is difficult to track why a specific prompt failed if every call is handled differently.

Step-by-step walkthrough

Building a production-grade integration involves wrapping the provider's SDK in a way that suits your specific business logic. Here is how to structure your integration.

1. Centralized Client Initialization

Never instantiate your AI client inside a function that handles a web request. Instead, use a Singleton pattern or a centralized configuration module. This ensures that settings like timeouts and retry logic are consistent across your entire application.

2. Implement a Wrapper Class

Create a dedicated class (e.g., AIEngine or LLMClient) that wraps the official SDK. This allows you to swap providers (e.g., moving from OpenAI to Anthropic) by changing the code in one place rather than searching through dozens of files.

3. Add Robust Error Handling

Production code must anticipate errors. Common LLM API errors include rate limits (429), authentication issues (401), and server errors (500). Use a "try-except" block coupled with an exponential backoff strategy, which waits longer between each retry attempt.

4. Enforce Structured Outputs

LLMs are non-deterministic. To ensure your application can process the data, use SDK features like "JSON Mode" or tools like Pydantic in Python to validate that the response matches the expected schema before it reaches your front end.

Code Example: A Production-Ready Wrapper


import os
from openai import OpenAI, APIError

class LLMService:
    def __init__(self):
        # Initialize client once with environment variables
        self.client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

    def generate_summary(self, text):
        try:
            response = self.client.chat.completions.create(
                model="gpt-4o",
                messages=[{"role": "user", "content": f"Summarize: {text}"}],
                timeout=10.0  # Always set a timeout
            )
            return response.choices[0].message.content
        except APIError as e:
            # Handle specific API errors and log them
            print(f"AI Provider Error: {e}")
            return "Service temporarily unavailable."

# Usage
ai_service = LLMService()
summary = ai_service.generate_summary("Long technical article content...")

Common mistakes

  • Ignoring Timeouts: By default, some SDKs wait indefinitely for a response. In production, this can hang your entire server. Always set a maximum timeout (e.g., 10-30 seconds).
  • Leaking Secrets: Never check your API keys into version control (GitHub). Use .env files or a secret management service.
  • Over-reliance on "Raw" Strings: Processing the raw text from an LLM without validation often leads to "undefined" errors in your UI. Always validate the shape of the data.
  • Skipping Logs: Not logging the "Prompt ID" or "Request ID" provided by the SDK makes it impossible to troubleshoot quality issues later with the provider's support team.

One practice task

Create a Python script that uses a mock function to simulate an LLM API call. Wrap this function in a class that includes a "retry" loop. The loop should attempt the call up to three times if it fails, waiting two seconds between each attempt. If it fails a third time, it should return a "Fallback Message" instead of crashing the program.
