SDK patterns for production-grade AI integrations

When moving from a simple script to a real-world application, the way you interact with Large Language Model (LLM) APIs changes significantly. In a local environment, a failed request is a minor inconvenience, but in production, it can lead to a broken user experience. SDK patterns are structured ways of organizing your code to ensure your integration is resilient, maintainable, and cost-effective. These patterns act as a bridge between your application logic and the raw API, handling the complexities of network communication and data formatting behind the scenes.

Why it matters

Integrating an LLM isn't just about sending a prompt and getting a response. Production environments demand reliability and predictability. Without proper SDK patterns, your application might crash during a minor API outage, or you might end up with "spaghetti code" that is impossible to update when a new model version is released.

By implementing standardized patterns, you gain:

  • Resilience: Your app can automatically recover from temporary network glitches.
  • Observability: You can easily track how many tokens you are using and how much they cost.
  • Flexibility: You can swap one model provider for another without rewriting your entire codebase.
  • Security: You ensure sensitive API keys are handled correctly across different environments.

Step-by-step walkthrough

1. The Client Singleton Pattern

Instead of creating a new API client instance every time you want to generate text, you should use a Singleton pattern. This ensures that a single client instance is reused throughout your application's lifecycle, which is more efficient for managing connection pools.

2. Implement Exponential Backoff

API providers often impose rate limits. If you send too many requests too quickly, the API will return an error. A production-grade SDK setup uses "exponential backoff," which means if a request fails, the system waits a short time before trying again, increasing the wait time with each subsequent failure.

3. Set Strict Timeouts

LLMs can sometimes take a long time to respond. Without a timeout, your application might hang indefinitely, waiting for a response that will never come. Always define a maximum wait time (e.g., 30 seconds) after which the request is cancelled.

4. Use Structured Output Wrappers

LLMs are non-deterministic, meaning they might return text in slightly different formats. To make this work in production, use a pattern that forces the SDK to parse the response into a structured format (like a JSON object or a Pydantic model) before it reaches your business logic.

Code Example: A Resilient Wrapper

This example demonstrates how to wrap a standard API call with basic retry logic and a timeout using Python.


import openai
from tenacity import retry, stop_after_attempt, wait_exponential

class AIService:
    def __init__(self, api_key):
        # Initialize the client once (Singleton-style)
        self.client = openai.OpenAI(api_key=api_key)

    # Automatically retry up to 3 times with increasing delay
    @retry(wait=wait_exponential(multiplier=1, min=2, max=10), stop=stop_after_attempt(3))
    def get_completion(self, prompt):
        response = self.client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": prompt}],
            timeout=15.0  # Set a 15-second timeout
        )
        return response.choices[0].message.content

# Usage
ai = AIService("your-api-key")
print(ai.get_completion("Explain SDKs in one sentence."))

Common mistakes

  • Hardcoding API Keys: Never put your API keys directly in your code. Always use environment variables or a secret management service.
  • Ignoring Token Limits: Every model has a "context window." Failing to check the length of your input before sending it to the SDK will result in frequent 400 Bad Request errors.
  • Lack of Logging: In production, you need to know why a request failed. Many beginners forget to log the specific error codes (like 429 for rate limits or 500 for server errors) returned by the SDK.
  • Blocking the Main Thread: In web applications, making a slow API call can freeze the user interface. Always use asynchronous patterns (like async/await) for AI integrations.

One practice task

Create a "Model Factory" class. This class should have a method that takes a string (like "fast" or "cheap") and returns a configured SDK client for a specific model based on that string. For example, if you pass "cheap," it returns a client configured for GPT-4o-mini; if you pass "powerful," it returns a client for GPT-4o. This helps you abstract the specific model names away from your main application logic.
