Azure Data Factory orchestration patterns

Azure Data Factory (ADF) is a cloud-based data integration service that allows you to create data-driven workflows for orchestrating and automating data movement and data transformation. Think of orchestration as the conductor of an orchestra, ensuring that every instrument plays at the right time and in the right sequence. In the world of data engineering, orchestration ensures that your data moves from source to destination accurately, even when the process involves multiple complex steps across different platforms like SQL databases, Blob storage, and Spark clusters.

Why it matters

Effective orchestration is the backbone of any reliable data platform. Without structured patterns, data pipelines become "spaghetti code"-tangled, difficult to debug, and prone to failure. By using established orchestration patterns, you gain:

  • Resilience: Your pipelines can handle intermittent failures through retries and error-handling paths.
  • Efficiency: You can run independent tasks simultaneously (parallelism) to reduce total processing time.
  • Maintainability: Standardized patterns make it easier for other team members to understand and update the workflows.
  • Cost Control: Better orchestration prevents unnecessary compute usage by ensuring tasks only run when their prerequisites are met.

Step-by-step walkthrough

When building in ADF, you will typically use a combination of these four fundamental patterns.

1. The Sequential Chain

This is the most basic pattern where activities run one after another. You create this by dragging the green "Success" connector from one activity to the next. Use this when the second task strictly depends on the output of the first.

  • Example: Extracting data to a CSV, then loading that CSV into a database.

2. Parallel Processing (Fan-out)

If you have five different tables to copy and they don't depend on each other, do not run them sequentially. Instead, connect them all to a single starting trigger or activity. ADF will execute them at the same time, significantly cutting down your "wall-clock" time.

3. Conditional Branching

Use the If Condition or Switch activity to decide which path the pipeline should take based on a variable or the result of a previous step.

  • If Condition: Great for binary choices (e.g., if "FileExists" is true, process it; otherwise, send an email).
  • Switch: Best for multiple categories (e.g., if the file type is "Sales," go to Pipeline A; if "HR," go to Pipeline B).

4. Iterative Processing (ForEach)

When you need to perform the same action on a list of items (like 50 different Excel files), use the ForEach activity. This acts like a loop in programming. Inside the ForEach container, you define the logic once, and ADF repeats it for every item in your input list.

Code Example: Defining Dependencies

In ADF, these patterns are defined in the JSON code of the pipeline. Here is how a simple dependency (Sequential Pattern) looks:


{
    "name": "TransformData",
    "type": "DataFlow",
    "dependsOn": [
        {
            "activity": "CopyFromSource",
            "dependencyConditions": ["Succeeded"]
        }
    ]
}

Common mistakes

  • Hardcoding values: Beginners often type file names or database strings directly into activities. Use Parameters and Variables to make your orchestration flexible.
  • Ignoring "On Failure" paths: Most people only connect the green (success) line. Always consider what should happen if a task fails. Should you send a Slack notification? Should you run a cleanup script?
  • Giant pipelines: Avoid putting 20+ activities in one pipeline. It becomes unreadable. Instead, use the Execute Pipeline activity to call smaller, modular sub-pipelines.
  • Not setting Retries: Cloud environments can have "transient" glitches. Set your activities to retry 1-3 times with a short interval to make your orchestration more robust.

One practice task

The "Safe Ingest" Challenge:

Try to build a pipeline in your ADF instance (or map it out on paper) that performs the following logic:

  • Lookup: Check a SQL table for a list of filenames to import.
  • ForEach: Loop through that list.
  • Copy: Inside the loop, copy the file from Azure Blob Storage to a SQL Database.
  • Conditional: If the Copy activity succeeds, move the file to an "Archive" folder. If it fails, send a web notification or log the error to a separate table.
