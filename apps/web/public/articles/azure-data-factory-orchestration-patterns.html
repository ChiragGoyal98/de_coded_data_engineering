Azure Data Factory orchestration patterns

In the world of data engineering, building a single pipeline to move data is just the beginning. The real challenge lies in managing how multiple tasks interact with one another. Azure Data Factory (ADF) uses orchestration to coordinate these activities, ensuring that data flows in the correct sequence, handles errors gracefully, and runs efficiently. Think of orchestration as the brain of your data integration project, deciding when to start a task and what to do if something goes wrong.

Why Orchestration Matters

Without proper orchestration patterns, data pipelines become fragile and difficult to maintain. By implementing structured patterns, you gain several key advantages:

  • Reliability: You can ensure that a transformation task only starts after the data ingestion task has successfully finished.
  • Efficiency: You can run independent tasks simultaneously (parallel processing) to reduce the total execution time.
  • Error Handling: Instead of a pipeline simply failing, orchestration allows you to build "retry" logic or send notifications when an error occurs.
  • Reusability: Using parameters and loops allows you to use a single pipeline to process hundreds of different tables.

Step-by-Step Walkthrough: Common Orchestration Patterns

1. Sequential Chaining

The most basic pattern is sequential chaining. This is used when Task B depends on the output of Task A. In the ADF UI, this is represented by the green connector (On Success).

  • Drag a "Copy Data" activity onto the canvas.
  • Drag a "Stored Procedure" activity next to it.
  • Click the green square on the right side of the Copy activity and drag the line to the Stored Procedure.

2. Parallel Execution

If you have multiple tasks that do not depend on each other, you should run them in parallel to save time.

  • Place three "Copy Data" activities on the canvas.
  • Do not connect them to each other.
  • When the pipeline triggers, ADF will attempt to start all three at the same time, subject to your integration runtime limits.

3. The "Execute Pipeline" Pattern (Modularization)

As your projects grow, putting everything in one pipeline makes it messy. The best practice is to create smaller "child" pipelines and call them from a "parent" pipeline.

  • Create a child pipeline that handles a specific task (e.g., loading a specific table).
  • Create a parent pipeline and drag the "Execute Pipeline" activity onto the canvas.
  • Under the "Settings" tab of the activity, select your child pipeline.

4. ForEach Looping

When you need to perform the same action on a list of items (like a list of 50 files), use the ForEach activity. This is often paired with a "Get Metadata" or "Lookup" activity to provide the list of items.

Code Example: Dependency JSON

Under the hood, ADF defines these relationships in JSON. Here is how a dependency looks when one activity waits for another:


{
    "name": "SecondActivity",
    "type": "StoredProcedure",
    "dependsOn": [
        {
            "activity": "FirstActivity",
            "dependencyConditions": ["Succeeded"]
        }
    ]
}

Common Mistakes

  • Circular Dependencies: This happens when Activity A waits for Activity B, but Activity B is also waiting for Activity A. The pipeline will never start.
  • Hardcoding Values: Beginners often type table names directly into activities. Use parameters so your orchestration logic can be reused across different environments (Dev, Test, Prod).
  • Ignoring Failure Paths: Most developers only use the green "On Success" path. Always consider adding a red "On Failure" path to log errors or send an email alert via a Logic App.
  • Over-nesting: Avoid putting ForEach activities inside other ForEach activities whenever possible, as this makes debugging extremely difficult.

Practice Task

To put these concepts into action, try building the following workflow in your ADF environment:

  • Create a "Lookup" activity that retrieves a list of three dummy table names (you can use a manual array in the activity settings).
  • Connect the Lookup activity to a "ForEach" activity.
  • Inside the ForEach activity, add a "Wait" activity.
  • Configure the Wait activity to pause for 5 seconds.
  • Set the ForEach activity to run in "Batch" mode (sequential unchecked) and observe how all three wait activities trigger simultaneously in the pipeline monitor.
