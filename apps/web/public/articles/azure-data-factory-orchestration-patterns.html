Azure Data Factory orchestration patterns

Azure Data Factory is a cloud-based data integration service that allows you to create, schedule, and orchestrate data workflows. At its core, orchestration is the process of coordinating complex tasks into a single, automated workflow. Instead of manually running scripts or managing individual data moves, orchestration ensures that every step happens in the right order, under the right conditions, and at the right time.

Why Orchestration Matters

In a modern data environment, data rarely moves from point A to point B in a single step. You might need to check if a file exists, copy it, transform it using a SQL script, and then notify a team via email.

Without proper orchestration patterns, your data pipelines become fragile. Proper patterns offer:

  • Resilience: Pipelines can automatically handle failures or retry steps.
  • Efficiency: Running tasks in parallel saves time and reduces costs.
  • Scalability: You can process one file or one thousand files using the same logic.
  • Maintainability: Clear patterns make it easier for other developers to understand your workflow.

Step-by-Step Walkthrough: Common Patterns

1. The Sequential Chain

This is the simplest pattern where activities run one after another. You use this when Activity B depends entirely on the successful completion of Activity A.

  • Drag two activities onto the canvas (e.g., a Copy Data activity and a Stored Procedure activity).
  • Click the green box on the right side of the first activity and drag the connector to the second activity.
  • This creates a "Success" dependency.

2. The Parallel (Fan-out) Pattern

Use this pattern when you have multiple tasks that do not depend on each other. Running them simultaneously significantly reduces the total execution time.

  • Place three Copy Data activities on the canvas.
  • Do not link them to each other.
  • Instead, link them all to a single "Trigger" or leave them unlinked if they should start at the exact same time.

3. The Conditional (Branching) Pattern

Data workflows often require logic. For example, if a file arrives, process it; if it doesn't, send an alert.

  • Use the If Condition activity.
  • Inside the activity, define an expression (e.g., checking if a variable is true).
  • Build one set of activities in the "True" block and another in the "False" block.

4. The Iterative Pattern (ForEach)

When you need to perform the same action on a list of items-like processing twenty different Excel files-you use the ForEach activity.

  • Use a Get Metadata activity to list files in a folder.
  • Pass the output list to a ForEach activity.
  • Inside the ForEach, define the activity (like Copy Data) that should run for every item in the list.

Code Example: ForEach Iteration

In the JSON definition of an ADF pipeline, a ForEach activity that iterates through a list of table names looks like this:


{
    "name": "IterateTables",
    "type": "ForEach",
    "typeProperties": {
        "items": {
            "value": "@pipeline().parameters.TableList",
            "type": "Expression"
        },
        "activities": [
            {
                "name": "CopyTableData",
                "type": "Copy"
            }
        ]
    }
}

Common Mistakes

  • Hardcoding Values: Beginners often type folder paths or database names directly into activities. Use Parameters and Variables instead to make your pipelines reusable.
  • Ignoring Failure Paths: Most developers only connect the green (Success) lines. Remember to handle the red (Failure) paths to send alerts or log errors when something goes wrong.
  • Over-nesting: Putting too many activities inside ForEach or If-Condition blocks makes the pipeline hard to debug. If a logic block gets too complex, move it into a separate "Child Pipeline" and use the Execute Pipeline activity.

Practice Task: The "Safe Move" Pattern

To practice your orchestration skills, try building a pipeline that performs a "Safe Move."

  • Step 1: Use a Copy Data activity to move a file from a "Landing" folder to a "Processed" folder.
  • Step 2: Connect a Delete activity to the Copy activity using the green "Success" link.
  • Step 3: Configure the Delete activity to remove the original file from the "Landing" folder.
  • Validation: Run the pipeline. If the copy fails, the delete should not trigger, ensuring you never lose data.
