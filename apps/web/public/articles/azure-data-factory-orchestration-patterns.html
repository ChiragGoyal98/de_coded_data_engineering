Orchestration in Azure Data Factory refers to the management and coordination of various activities to ensure data flows smoothly from source to destination. Think of it as a workflow engine that decides when and how tasks like data copying, transformation, or data clearing should run. Instead of running isolated tasks manually, orchestration allows you to build complex logic that handles dependencies, timing, and error scenarios automatically.

Why it matters

In a professional data environment, data rarely moves in a single, simple step. Orchestration is critical because it manages the "if-then-else" logic of your data estate. It ensures that a reporting table isn't updated until the raw data has been successfully ingested. By using orchestration patterns, you reduce manual intervention, minimize the risk of data corruption from out-of-order execution, and create a system that can recover gracefully from transient network failures. It also allows for parallelism, which significantly speeds up large-scale data movements.

Step-by-step walkthrough

Building an effective orchestration workflow involves combining specific patterns. Here are the four most common patterns you will use in Azure Data Factory (ADF).

1. The Sequential Pattern

This is the most basic pattern where activities run one after another. In the ADF UI, you create this by dragging a green connector (on success) from one activity to the next.

  • Drag a Copy Data activity to the canvas.
  • Drag a Data Flow activity next to it.
  • Connect the green output of the Copy activity to the Data Flow.
  • Result: The Data Flow will only start if the Copy Data activity completes successfully.

2. The Parallel Pattern

To save time, you often want to run independent tasks simultaneously.

  • Place three different Copy Data activities on the canvas.
  • Do not connect them to each other.
  • Trigger the pipeline.
  • Result: ADF will attempt to run all three at once, depending on your available Integration Runtime resources.

3. The ForEach Pattern (Iterative)

If you have a list of 50 tables to copy, you don't want to create 50 activities. Instead, you use a loop.

  • Use a Lookup activity to get a list of table names from a SQL database.
  • Connect the Lookup activity to a ForEach activity.
  • Inside the ForEach activity, place a single Copy Data activity.
  • Use the @item().TableName expression to dynamically change the source for each iteration.

4. The Parent-Child Pattern

For complex projects, putting everything in one pipeline makes it hard to manage. Instead, break them into "Child" pipelines and call them from a "Parent" pipeline.

  • Use the Execute Pipeline activity in your main workflow to trigger a secondary pipeline.
  • You can pass parameters from the parent to the child to keep the logic dynamic.

Here is an example of how an Execute Pipeline activity is defined in the JSON code of a pipeline:


{
    "name": "TriggerSubProcess",
    "type": "ExecutePipeline",
    "dependsOn": [],
    "userProperties": [],
    "typeProperties": {
        "pipeline": {
            "referenceName": "ChildPipelineName",
            "type": "PipelineReference"
        },
        "waitOnCompletion": true,
        "parameters": {
            "SourceFolder": "raw-data",
            "TargetFolder": "processed-data"
        }
    }
}

Common mistakes

  • Ignoring the "Wait on Completion" setting: In the Execute Pipeline activity, if you uncheck "Wait on Completion," the parent pipeline will continue running as soon as the child starts, which often leads to dependency errors.
  • Hardcoding values: Beginners often type table names or file paths directly into activities. Always try to use parameters and variables to make your orchestration patterns reusable.
  • Overlooking the "Max Batch Count": In a ForEach loop, the default behavior is to run iterations in parallel (up to 50). If your source database cannot handle 50 simultaneous connections, your pipeline will fail. Always check the "Sequential" box if order matters, or set a specific batch count.
  • Missing Error Paths: Only connecting the "Success" (green) paths means your pipeline just stops if something fails. Always consider adding "Failure" (red) paths to send an email alert or log the error to a table.

One practice task

The "Conditional Archiver" Challenge

Create a pipeline that performs the following logic:

  • Use a Get Metadata activity to check if a specific file exists in your Azure Blob Storage.
  • Use an If Condition activity to check the output of the metadata activity.
  • If True: Move the file to an "Archive" folder using a Copy Data activity and then delete the original using a Delete activity.
  • If False: Use a Web Activity to send a "File Not Found" notification to a dummy URL (like a logic app endpoint or a test site).

This task will help you master sequential logic, conditional branching, and metadata-driven orchestration.
