Azure Data Factory orchestration patterns

Azure Data Factory (ADF) is a cloud-based data integration service that allows you to create data-driven workflows for orchestrating and automating data movement and data transformation. Orchestration is the process of coordinating these different tasks-like moving a file, running a script, or triggering a Spark job-to ensure they happen in the right order and under the right conditions. Think of it as a blueprint for your data's journey from source to destination, acting as the conductor of a complex digital orchestra.

Why it matters

Without proper orchestration, data pipelines become chaotic and fragile. If you try to transform data before it has finished moving from your local server to the cloud, the process will fail. Orchestration patterns provide a standardized way to handle these dependencies.

By using defined patterns, you gain several benefits:

  • Reliability: Ensures tasks only run when their prerequisites are met.
  • Error Handling: Allows you to define what happens if a specific step fails.
  • Efficiency: Enables parallel processing to save time and reduce costs.
  • Scalability: Makes it easier to manage hundreds of files or tables without building a unique pipeline for every single one.

Step-by-step walkthrough

Let's look at the four most common patterns used in Azure Data Factory to manage data flows.

1. Sequential Execution (The Chain)

This is the simplest pattern where activities run one after another. You use "Dependency Links" (the green arrows) to connect activities. Activity B will only start once Activity A finishes successfully.

  • Drag two activities (e.g., Copy Data and Notebook) onto the canvas.
  • Click the small green box on the right side of the first activity and drag the connector to the second activity.

2. Parallel Execution (The Fan-out)

If you have multiple tasks that don't depend on each other-like loading five separate dimension tables-you should run them at the same time to save time.

  • Drag multiple activities onto the canvas.
  • Connect them all to the same starting trigger or a single "upstream" activity. ADF will start all "downstream" activities simultaneously.

3. Iterative Processing (The Loop)

When you need to perform the same action on a collection of items (like 50 different CSV files), you use the ForEach activity. Instead of creating 50 copy activities, you create one loop that iterates through a list.

  • Use a Get Metadata activity to get a list of files in a folder.
  • Pass that list into a ForEach activity.
  • Inside the ForEach, place a Copy Data activity that uses a parameter for the filename.

4. Conditional Branching (The If/Else)

Sometimes you only want to run an activity if a certain condition is met-for example, if a file exists or if today is the end of the month.

  • Use the If Condition activity.
  • In the "Expression" tab, write your logic (e.g., checking a variable).
  • Inside the "True" block, put the activities you want to run if the condition is met; leave the "False" block empty or add alternative steps.

Code Example: Defining a Dependency

In ADF, orchestration logic is stored in JSON. The dependsOn property is what tells the service to wait for another activity to finish.


{
    "name": "SecondActivity",
    "type": "Copy",
    "dependsOn": [
        {
            "activity": "FirstActivity",
            "dependencyConditions": [
                "Succeeded"
            ]
        }
    ],
    "typeProperties": { ... }
}

Common mistakes

  • Hardcoding values: Beginners often type specific filenames into activities. Use Parameters and Variables instead so your patterns can be reused for different datasets.
  • Ignoring Failure paths: Most people only connect the "Success" (green) path. It is often a good idea to connect the "Failure" (red) path to a Web activity that sends an email or a Slack alert when something goes wrong.
  • Over-nesting: Avoid putting loops inside loops inside loops. This makes pipelines hard to debug and can hit ADF's activity limits. If it gets too complex, break it into "Parent" and "Child" pipelines using the Execute Pipeline activity.

One practice task

To practice these patterns, try building a "Validation and Move" pipeline:

  • Use a Get Metadata activity to check if a specific folder is empty.
  • Use an If Condition to check the "childItems" count from the metadata.
  • If the folder is NOT empty (True), use a Copy Data activity to move the files to a "Processed" folder.
  • If the folder IS empty (False), use a Web Activity to send a mock notification or simply log a message using a Wait activity.
