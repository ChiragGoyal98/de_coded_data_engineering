Azure Data Factory orchestration patterns

Azure Data Factory is a powerful cloud-based integration service, but its true potential lies in orchestration. Orchestration refers to the coordination and management of complex data workflows. Instead of just running single tasks, it allows you to define the order, conditions, and dependencies of various activities to ensure data flows smoothly from source to destination. By mastering orchestration patterns, you move beyond simple data copying and start building resilient, automated data systems.

Why it matters

In real-world scenarios, data is rarely ready to move all at once. You might need to check if a file exists before processing it, or you might need to run five different tasks simultaneously to save time. Orchestration matters because it provides:

  • Resilience: It allows you to build "retry" logic or failure paths so that one small error doesn't break your entire data ecosystem.
  • Efficiency: You can run independent tasks in parallel, significantly reducing the total time a pipeline takes to run.
  • Scalability: Patterns like "Looping" allow you to handle one file or one thousand files using the same logic.
  • Cost Management: By coordinating tasks effectively, you avoid keeping expensive compute resources active longer than necessary.

Step-by-step walkthrough: The "Iterate and Partition" Pattern

One of the most common orchestration patterns is the "Lookup and ForEach" pattern. This is used when you have a list of items (like table names or file paths) and you want to perform the same action on each item.

1. The Lookup Activity

Start by adding a Lookup activity to your pipeline canvas. This activity acts as the "brain" that identifies what needs to be processed. For example, it might run a SQL query to get a list of active customers or fetch a list of filenames from a configuration table.

2. The ForEach Activity

Drag a ForEach activity onto the canvas and connect the green "Success" line from the Lookup activity to it. In the settings of the ForEach activity, you will link its items to the output of your Lookup activity.

3. Defining the Inner Activity

Click the "Edit" (pencil) icon inside the ForEach activity. This opens a "sub-canvas." Whatever you place here-such as a Copy activity or a Notebook activity-will run once for every item identified by the Lookup activity.

4. Setting Concurrency

Back on the main ForEach settings, you can decide if the items should be processed one by one (Sequential) or all at once (Parallel). Parallel processing is usually faster but requires more resources from your data source.

Code Example: ForEach Item Reference

Inside the ForEach loop, you use dynamic content to refer to the current item being processed. Here is how that looks in the activity's JSON definition:


{
    "name": "CopyIndividualFile",
    "type": "Copy",
    "typeProperties": {
        "source": {
            "type": "BinarySource",
            "storeSettings": {
                "fileName": "@item().Name"
            }
        }
    }
}

Common mistakes

  • Hardcoding values: Beginners often type specific file names into activities. Always use Parameters and Variables to make your pipelines reusable across different environments.
  • Ignoring Dependency Constraints: Connecting activities with only the green "Success" line means the pipeline stops if an activity fails. Remember to use the red "Failure" or blue "Completion" lines for error handling.
  • Over-nesting: Azure Data Factory does not allow you to put a ForEach activity inside another ForEach activity directly. To solve this, you must put the second loop inside a separate pipeline and call it using the "Execute Pipeline" activity.
  • Neglecting Timeouts: Default timeouts are often very long (7 days). If a process hangs, it can waste credits. Always set a reasonable timeout for your activities based on expected runtimes.

Practice task

Create a "Safe Copy" pipeline. Your goal is to move a file, but only if a specific condition is met.

  • Create a new pipeline and add a Get Metadata activity to check if a file exists in your storage.
  • Add an If Condition activity and connect it to the Get Metadata activity.
  • In the If Condition expression, check if the exists property is true.
  • Inside the "True" path of the If Condition, place a Copy activity.
  • Inside the "False" path, place a Wait activity or a Web activity to send a notification that the file was missing.
