Azure Data Factory orchestration patterns

Azure Data Factory orchestration is the process of coordinating and managing the execution of various data activities to create an end-to-end workflow. Instead of running isolated tasks, orchestration allows you to define dependencies, handle conditional logic, and manage loops. It acts as the brain of your data integration project, ensuring that Task B only starts if Task A completes successfully, or that an error-handling routine triggers if something goes wrong.

Why it matters

Orchestration is what transforms a simple data copy task into a robust enterprise data pipeline. Without proper patterns, your data environment becomes fragile and difficult to maintain. By implementing structured orchestration, you gain:

  • Efficiency: Running tasks in parallel saves time and reduces the duration of your data loads.
  • Reliability: Built-in retry logic and failure paths ensure that one minor error doesn't break your entire system.
  • Scalability: Looping patterns (like ForEach) allow you to process hundreds of tables or files using a single, dynamic pipeline rather than creating hundreds of manual tasks.
  • Cost Management: By controlling when clusters (like Azure Databricks or SQL pools) spin up and shut down, you avoid paying for idle compute time.

Step-by-step walkthrough

Building an orchestrated pipeline involves connecting activities using "Dependencies" and "Control Flow" activities. Here is how to implement the most common patterns.

1. Sequential and Conditional Execution

The simplest pattern is the sequential chain. In the ADF canvas, you connect activities using colored arrows.

  • Green (Success): The next activity runs only if the previous one succeeds.
  • Red (Failure): This allows you to "Catch" an error. For example, if a Copy activity fails, you can trigger a Web activity to send a Slack or Email alert.
  • Blue (Completion): The next activity runs regardless of whether the previous one succeeded or failed.

2. Parallel Processing

To speed up your pipelines, you can drag multiple activities onto the canvas without connecting them to each other. If they all depend on the same starting activity, they will execute simultaneously. This is ideal for loading multiple independent dimension tables at the same time.

3. Iteration with ForEach

If you need to process a list of files or tables, use the ForEach activity.

  • Use a 'Get Metadata' or 'Lookup' activity to find the list of items.
  • Pass that list into the 'ForEach' activity.
  • Inside the ForEach container, define the activities (like Copy or Notebook) that should run for every item in that list.

4. Code Example: ForEach Logic

While ADF is primarily visual, the underlying definition is JSON. Here is a snippet of how a ForEach activity iterates through a list of tables:


{
    "name": "IterateTables",
    "type": "ForEach",
    "typeProperties": {
        "items": {
            "value": "@pipeline().parameters.TableList",
            "type": "Expression"
        },
        "isSequential": false,
        "activities": [
            {
                "name": "CopyTableData",
                "type": "Copy"
            }
        ]
    }
}

Common mistakes

Even experienced developers fall into traps when designing complex orchestrations. Watch out for these:

  • Ignoring Concurrency Limits: By default, a ForEach loop might try to run 20 tasks at once. If your source database can only handle 5 connections, your pipeline will crash. Always check the 'Batch Count' setting in your loop.
  • Hardcoding Values: Avoid typing table names or file paths directly into activities. Use Parameters and Variables to make your orchestration patterns reusable across Dev, Test, and Production environments.
  • Deep Nesting: ADF does not allow you to put a ForEach activity inside another ForEach activity directly. To get around this, you must "Execute" a child pipeline from within the first loop.
  • Lack of Timeouts: If an activity hangs, it can run for days and consume your budget. Always set a reasonable 'Timeout' value on each activity.

One practice task

To get hands-on with orchestration, try building a "Validation Gate" pipeline. Create a pipeline with a Lookup activity that checks a SQL table for the count of rows. Use an 'If Condition' activity to check if the count is greater than zero. If true, trigger a Copy activity to move the data. If false, use a Web activity or a script activity to log that no data was found for processing.
