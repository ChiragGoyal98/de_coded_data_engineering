Azure Data Factory orchestration patterns

Azure Data Factory (ADF) is often described as the glue that holds data integration projects together. While individual activities like moving data from a database to a lake are important, orchestration focuses on the logic that connects these steps. Think of it as a conductor leading an orchestra; it ensures every activity starts at the right time, follows the correct sequence, and handles interruptions gracefully. By mastering orchestration patterns, you transition from running manual tasks to building robust, automated data systems.

Why it matters

Effective orchestration is the difference between a fragile data process and a resilient production pipeline. Here is why these patterns are essential for any data professional:

  • Efficiency: Running tasks in parallel instead of one after another can significantly reduce total processing time.
  • Dependency Management: It ensures that "Step B" only starts if "Step A" completes successfully, preventing data corruption.
  • Error Handling: Proper patterns allow you to define what happens when a task fails, such as sending an alert or triggering a rollback.
  • Scalability: Patterns like looping allow you to process 100 tables using the same logic instead of building 100 individual pipelines.

Step-by-step walkthrough

To build effective pipelines, you need to understand the four primary orchestration patterns used in Azure Data Factory.

1. Sequential Chaining

The most basic pattern is the sequence. This is used when Task B depends entirely on the output of Task A. In the ADF UI, this is represented by the green connector (on success) or blue connector (on completion).

  • Drag two activities onto the canvas.
  • Click the small green box on the right side of the first activity.
  • Drag the arrow to the second activity.

2. Parallel Execution (Fan-out)

If you have five independent tasks, running them one after another is a waste of time. Parallel execution allows ADF to trigger multiple activities simultaneously.

  • Place multiple activities on the canvas.
  • Do not connect them to each other.
  • Connect them all to a single "starter" activity or leave them disconnected to run as soon as the pipeline starts.

3. Conditional Logic (The 'If' Decision)

Sometimes you only want to run a task if a certain condition is met-for example, only move data if it is the first day of the month.

  • Use the If Condition activity.
  • Inside the activity, define an expression (e.g., checking a variable).
  • Define two separate paths: "True" and "False." ADF will only execute the path that matches the result.

4. Iteration and Looping

If you need to perform the same action on a list of files, you use the ForEach activity. This is the "scale-out" pattern.

  • Use a Get Metadata or Lookup activity to get a list of items.
  • Pass that list into a ForEach activity.
  • Inside the ForEach block, define the activities you want to repeat for every item in that list.

Code Example: ForEach Logic

Below is a simplified JSON representation of how a ForEach activity looks in the code behind your pipeline:


{
    "name": "IterateOverFiles",
    "type": "ForEach",
    "typeProperties": {
        "items": {
            "value": "@pipeline().parameters.fileList",
            "type": "Expression"
        },
        "activities": [
            {
                "name": "CopyIndividualFile",
                "type": "Copy"
            }
        ]
    }
}

Common mistakes

Even experienced developers fall into these traps when starting with ADF orchestration:

  • Over-nesting: Avoid putting a ForEach inside a ForEach inside an If condition. It makes debugging extremely difficult. Instead, use "Execute Pipeline" to break complex logic into sub-pipelines.
  • Ignoring Retry Policies: By default, if an activity fails, it stops. Always configure the Retry setting in the activity properties for tasks that might fail due to temporary network issues.
  • Hardcoding Values: Beginner developers often type table names or folder paths directly into activities. Use Parameters and Variables to make your orchestration patterns reusable.
  • Forgetting Constraints: If you connect two activities with a "Success" line, but the first one fails, the second will never run. Always consider if you need a "Failure" path for error logging.

One practice task

To practice these concepts, try building a "Validation Pattern" in your ADF sandbox:

  • Create a pipeline with a Get Metadata activity to check if a specific CSV file exists in your storage account.
  • Add an If Condition activity that checks the exists output of the first activity.
  • In the True path, add a Copy Data activity to move the file.
  • In the False path, add a Web activity (or a simple Wait activity for now) to simulate sending an error notification that the file is missing.
