Azure Data Factory orchestration patterns

Azure Data Factory (ADF) is a cloud-based data integration service that allows you to create data-driven workflows for orchestrating and automating data movement and data transformation. Think of orchestration as the brain behind your data pipelines. Instead of just running a single task, orchestration allows you to define the logic, order, and dependencies between multiple activities. Whether you are dealing with a simple file copy or a complex multi-stage ETL process, understanding orchestration patterns is key to building robust data systems.

Why it matters

In a production environment, data processes rarely happen in a single, isolated step. You might need to wait for a specific file to arrive, check if a database is online, or process twenty different tables simultaneously. Proper orchestration ensures:

  • Error Resilience: If one step fails, the orchestration determines whether to retry, stop, or follow a "failure path."
  • Efficiency: By running independent tasks in parallel, you significantly reduce the total execution time of your pipelines.
  • Cost Management: Orchestration allows you to spin up compute resources (like Azure Databricks clusters) only when they are needed and shut them down immediately after.
  • Maintainability: Breaking complex tasks into smaller, orchestrated modules makes your code easier to debug and update.

Step-by-step walkthrough

Building orchestration patterns in ADF involves using the visual canvas to connect "Activities" using dependency arrows and control flow logic.

1. Sequential Chaining

This is the most basic pattern where activities run one after another. You connect activities using green (Success), red (Failure), or blue (Completion) lines.

  • Drag two Copy Activities onto the canvas.
  • Connect the first to the second using the green box on the right of the activity.
  • The second activity will only start if the first finishes successfully.

2. Parallel Execution

If two tasks are not dependent on each other-for example, loading "Customer" data and loading "Product" data-they should run at the same time.

  • Drag two activities onto the canvas.
  • Do not connect them to each other.
  • Connect both of them to a common trigger or a starting activity. ADF will start them simultaneously.

3. Iteration and Looping

When you need to perform the same action on a list of items (like 50 different CSV files), use the ForEach activity.

  • Use a Get Metadata activity to list the files in a folder.
  • Pass that list into a ForEach activity.
  • Inside the ForEach "sub-canvas," define the activity (e.g., Copy or Notebook) that should run for every item in that list.

4. Conditional Logic

Use the If Condition or Switch activity to create branches in your logic.

  • An If Condition evaluates an expression (e.g., Is today Monday?).
  • If True, it executes one set of activities; if False, it executes another.

JSON Code Example: ForEach Orchestration

Below is a simplified snippet of how a ForEach activity looks in the underlying JSON code of a pipeline:


{
    "name": "IterateFiles",
    "type": "ForEach",
    "typeProperties": {
        "items": {
            "value": "@pipeline().parameters.fileList",
            "type": "Expression"
        },
        "activities": [
            {
                "name": "CopyIndividualFile",
                "type": "Copy",
                "inputs": [ { "referenceName": "SourceDataset", "type": "DatasetReference" } ],
                "outputs": [ { "referenceName": "DestinationDataset", "type": "DatasetReference" } ]
            }
        ]
    }
}

Common mistakes

  • Hardcoding values: Beginners often type file names or folder paths directly into activities. Always use Parameters and Variables to make your orchestration reusable.
  • Ignoring Timeouts: By default, activities can run for a very long time. If a task gets stuck, it can drain your budget. Always set a reasonable "Timeout" period in the activity settings.
  • The Monolithic Pipeline: Putting 50 activities in one single pipeline makes it impossible to read. Use the Execute Pipeline activity to call smaller, "child" pipelines from a "parent" pipeline.
  • Forgetting Retry Logic: Networks glitch and databases briefly blink. For critical tasks, set the "Retry" count to 2 or 3 in the activity settings to handle transient errors automatically.

One practice task

To practice these concepts, try building a "Validation and Move" pipeline:

  • Use a Get Metadata activity to check if a specific file exists in Azure Blob Storage.
  • Use an If Condition activity to check the output of the metadata activity.
  • In the True path, add a Copy Activity to move the file to a "processed" folder and a Delete Activity to remove the original.
  • In the False path, add a Web Activity to send an email notification (or a simple Wait Activity) indicating the file was missing.
