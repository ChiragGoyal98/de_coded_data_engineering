Azure Data Factory orchestration patterns

Azure Data Factory (ADF) is a cloud-based data integration service that allows users to create data-driven workflows. Orchestration is the process of coordinating these workflows to ensure data moves from source to destination in a specific order and under specific conditions. By using orchestration patterns, developers can manage complex dependencies between different data tasks without manual intervention. This ensures that a database update does not begin until the preceding file ingestion has successfully completed.

Why it matters

In a real-world data environment, tasks rarely exist in isolation. If you have hundreds of pipelines, managing them manually is impossible. Orchestration patterns matter because they provide:

  • Dependency Management: Ensures tasks run in the correct sequence (e.g., Load Dim tables before Fact tables).
  • Error Handling: Allows you to define what happens if a task fails, such as sending an email or running a rollback script.
  • Efficiency: Parallel processing allows independent tasks to run simultaneously, saving time and reducing costs.
  • Reusability: By using a "Master-Child" pattern, you can build modular pipelines that can be triggered by multiple different processes.

Step-by-step walkthrough: The Master-Child Pattern

The most fundamental orchestration pattern in ADF is the Master-Child (or Parent-Child) pattern. This involves a "Master" pipeline that triggers one or more "Child" pipelines.

1. Create the Child Pipeline

Start by creating a simple pipeline that performs a specific task, such as moving a single table. Add parameters to this pipeline (e.g., TableName) so it isn't hardcoded to one source.

2. Create the Master Pipeline

Create a new pipeline in your ADF instance. This will serve as the controller that decides when the child pipelines should run.

3. Add the 'Execute Pipeline' Activity

Search for the Execute Pipeline activity in the Activities panel and drag it onto the Master pipeline canvas. Under the "Settings" tab of this activity, select the child pipeline you created in step 1.

4. Pass Parameters

If your child pipeline has parameters, the Master pipeline will show these under the "Settings" tab. You can pass values directly or use dynamic expressions to send data from the Master to the Child.

5. Define Dependencies

Connect activities using green (Success), red (Failure), or blue (Completion) arrows. For example, if you have two Execute Pipeline activities, connecting them with a green arrow ensures the second one only starts if the first succeeds.

Example Code: Execute Pipeline Activity

In the underlying JSON of an ADF pipeline, an orchestration step using the Execute Pipeline activity looks like this:


{
    "name": "TriggerChildPipeline",
    "type": "ExecutePipeline",
    "settings": {
        "pipeline": {
            "referenceName": "Child_Copy_Data",
            "type": "PipelineReference"
        },
        "waitOnCompletion": true,
        "parameters": {
            "TargetFolder": "Sales_Data_2023"
        }
    }
}

Common mistakes

  • Wait on Completion: Forgetting to check the "Wait on completion" box in the Execute Pipeline activity. If unchecked, the Master pipeline will trigger the Child and immediately move to the next step without waiting for the Child to finish.
  • Infinite Loops: Creating a pattern where Pipeline A calls Pipeline B, and Pipeline B calls Pipeline A. This will quickly consume your Azure credits and cause system failures.
  • Hardcoding Values: Not using parameters. If you hardcode file paths or table names inside your child pipelines, you lose the ability to reuse those pipelines for other datasets.
  • Ignoring Failure Paths: Only planning for the "Happy Path" (success). Always include a logic branch for when a pipeline fails, such as a Web Activity to post a message to Microsoft Teams or Slack.

One practice task

Create a "Conditional Orchestration" workflow.

  • Create a Master pipeline with a Lookup Activity that checks if a specific file exists in your Azure Blob Storage.
  • Use an If Condition Activity to evaluate the output of that lookup.
  • If the file exists (True), use an Execute Pipeline Activity to run a data ingestion pipeline.
  • If the file does not exist (False), use a Web Activity to send a notification or a Fail Activity to stop the process with a custom error message.
