Working in a shared data environment often feels like a crowded kitchen. In Databricks, teams can work on the same notebook simultaneously, which is powerful but can lead to confusion without the right guardrails. Collaboration goes beyond just sharing access; it involves how you track changes, communicate within the code, and manage resources to ensure everyone is working on the most accurate version of the data logic.

Why it matters

Effective collaboration reduces the risk of accidentally overwriting a teammate's work or running expensive computations twice. It also improves code quality through peer reviews and ensures that the transition from development to production is seamless. When everyone follows a standardized workflow, troubleshooting becomes faster because the code is structured predictably, and the history of "who changed what" is always available.

Step-by-step walkthrough

1. Use Databricks Repos for Git Integration

The most important practice is moving away from standalone workspace notebooks and using Databricks Repos. This allows you to link your notebooks to a Git provider like GitHub, GitLab, or Azure DevOps.

  • Create a separate branch for every new feature or bug fix.
  • Commit and push changes frequently to avoid losing work.
  • Use Pull Requests (PRs) for code reviews before merging into the main branch. This ensures that at least one other person has vetted the logic.

2. Leverage Built-in Commenting

Instead of sending screenshots via messaging apps, use the native commenting feature in the notebook.

  • Highlight a specific line of code or a markdown cell.
  • Click the comment icon on the right-hand sidebar.
  • Use the @ symbol to tag a teammate. They will receive an email notification with a link directly to the line of code you are discussing.

3. Manage Permissions with the Principle of Least Privilege

Avoid giving "Can Manage" permissions to every user. High-level permissions allow users to delete notebooks or change access for others, which can lead to accidental data loss.

  • Can View: For stakeholders who only need to see the results.
  • Can Run: For team members who need to execute the logic but shouldn't change the code.
  • Can Edit: For active developers on the project.

4. Parameterize with Widgets

To make notebooks reusable for different team members without changing the core code, use Databricks Widgets. This allows users to input variables (like dates, file paths, or environment names) through a UI at the top of the notebook.

Code Example: Creating a Text Widget


# Create a text widget to allow collaborators to specify an environment
dbutils.widgets.text("env", "development", "Target Environment")

# Access the value entered in the widget
current_env = dbutils.widgets.get("env")

# Use the variable in your logic
print(f"The notebook is currently pulling data for: {current_env}")

Common mistakes

  • Simultaneous cell editing: While Databricks supports real-time co-authoring, having two people edit the exact same cell at the same time can cause "session state" confusion. It is better to work on different cells or different branches.
  • Hardcoding personal file paths: Using paths like /Users/your.name@company.com/data.csv ensures the notebook will fail for everyone else. Always use shared paths or mount points.
  • Saving large outputs in Git: Large table previews or plots saved within the notebook metadata can make Git "diffs" unreadable. Use dbutils.widgets or clear cell outputs before committing large changes to a Repo.

One practice task

To practice these skills, pair up with a colleague and perform the following:

  • Create a new folder in Databricks Repos and link it to a test GitHub repository.
  • Create a new branch called test-collaboration.
  • Create a notebook and add one Python widget that accepts a "Username" string.
  • Have your colleague open the same notebook, use the "Comment" feature to leave a suggestion on your code, and then try changing the widget value to their own name.
  • Merge the branch into the main branch once you both agree on the code.
