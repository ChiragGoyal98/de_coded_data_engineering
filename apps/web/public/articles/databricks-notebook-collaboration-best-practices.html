Databricks notebook collaboration best practices

Databricks notebooks are more than just editors; they are live environments where multiple engineers often work simultaneously on data pipelines or machine learning models. Unlike local development, where code lives in isolation on a personal machine, Databricks promotes a workspace-first approach where transparency and real-time updates are the norm. Understanding how to navigate this shared space effectively ensures that team productivity remains high and the codebase remains stable.

Why it matters

Collaboration in a data environment presents unique challenges. Without established best practices, teams often face "code collisions" where one person's changes accidentally overwrite another's. Furthermore, because notebooks often execute against shared compute resources (clusters), unoptimized collaboration can lead to performance bottlenecks. Proper practices ensure that code is version-controlled, peer-reviewed, and documented, moving the workflow away from a "scratchpad" mentality and toward production-grade engineering.

Step-by-step walkthrough

1. Leverage Databricks Repos (Git Integration)

The most important step for professional collaboration is moving notebooks out of the general "Workspace" folders and into Databricks Repos. This allows you to link your notebook to a Git provider like GitHub, GitLab, or Azure DevOps.

  • Create a new Repo in the Databricks sidebar.
  • Create separate branches for features or bug fixes.
  • Perform Pull Requests (PRs) in your Git provider for code reviews before merging into the main branch.

2. Use Built-in Commenting

Rather than leaving "TODO" comments inside code cells that might be forgotten, use the built-in Databricks comment feature.

  • Highlight a piece of code and click the "Comment" icon on the right margin.
  • Use the @ symbol to tag a teammate; they will receive an email notification.
  • Resolve threads once the discussion is finalized to keep the workspace clean.

3. Parameterize with Widgets

When multiple people run the same notebook, they might need different inputs (e.g., different date ranges or file paths). Instead of manually changing variables in the code, use Databricks Widgets. This allows users to input values via a UI at the top of the notebook without altering the logic.


# Create a text input widget for a file path
dbutils.widgets.text("input_path", "/mnt/data/raw_files")

# Access the value in your code
current_path = dbutils.widgets.get("input_path")
print(f"Processing data from: {current_path}")

4. Organize with Workspace Folders

Avoid saving everything in the "Shared" root folder. Establish a clear hierarchy:

  • /Shared/Projects/[ProjectName]: For stable, collaborative project files.
  • /Users/[Email]: For personal drafts and experiments.
  • /Shared/Archive: For deprecated notebooks.

5. Managing Cluster Dependencies

In a collaborative environment, avoid using %pip install inside a notebook cell if possible, as this installs the library every time the notebook runs and affects the cluster environment for others. Instead:

  • Install libraries at the Cluster level via the Compute UI.
  • Use Environment YAML files if you are working within Databricks Repos to ensure everyone has the same dependencies.

Common mistakes

  • Hardcoding Secrets: Never type passwords or API keys directly into a notebook. If a teammate clones your notebook, they see your credentials. Use dbutils.secrets.get() instead.
  • Simultaneous Editing of the Same Cell: While Databricks supports real-time co-authoring, editing the exact same code block at the same time can lead to "lost updates." Communicate with your team or work on different cells.
  • Ignoring Revision History: If you accidentally delete a cell or logic, don't panic. Use the Revision History button (top right) to compare versions and restore previous states.
  • Large Notebooks: Avoid creating notebooks with hundreds of cells. This makes collaboration difficult. Break logic into smaller, modular notebooks and use %run ./OtherNotebook or Python modules to link them.

Practice task

To get comfortable with collaborative tools, try the following exercise:

  • Create a new notebook in your personal folder.
  • Add a widget at the top of the notebook that accepts a "Username" string.
  • Write a cell that prints a greeting using that widget's value.
  • Click the "Comment" icon on your print statement and tag a colleague (or yourself) asking for a code review.
  • Open the Revision History and see how your notebook state was saved after these changes.
