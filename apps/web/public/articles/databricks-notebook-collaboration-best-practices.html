In the world of data engineering, the ability to work together on the same set of code is essential. Databricks notebooks are designed to be collaborative, allowing multiple users to view and edit code simultaneously. However, without a clear strategy, this open-door policy can lead to confusion, overwritten logic, and messy workspaces. Understanding how to manage shared environments ensures that your team remains productive rather than getting in each other's way.

Why it matters

Effective collaboration is the backbone of any successful data project. When teams follow established patterns, they reduce the risk of breaking production pipelines and minimize the time spent fixing "merge conflicts" in human logic. It also makes onboarding new members much easier, as the code structure remains consistent and documented. Furthermore, using collaboration features properly provides an audit trail, ensuring you always know who changed what and why, which is vital for debugging and compliance in professional environments.

Step-by-step walkthrough

1. Use Databricks Repos for Version Control

The most critical practice for team collaboration is moving beyond basic workspace notebooks and using Databricks Repos. This feature allows you to link your Databricks workspace to a Git provider like GitHub, GitLab, or Bitbucket.

  • Create a new Repo in Databricks and link it to your remote Git repository.
  • Use branches for individual features. Work on a "feature/your-name" branch rather than editing the main branch directly.
  • Commit and push your changes regularly to keep the remote repository updated.

2. Communicate via Notebook Comments

Instead of leaving "TODO" notes inside your code cells, which can clutter the script, use the built-in commenting system.

  • Highlight a specific line of code.
  • Click the comment icon that appears on the right margin.
  • Use this space to ask questions or explain complex logic to your teammates. They can reply directly to your comment, creating a threaded discussion.

3. Parameterize Logic with Widgets

When sharing a notebook, different team members might want to run the same logic but with different inputs (like a specific date range or a different database schema). Instead of hardcoding these values, use Databricks Widgets.


# Create a dropdown widget for selecting an environment
dbutils.widgets.dropdown("env", "development", ["development", "staging", "production"])

# Retrieve the selected value to use in your code
current_env = dbutils.widgets.get("env")
print(f"Running notebook in {current_env} mode")

4. Organize with Workspace Folders and Permissions

Avoid keeping all notebooks in a single shared folder. Create a clear directory structure (e.g., /Shared/Project_A/ETL/). Once organized, use the "Permissions" settings to control who can view, edit, or manage the notebooks. This prevents accidental deletions by users who only need to see the results.

Common mistakes

  • Editing the same cell simultaneously: While Databricks supports multiple users, two people typing in the exact same cell at the same moment can lead to synchronization lag or lost work.
  • Hardcoding credentials: Never type passwords or secret keys into a notebook. Use Databricks Secrets and dbutils.secrets.get() so your teammates can run the code without having access to sensitive login info.
  • Forgetting to clear state: Before finishing your work, it is good practice to "Clear All Outputs." This prevents the notebook from saving large, sensitive, or confusing data previews in the version history.

Practice task

To practice these skills, pair up with a colleague or use a second account. Create a new notebook in a shared folder and perform the following:

  • Create a Markdown cell at the top describing the purpose of the notebook.
  • Add a Python cell with a simple function, then have your partner add a comment to that cell using the "Comment" button.
  • Add a text widget called "User_Name" and write a line of code that prints a greeting using the value from that widget.
  • Try to "Resolve" the comment once both of you have seen it.
