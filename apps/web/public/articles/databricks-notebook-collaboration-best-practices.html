Databricks notebook collaboration best practices

Databricks notebooks are more than just a place to write code; they are a collaborative environment where data engineers, scientists, and analysts work together in real-time. Much like a shared document, these notebooks allow multiple users to edit, comment, and run cells simultaneously. However, without a set of established rules, this shared space can quickly become chaotic. Managing shared code effectively ensures that team members do not overwrite each other's work and that the final pipeline remains readable and maintainable.

Why it matters

In a professional data engineering environment, code is rarely a solo project. Effective collaboration practices prevent "code drifting," where different versions of the same logic exist in multiple places. It also speeds up the peer review process, makes onboarding new team members easier, and ensures that sensitive information-like API keys or database passwords-remains protected even when multiple people have access to the workspace. Without these practices, teams often struggle with broken dependencies and "works on my machine" syndromes.

Step-by-step walkthrough

1. Leverage Databricks Git Folders (formerly Repos)

The most important rule for collaboration is to avoid working directly in the "Workspace" folder for production code. Instead, use Databricks Git Folders to connect your notebook to a version control system like GitHub or Azure DevOps.

  • Create a new Git Folder in your user space.
  • Create a feature branch for your changes.
  • Push your changes and use Pull Requests (PRs) for code reviews.

2. Use Markdown for Inline Documentation

Notebooks are unique because they allow you to mix code with rich text. Use Markdown cells (%md) to explain the "why" behind your logic.

  • Start every notebook with a header and a brief description.
  • Use headers (##) to break long notebooks into logical sections.
  • Document any specific cluster requirements or data dependencies at the top.

3. Manage Credentials with Secret Scopes

When collaborating, never hardcode passwords or access keys in a cell. If you do, anyone with access to the notebook can see them. Instead, use the Databricks Secret utility. This allows your teammates to run the code using their own permissions without ever seeing the actual secret values.


# Best practice: Retrieve credentials from a secret scope
database_password = dbutils.secrets.get(scope="adls_credentials", key="storage_key")

# Use the variable in your connection logic
spark.conf.set("fs.azure.account.key.mystorage.dfs.core.windows.net", database_password)

4. Utilize the Built-in Commenting Feature

Instead of leaving "TODO" notes inside code cells, use the built-in Databricks commenting tool. Highlight a piece of code, click the comment icon on the right sidebar, and tag your teammate using @their-email. This keeps the code clean while facilitating active discussion.

5. Modularize Code with %run or Python Files

To keep notebooks from becoming 2,000-line monsters, move helper functions to a separate notebook or a shared Python file. You can call them into your main notebook using the %run command. This makes the code reusable for everyone on the team.

Common mistakes

  • Ignoring the Revision History: Databricks automatically saves versions. If a teammate accidentally deletes a cell, don't panic. Check the "Revision History" in the top right corner to restore previous versions.
  • Overwriting Variables: Using generic variable names like df throughout a shared notebook leads to confusion. If multiple people are running cells out of order, one person's df might overwrite another's. Use descriptive names like df_silver_sales_cleaned.
  • Leaving "Print" and "Display" Statements: While helpful for debugging, leaving dozens of display(df) commands makes the notebook slow to load and messy for others. Clean up your exploratory code before merging.
  • Hardcoding Paths: Avoid using absolute paths to your personal user folder. Use parameters or configuration files so the notebook works for everyone.

Practice task

To get comfortable with these practices, perform the following exercise with a colleague or using a secondary test account:

  • Create a Git Folder: Connect a repository to your Databricks environment and create a branch named collaboration-test.
  • Add a Parameter: Add a widget at the top of the notebook that allows a user to input their name.
  • Document and Comment: Write a function that calculates a simple value, add a Markdown cell explaining it, and then have a teammate leave a comment on a specific line of that function.
  • Merge: Commit your changes to Git, create a Pull Request, and merge it into the main branch.
