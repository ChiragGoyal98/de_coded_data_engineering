Databricks notebook collaboration best practices

Databricks notebooks offer a powerful environment for data engineers to build and test code in real-time. However, because these notebooks are cloud-based and accessible by entire teams, they require a disciplined approach to ensure that work remains organized and secure. Effective collaboration in Databricks involves more than just sharing a link; it requires using the built-in versioning, commenting, and security features to maintain a clean and professional workflow.

Why it matters

In a professional data engineering environment, multiple people often touch the same codebase. Without collaboration standards, teams face several risks: code being accidentally overwritten, lack of accountability for changes, and security vulnerabilities like hardcoded credentials. By following best practices, teams can ensure that their work is reproducible, easily peer-reviewed, and ready for production. Standardizing how you work in notebooks transforms a collection of messy scripts into a robust data platform.

Step-by-step walkthrough

1. Connect to Databricks Repos

The most important practice for any team is moving away from standalone notebooks and toward Databricks Repos. This feature allows you to link your Databricks environment to a Git provider like GitHub or Azure DevOps.

  • Navigate to the Repos tab in the sidebar.
  • Click Add Repo and paste your Git URL.
  • This allows you to create branches, commit your changes, and pull updates from your teammates. Never work directly on the "Main" or "Master" branch; always create a feature branch for your specific task.

2. Use the Built-in Commenting System

Instead of cluttering the code with temporary notes, use the "Comments" feature located on the right side of every cell.

  • Highlight a specific line of code to leave a targeted comment.
  • Use the @ symbol to tag a teammate. This sends them an email notification and a link directly to the cell in question.
  • Resolve comments once the issue is addressed to keep the workspace clean.

3. Organize with Markdown and Headings

Collaborative notebooks should read like a story. Use Markdown cells to explain the "why" behind your code.

  • Use ## and ### headers to create a Table of Contents.
  • Use the Clear State and Run All functions to ensure that your notebook can be executed from top to bottom by a teammate without errors.

4. Manage Permissions (ACLs)

Not everyone needs to edit every notebook. Use Access Control Lists to protect your work:

  • Click the Share button at the top right of the notebook.
  • Assign roles such as Can View, Can Run, or Can Edit.
  • For production-level notebooks, restrict access so that only lead engineers or service principals can modify the logic.

5. Parameterize Your Notebooks

Avoid hardcoding values like file paths or dates. Use Databricks Widgets to make your notebooks interactive and reusable for your colleagues.


# Create a text widget for a database name
dbutils.widgets.text("database_name", "default_db", "Target Database")

# Access the value in your code
target_db = dbutils.widgets.get("database_name")
print(f"Data will be written to: {target_db}")

Common mistakes

  • Hardcoding Secrets: Never type passwords or API keys directly into a notebook cell. Use Databricks Secrets and dbutils.secrets.get() to keep credentials hidden from collaborators.
  • Concurrent Editing Conflicts: While Databricks allows multiple people to type in a notebook at once, editing the same cell simultaneously can lead to lost work. Coordinate with your team before making major changes to shared logic.
  • Large Notebooks: Creating a notebook with hundreds of cells makes it difficult for others to review. Break large workflows into smaller, modular notebooks and call them using %run or the dbutils.notebook.run() command.

One practice task

To get comfortable with collaboration, perform the following exercise:

  • Create a new notebook in your personal folder.
  • Create a Markdown cell at the top with a title and a brief description of a "fake" data task.
  • Add a Comment to a code cell and mention a teammate (or yourself) using the @ symbol.
  • Click the Share button and change the permissions for a colleague to Can View only.
  • Practice "Commit and Push" if you have a Git repository connected, using a descriptive commit message like "Initial setup of collaboration exercise."
