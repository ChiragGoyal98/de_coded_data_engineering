Databricks notebook collaboration best practices

Databricks notebooks are more than just a place to write code; they are a collaborative workspace where data engineers and scientists can work together in real-time. Much like sharing a document in the cloud, these notebooks allow multiple users to edit the same file simultaneously, see who is working on what, and leave comments for feedback. For a data engineering team, mastering these collaborative tools is essential for maintaining a fast-paced and error-free workflow.

Why it matters

Collaboration in data engineering isn't just about sharing a script. It is about maintaining "one version of the truth." Without standard practices, teams often end up with dozens of notebooks named "analysis_v1," "analysis_v2_final," and "analysis_v3_FIXED."

Using Databricks' built-in collaboration features helps:

  • Reduce Redundancy: Multiple team members can work on different parts of a pipeline without overwriting each other's progress.
  • Improve Code Quality: Integrated commenting and version control allow for immediate peer reviews.
  • Ensure Security: Proper permission settings prevent unauthorized users from running expensive clusters or accessing sensitive data.

Step-by-step walkthrough

1. Set Workspace Permissions

Before sharing a notebook, you must define who can do what. Databricks uses Access Control Lists (ACLs).

  • Open the notebook you want to share.
  • Click the Permissions button at the top right.
  • Add users or groups and assign one of the following levels:
  • Can Read: View code and results.
  • Can Run: View code and attach it to a cluster to run cells.
  • Can Edit: Modify the code and cells.
  • Can Manage: Change permissions and delete the notebook.

2. Leverage Databricks Repos (Git Integration)

While real-time editing is great, professional teams use Git for version control. Databricks Repos allows you to sync your notebooks with providers like GitHub or Azure DevOps.

  • Go to the Repos tab in the sidebar.
  • Click Add Repo and paste your Git URL.
  • This creates a shared environment where team members can create branches, commit changes, and submit Pull Requests (PRs).

3. Use Comments for Peer Review

Instead of sending Slack messages about a specific line of code, use the built-in commenting tool.

  • Highlight a piece of code or a specific cell.
  • Click the Comment icon that appears in the margin.
  • Tag your teammate using the @ symbol to notify them.

4. Parameterize Notebooks with Widgets

When collaborating, your teammate might want to run your notebook with different dates or file paths. Instead of forcing them to edit your code, use Widgets. This creates input boxes at the top of the notebook.


# Create a text widget for a department name
dbutils.widgets.text("department", "Sales")

# Access the value in your code
dept = dbutils.widgets.get("department")
print(f"Filtering data for: {dept}")

5. Review Revision History

If a collaborator accidentally deletes a cell or breaks a logic loop, don't panic.

  • Click the Revision History (clock icon) on the right sidebar.
  • You can see a list of every version, who saved it, and when.
  • Click Restore this version to go back in time.

Common mistakes

  • Hardcoding Credentials: Never type passwords or API keys directly in a notebook. If you share the notebook, everyone sees them. Use Databricks Secrets instead.
  • Ignoring the 'Shared' Folder: Working only in your "User" folder makes it hard for others to find your work. Use the Workspace/Shared folder for team projects.
  • Overwriting Variables: Because notebooks share a state, two people running different cells simultaneously can overwrite global variables. Always keep your notebooks modular and clear.
  • Leaving Clusters Running: Collaborators often attach notebooks to high-concurrency clusters. Ensure everyone knows the "Auto-Termination" rules to avoid high costs.

Practice task

To get comfortable with these features, perform the following exercise with a teammate:

  • Create a new notebook in your personal folder.
  • Grant your teammate Can Edit permissions.
  • Add a simple Python print statement and ask your teammate to add a comment to that cell.
  • Open the Revision History and identify the change your teammate made.
  • Create a text widget and verify that both of you can change the input value at the top of the screen.
