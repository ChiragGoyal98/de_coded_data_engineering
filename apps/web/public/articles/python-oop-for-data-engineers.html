Object-Oriented Programming (OOP) is a paradigm that organizes software design around data, or objects, rather than functions and logic. For someone starting in data engineering, Python often feels like a series of scripts-linear blocks of code that run from top to bottom. While scripts are great for small tasks, production-grade data pipelines require a more organized structure. OOP allows you to bundle related data and the operations performed on that data into a single unit called a class.

Why it matters for Data Engineers

In a professional data environment, you rarely write code for a one-off task. You build systems that need to be maintained, scaled, and reused. OOP provides three major benefits for the DE workflow:

  • Reusability: Instead of rewriting the connection logic for every Snowflake or S3 script, you can create a single "Connector" class and reuse it across multiple projects.
  • Maintenance: If an API changes its authentication method, you only have to update the logic in one class rather than hunting through dozens of separate scripts.
  • Abstraction: You can hide complex implementation details. A team member can use your DataCleaner class to "clean()" a dataset without needing to know the 200 lines of regex logic happening inside the method.

Step-by-step walkthrough

1. Defining a Class and Object

A class is a blueprint, while an object is an instance of that blueprint. Think of a "Database" as a class and "Production_Postgres" as the actual object you interact with.


class DatabaseConnector:
    pass

# Creating an instance (object)
my_db = DatabaseConnector()

2. The init Method and Attributes

The __init__ method is a special function that runs automatically when you create a new object. It is used to set the initial state of the object using "attributes" (variables belonging to the class).


class DataPipeline:
    def __init__(self, source_name, batch_size):
        self.source = source_name
        self.batch_size = batch_size

# Now every pipeline object has a name and a size
sales_pipeline = DataPipeline("sales_api", 500)
print(sales_pipeline.source)

3. Methods

Methods are functions defined inside a class that define the "behavior" of the object. For a data engineer, these might be actions like connect(), extract(), or load().


class FileProcessor:
    def __init__(self, file_path):
        self.file_path = file_path

    def get_extension(self):
        return self.file_path.split('.')[-1]

processor = FileProcessor("data_logs.csv")
print(processor.get_extension())

4. Inheritance

Inheritance allows one class to take on the attributes and methods of another. This is perfect for creating a general "Extractor" class and then making specific versions for CSVs, APIs, or SQL databases.


class BaseExtractor:
    def log_status(self):
        print("Extraction started...")

class ApiExtractor(BaseExtractor):
    def fetch_data(self, url):
        self.log_status()
        print(f"Fetching from {url}")

# ApiExtractor has access to log_status() even though it's not defined there
api = ApiExtractor()
api.fetch_data("https://api.example.com")

Common mistakes

  • Forgetting 'self': In Python, the first argument of any method in a class must be self. It represents the specific instance of the object. Forgetting it will result in a TypeError.
  • Over-engineering: Not everything needs to be a class. If you are just writing a simple mathematical transformation, a plain function is often better and more readable.
  • Mutable default arguments: Never use lists or dictionaries as default arguments in __init__ (e.g., def __init__(self, data=[])). Because of how Python handles memory, that list will be shared across every instance of the class you create, leading to strange data leaks.

Practice task

  • The __init__ method should take a list of numbers and store it in an attribute called data.
  • Add a method called multiply_by(n) that returns a new list where every number in data is multiplied by n.
  • Add a method called get_sum() that returns the total sum of the numbers in data.

Try instantiating it with the list [1, 2, 3] and calling your methods to verify the results.
