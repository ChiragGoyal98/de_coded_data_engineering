While functional programming is common in data science scripts, Object-Oriented Programming (OOP) is the backbone of robust data engineering. In its simplest form, OOP is a way of organizing code by grouping related data and behaviors into "objects." Instead of writing a long list of instructions to process a CSV file, you create a dedicated "FileProcessor" object that knows its own file path and has specific instructions on how to open, clean, and save that data. This shift from writing steps to building components makes your code more modular and easier to debug as your data pipelines grow in complexity.

Why it matters for Data Engineers

Data engineering is rarely about one-off scripts; it is about building reliable systems. OOP provides three major benefits to a Data Engineer:

  • Modularity: You can build a generic "DatabaseConnector" and then create specific versions for Snowflake, Postgres, or BigQuery without rewriting the core logic.
  • Maintainability: If the authentication logic for an API changes, you only need to update it in one class rather than hunting through dozens of scripts.
  • Abstraction: Your teammates don't need to know the complex details of how a S3 connection is established; they just need to call a simple .upload() method on your object.

Step-by-step walkthrough

1. Defining the Blueprint (The Class)

A class is like a template. For example, if you are building an ETL (Extract, Transform, Load) tool, you start by defining what an "Extractor" looks like.

2. Setting Initial State (The __init__ Method)

When you create an object from a class, you often need to provide starting information, like a URL or a database name. We use the __init__ method to assign these values to the object using self.

3. Adding Actions (Methods)

Methods are functions that belong to the class. In a data context, these are usually actions like connect(), fetch_data(), or validate_schema().

4. Inheritance

This is where the power lies. You can create a parent class with general logic and child classes for specific data sources.


class DataConnector:
    def __init__(self, connection_string):
        self.connection_string = connection_string

    def connect(self):
        print(f"Connecting to {self.connection_string}...")

class PostgresConnector(DataConnector):
    def fetch_query(self, sql):
        self.connect()
        return f"Executing {sql} on Postgres"

# Usage
pg = PostgresConnector("localhost:5432/mydb")
print(pg.fetch_query("SELECT * FROM users"))

Common mistakes

  • Forgetting self: In Python, the first argument of every method must be self. Forgetting this is the most common cause of "TypeError: method() takes 0 positional arguments but 1 was given."
  • Over-engineering: Don't create a complex hierarchy of classes for a simple five-line script. Use OOP when you have shared logic or state that needs to be managed across multiple steps.
  • Using mutable defaults: Never use a list or dictionary as a default argument in a class method (e.g., def process(self, data=[])). Because of how Python handles memory, that list will be shared across every instance of the class, leading to data leaks between runs.

Practice task

Create a class called DataProfiler.

  • The class should take a list of numbers during initialization.
  • Add a method called get_mean() that returns the average of the numbers.
  • Add a method called get_summary() that prints a message: "The dataset has X items with an average of Y."

Once you finish this, try creating a child class called AdvancedProfiler that adds a method to find the maximum value in the list.
