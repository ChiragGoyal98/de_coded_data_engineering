SQL Window Functions with Real ETL Use Cases

SQL window functions might sound like something you'd find in a complex database architecture exam, but they are actually one of the most practical tools in a data engineer's toolkit. Unlike traditional aggregate functions that group multiple rows into a single result, window functions allow you to perform calculations across a specific set of rows while still keeping the individual rows visible. Imagine being able to calculate a running total or find a customer's previous purchase without losing the details of the current transaction; that is the power of a window function.

Why it matters

In the world of ETL (Extract, Transform, Load), we rarely just move data from point A to point B. We usually need to clean it, rank it, or compare it. Traditional GROUP BY statements are destructive-they collapse your data into summaries.

Window functions are essential for ETL because:

  • They allow for easy deduplication of data (keeping only the "latest" record).
  • They enable trend analysis by comparing the current row to the previous one (identifying changes).
  • They help in calculating running totals or moving averages for financial reporting.
  • They preserve the original granularity of the data while adding analytical context.

Step-by-step walkthrough

To master window functions, you need to understand the three main components of the syntax: the function itself, the PARTITION BY clause, and the ORDER BY clause.

1. The Core Syntax

The general structure looks like this: FUNCTION() OVER (PARTITION BY column_a ORDER BY column_b).

  • PARTITION BY: This divides the data into logical groups (like "folders").
  • ORDER BY: This determines the sequence of rows within those groups.

2. Use Case: Deduplication with ROW_NUMBER()

In many ETL pipelines, you might receive duplicate records for the same ID. To keep only the most recent one, we use ROW_NUMBER().


SELECT 
    order_id, 
    customer_id, 
    order_date,
    ROW_NUMBER() OVER (PARTITION BY order_id ORDER BY order_date DESC) as row_num
FROM raw_sales_data;

In this example, if order_id 101 appears twice, the query assigns "1" to the most recent date and "2" to the older one. In your ETL script, you would simply filter for row_num = 1.

3. Use Case: Comparing Changes with LAG()

If you need to see how much a price changed compared to the last update, LAG() is your best friend. It "reaches back" to the previous row in the window.

4. Use Case: Running Totals with SUM()

By using a standard aggregate function with an OVER clause, you can create a cumulative sum that grows with every row.

Common mistakes

  • Missing the ORDER BY clause: For functions like ROW_NUMBER() or RANK(), the order is critical. Without it, the database will assign numbers arbitrarily, making your ETL results unpredictable.
  • Over-partitioning: If you partition by a unique ID (like a primary key), every "window" will only have one row, rendering the function useless.
  • Performance overhead: Window functions can be resource-intensive on massive datasets. Always try to filter your data (using a WHERE clause) before applying window functions to keep the "window" as small as possible.
  • Confusing ROW_NUMBER and RANK: ROW_NUMBER() always gives unique numbers (1, 2, 3), while RANK() will give the same number to rows with identical values in the ORDER BY column (1, 1, 3).

One practice task

Suppose you have a table called website_traffic with columns user_id, page_url, and visit_time.

The Task: Write a query that shows each user's visit, but also adds a column showing the page_url they visited immediately before the current one.

Hint: Use the LAG() function and partition by the user so you don't accidentally see a different user's history!
