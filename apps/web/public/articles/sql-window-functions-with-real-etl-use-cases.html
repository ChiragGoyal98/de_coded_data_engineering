SQL Window Functions with Real ETL Use Cases

SQL window functions are powerful tools that allow you to perform calculations across a set of table rows that are related to the current row. Unlike a standard GROUP BY clause, which collapses your data into a single summary row, window functions let you retain the individual records while adding aggregate insights alongside them. This is achieved using the OVER clause, which defines the "window" or the frame of data the function will look at.

Why it matters in ETL

In Data Engineering and ETL (Extract, Transform, Load) pipelines, data is rarely clean or perfectly organized. You often encounter duplicate records, out-of-order events, or the need to compare a current value against a previous one. Window functions solve these problems efficiently.

They are particularly useful for:

  • Data Deduplication: Identifying the "latest" version of a record when multiple updates exist for the same ID.
  • Trend Analysis: Calculating running totals or moving averages to see how metrics change over time.
  • Sessionization: Assigning IDs to groups of user actions based on time gaps.

Step-by-step walkthrough

To use a window function, you need three main components: the function itself, the PARTITION BY clause, and the ORDER BY clause.

1. The ROW_NUMBER() function for Deduplication

This is perhaps the most common ETL use case. Imagine you have a table where a user's address is updated multiple times. You only want the most recent address.


SELECT 
    user_id, 
    address, 
    updated_at,
    ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY updated_at DESC) as row_num
FROM user_updates;

In this example:

  • PARTITION BY user_id tells SQL to group the rows by each user.
  • ORDER BY updated_at DESC ensures the newest record gets the number 1.
  • You can then wrap this in a subquery and filter for WHERE row_num = 1.

2. The SUM() function for Running Totals

If you are building a financial dashboard, you might need to show how revenue accumulates throughout the month.

3. LEAD() and LAG() for Comparisons

These functions allow you to look at the row immediately following or preceding the current one. In ETL, this is great for calculating the time difference between two consecutive events in a log file.

Common mistakes

  • Confusing GROUP BY with PARTITION BY: Remember that GROUP BY reduces the number of rows returned, while PARTITION BY keeps all original rows and simply adds the calculation to each one.
  • Forgetting ORDER BY in Ranking: If you use ROW_NUMBER() or RANK() without an ORDER BY clause inside the OVER() parentheses, the results will be non-deterministic (essentially random), which can break your ETL logic.
  • Performance Overhead: Running window functions on extremely large datasets (billions of rows) without proper indexing on the partition columns can significantly slow down your pipeline.

Practice task

Suppose you have a table named sales with columns store_id, sale_date, and amount. Write a query that shows each sale, but also includes a column called store_total that shows the total sum of all sales for that specific store.

Hint: You will need to use SUM(amount) combined with an OVER clause that partitions by the store ID.
