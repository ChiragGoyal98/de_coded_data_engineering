SQL Window Functions with Real ETL Use Cases

SQL window functions are powerful tools that perform calculations across a set of table rows related to the current row. Unlike regular aggregate functions, which group multiple rows into a single output row, window functions allow each row to maintain its individual identity. This unique behavior makes them essential for advanced data analysis and complex data transformations where you need to see both the individual record and a summary value at the same time.

Why it matters in ETL

In Extract, Transform, Load (ETL) pipelines, window functions solve problems that would otherwise require multiple joins or complex scripting. They are particularly useful for three major use cases:

  • Data Deduplication: Identifying the most recent version of a record in a stream of updates.
  • Time-Series Analysis: Calculating running totals or moving averages to track trends over time.
  • Delta Detection: Comparing the value of the current row with the previous row (e.g., finding the price difference between two consecutive dates).

By performing these operations directly in the SQL layer, you improve the performance of your data pipeline and keep your transformation logic clean and readable.

Step-by-step walkthrough

To use a window function, you need to understand the OVER clause, which defines the "window" of data the function will look at.

1. The PARTITION BY clause

Think of PARTITION BY as a "Group By" that doesn't collapse rows. It divides the result set into logical groups. For example, if you are analyzing sales, you might partition by region to perform calculations for each area independently.

2. The ORDER BY clause

This determines the sequence of rows within each partition. It is critical for functions like ROW_NUMBER() or RANK(), where the order of appearance dictates the value assigned to the row.

3. Common ETL Functions

  • ROW_NUMBER(): Assigns a unique sequential integer to rows. This is the gold standard for deduplication.
  • SUM() OVER(): When used with an order clause, this creates a running total.
  • LAG() and LEAD(): These allow you to "look back" at the previous row or "look forward" to the next row without using a self-join.

Code Example: Deduplicating User Profiles

In this example, we have a table with multiple updates for the same user, and we only want the most recent record based on the updated_at timestamp.


SELECT 
    user_id, 
    email, 
    updated_at
FROM (
    SELECT 
        user_id, 
        email, 
        updated_at,
        ROW_NUMBER() OVER(PARTITION BY user_id ORDER BY updated_at DESC) as rank_id
    FROM raw_user_data
) AS ranked_table
WHERE rank_id = 1;

Common mistakes

  • Confusing ROW_NUMBER, RANK, and DENSE_RANK: ROW_NUMBER always gives a unique number. RANK will give the same number to tied values and skip the next number (1, 2, 2, 4). DENSE_RANK will give the same number to ties but won't skip (1, 2, 2, 3).
  • Forgetting the ORDER BY: For many window functions, omitting the ORDER BY inside the OVER clause will result in the function processing the entire partition as an unordered block, which often leads to incorrect running totals.
  • Performance overhead: While window functions are efficient, applying them over extremely large partitions (millions of rows per partition) can consume significant memory on your database server.

Practice task

Imagine you have a table named monthly_revenue with columns month and revenue_amount. Write a query that returns a third column showing the "Total Revenue to Date" (a running total) ordered by the month.

Hint: Use the SUM() function combined with the OVER() clause and an ORDER BY on the month column.
