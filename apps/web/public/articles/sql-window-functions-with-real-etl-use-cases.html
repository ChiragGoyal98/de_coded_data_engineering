SQL Window Functions with Real ETL Use Cases

In the world of data engineering and analytics, the ability to perform complex calculations without losing the granularity of your data is a superpower. SQL window functions allow you to perform "over the shoulder" calculations, where you look at surrounding rows to provide context for the current one. Unlike standard aggregate functions like SUM or AVG that collapse multiple rows into a single result, window functions append the result to each individual row, keeping your dataset's original structure intact.

Why it matters in ETL

During the Transform phase of an ETL (Extract, Transform, Load) pipeline, data often arrives messy or incomplete. Window functions are the primary tools used to clean and enrich this data. They are specifically useful for:

  • Deduplication: Identifying the most recent record when multiple versions of the same entry exist.
  • Trend Analysis: Comparing today's sales against yesterday's without complex self-joins.
  • Running Totals: Calculating cumulative sums for financial reporting or inventory tracking.
  • Sessionization: Grouping user actions into distinct sessions based on time intervals.

Step-by-step walkthrough

To master window functions, you need to understand the three main components of the OVER() clause. This clause tells SQL exactly which "window" of data to look at.

1. PARTITION BY: The Grouping Mechanism

Think of PARTITION BY as a GROUP BY that doesn't hide the details. It divides the result set into buckets. For example, if you partition by customer_id, the window function will start its calculation fresh for every new customer.

2. ORDER BY: The Sequence

Within each partition, the order matters. If you are calculating a running total or finding the "first" login, you must tell the database how to sequence the rows (usually by a timestamp or an ID).

3. The Function Itself

Common functions include ROW_NUMBER() for unique IDs, RANK() for handling ties, and LEAD() or LAG() for looking at the next or previous rows.

ETL Use Case: Removing Duplicates

Imagine an ETL pipeline where a "Users" table receives multiple updates for the same person. You only want to load the most recent profile into your data warehouse.


WITH RankedUpdates AS (
    SELECT 
        user_id, 
        email, 
        updated_at,
        ROW_NUMBER() OVER(PARTITION BY user_id ORDER BY updated_at DESC) as update_rank
    FROM raw_users_staging
)
SELECT user_id, email, updated_at
FROM RankedUpdates
WHERE update_rank = 1;

In this example, PARTITION BY user_id groups all records for the same person, ORDER BY updated_at DESC puts the newest record at the top, and ROW_NUMBER() assigns "1" to that latest record.

Common mistakes

  • Confusing ROW_NUMBER and RANK: ROW_NUMBER() always assigns a unique increment (1, 2, 3), whereas RANK() will give the same number to tied values (1, 1, 3). In ETL deduplication, always use ROW_NUMBER() to ensure you pick exactly one record.
  • Filtering in the same step: You cannot use a window function result in a WHERE clause in the same query block. You must use a Subquery or a Common Table Expression (CTE), as shown in the code example above.
  • Ignoring Performance: Running a window function over millions of rows without a PARTITION BY clause forces the database to process the entire dataset as one giant window, which can cause significant latency or memory errors.

Practice task

Suppose you have a table named daily_sales with columns sale_date and amount. Write a query using the LAG() function to create a third column called previous_day_sale that shows the sales amount from the day before.

Hint: You will need to use OVER(ORDER BY sale_date). This is a classic ETL transformation used to calculate day-over-day growth percentages.
