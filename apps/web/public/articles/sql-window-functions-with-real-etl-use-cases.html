SQL Window Functions with Real ETL Use Cases

SQL window functions are a powerful feature in SQL that allow you to perform calculations across a specific set of table rows that are related to the current row. Unlike regular aggregate functions, which group multiple rows into a single output row, window functions keep each individual row intact while adding calculated columns. This makes them indispensable for data engineering tasks where you need to analyze trends or clean data without losing the underlying detail.

Why it Matters in ETL

In the world of Extract, Transform, Load (ETL), window functions are the "Swiss Army knife" for data transformation. Data engineers often deal with raw, messy data that needs to be refined before it reaches a dashboard or a machine learning model. Window functions help solve several critical problems:

  • Deduplication: When a source system sends duplicate records, window functions can help you identify and keep only the latest version.
  • Running Totals: They allow you to calculate cumulative sums, such as year-to-date revenue, without complex self-joins.
  • Comparative Analysis: You can easily compare a current row's value to the previous or next row (e.g., calculating the time difference between two user clicks).
  • Data Quality: They are used to flag outliers by comparing individual data points against moving averages or standard deviations within a specific "window."

Step-by-Step Walkthrough

To master window functions, you need to understand the syntax structure, specifically the OVER clause, which defines the "window" of data.

1. The Basic Syntax

The general structure looks like this:

FUNCTION() OVER (PARTITION BY column_a ORDER BY column_b)

  • PARTITION BY: This divides the result set into groups (like a GROUP BY but without collapsing rows).
  • ORDER BY: This defines the sequence of rows within each partition.

2. Deduplication with ROW_NUMBER()

In ETL, you often find duplicate entries for the same ID. To keep only the most recent entry, you can use ROW_NUMBER(). It assigns a unique integer to rows within a partition.


SELECT 
    order_id, 
    status, 
    updated_at,
    ROW_NUMBER() OVER (PARTITION BY order_id ORDER BY updated_at DESC) as row_num
FROM raw_orders_table;

In this example, the row with row_num = 1 will always be the most recent update for each order_id.

3. Running Totals with SUM()

If you want to see how revenue grows day by day without losing the daily breakdown, you use an aggregate function as a window function.


SELECT 
    sale_date, 
    daily_revenue,
    SUM(daily_revenue) OVER (ORDER BY sale_date) as running_total
FROM sales_summary;

4. Navigating Rows with LAG() and LEAD()

These functions allow you to "look back" at the previous row (LAG) or "look ahead" at the next row (LEAD). This is vital for calculating the duration of events or growth rates.

Common Mistakes

  • Forgetting the WHERE clause limitation: You cannot use a window function result directly in a WHERE clause. You must wrap the query in a Common Table Expression (CTE) or a subquery and filter the results from there.
  • Confusion between RANK() and DENSE_RANK(): RANK() leaves gaps in the numbering if there is a tie (e.g., 1, 2, 2, 4), while DENSE_RANK() does not (e.g., 1, 2, 2, 3).
  • Omitting ORDER BY: For functions like ROW_NUMBER() or LAG(), forgetting the ORDER BY inside the OVER clause will lead to unpredictable or non-deterministic results.
  • Performance Overhead: Running window functions on millions of rows without a PARTITION BY clause can be extremely slow because the database has to treat the entire dataset as a single window.

Practice Task

Imagine you have a table named user_logins with columns user_id and login_timestamp.

Task: Write a query that shows each login and the timestamp of the previous login for that same user. If it is the user's first login, the previous timestamp column should be null.

Hint: Use the LAG() function and partition the data by the user's ID.
