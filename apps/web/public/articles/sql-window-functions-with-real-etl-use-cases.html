SQL Window Functions with Real ETL Use Cases

Data transformation is a core part of any data engineering pipeline, and SQL window functions are often the most efficient way to handle complex calculations. Unlike standard aggregate functions like SUM or MEAN, which collapse multiple rows into a single result, window functions allow you to perform calculations across a set of table rows that are still related to the current row. This means you can keep your original row-level detail while simultaneously seeing "big picture" metrics like running totals, rankings, or period-over-period changes.

Why Window Functions Matter in ETL

In the world of Extract, Transform, Load (ETL), data is rarely clean or perfectly structured. You often encounter duplicate records, out-of-order events, or the need to compare a current record against a previous one. Without window functions, these tasks would require complex self-joins or temporary tables, which are slow and difficult to read.

Window functions provide a cleaner, more performant way to:

  • Deduplicate data by identifying the "latest" record in a set.
  • Calculate business metrics like Year-to-Date (YTD) totals or moving averages.
  • Assign unique ranks to items within specific categories.

Step-by-Step Walkthrough

To master window functions, you need to understand the three main components of the OVER() clause: PARTITION BY, ORDER BY, and the function itself.

1. The Basic Syntax

The general structure looks like this:

FUNCTION() OVER (PARTITION BY column_a ORDER BY column_b)

  • FUNCTION(): The calculation you want (e.g., ROW_NUMBER, SUM, AVG).
  • PARTITION BY: This divides the result set into groups (like "folders") where the function is applied independently.
  • ORDER BY: This defines the logical sequence of rows within each partition.

2. ETL Use Case: Deduplication with ROW_NUMBER()

Imagine you have a table of user profile updates where a user might have changed their email multiple times. You only want the most recent update for your target data warehouse.


SELECT 
    user_id, 
    email, 
    updated_at
FROM (
    SELECT 
        user_id, 
        email, 
        updated_at,
        ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY updated_at DESC) as rank_desc
    FROM raw_user_updates
) as ranked_updates
WHERE rank_desc = 1;

In this example, PARTITION BY user_id groups the rows by each specific user. ORDER BY updated_at DESC ensures the most recent update gets the number 1. By filtering for rank_desc = 1 in the outer query, we effectively remove all older duplicates.

3. ETL Use Case: Running Totals

A common requirement is calculating a running total of sales over time to track performance trends. Using SUM() as a window function makes this effortless.


SELECT 
    sale_date, 
    amount,
    SUM(amount) OVER (ORDER BY sale_date) as running_total
FROM daily_sales;

Because we didn't use PARTITION BY, the window covers the entire table. The ORDER BY sale_date tells SQL to add the current row's amount to the sum of all previous rows.

Common Mistakes

  • Forgetting the ORDER BY clause: For functions like ROW_NUMBER or LEAD, the order is critical. If you omit it, the database will assign numbers arbitrarily, leading to inconsistent results.
  • Using Window Functions in WHERE clauses: You cannot use a window function directly in a WHERE clause because window functions are processed after filtering. You must use a Subquery or a Common Table Expression (CTE) to filter the results.
  • Confusing RANK() vs DENSE_RANK(): If two rows have the same value, RANK() will skip the next number in the sequence (1, 2, 2, 4), while DENSE_RANK() will not (1, 2, 2, 3).

Practice Task

Scenario: You have a table called store_inventory with columns store_id, product_name, and stock_count.

Task: Write a query to find the top 3 products with the highest stock counts for each store.

Hint: Use the DENSE_RANK() function and partition by the store ID.
