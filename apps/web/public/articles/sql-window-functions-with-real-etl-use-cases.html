SQL Window Functions with Real ETL Use Cases

In the world of data engineering and analysis, SQL is the primary tool for shaping raw data into meaningful insights. One of the most powerful features of SQL is the window function. While traditional aggregate functions like SUM or AVG collapse multiple rows into a single result, window functions allow you to perform calculations across a set of table rows that are still related to the current row. This means you can calculate totals, rankings, or averages while keeping all your individual data rows visible in the final output.

Why it matters in ETL

In Extract, Transform, Load (ETL) processes, window functions are essential for cleaning and organizing data. They solve problems that would otherwise require complex subqueries or multiple self-joins. For example, if you are loading a stream of user updates into a data warehouse, you might receive multiple records for the same user ID. Using a window function allows you to quickly identify which record is the most recent so you can filter out the old ones.

They are also vital for financial reporting. Tasks like calculating a running total of sales over a month or determining a year-over-year growth percentage become straightforward one-liners. Without window functions, these operations are computationally expensive and harder to maintain as your codebase grows.

Step-by-step walkthrough

To master window functions, you need to understand three main components: the function itself, the OVER clause, and the optional PARTITION BY and ORDER BY clauses.

1. The OVER Clause

The OVER clause defines the "window" or the set of rows the function will look at. If you leave the parentheses empty, the function treats the entire result set as one single window.

2. PARTITION BY

This acts like a GROUP BY but for your window. It divides the data into buckets based on a column. For example, if you partition by department_id, the function will restart its calculation every time the department changes.

3. ORDER BY

Within each partition, you often need the data to be in a specific sequence. For instance, to find the "latest" record, you must order by a timestamp.

4. ROW_NUMBER()

This is perhaps the most common ETL window function. It assigns a unique sequential integer to rows within a partition. It is the gold standard for deduplicating data.


SELECT 
    order_id, 
    customer_id, 
    order_date,
    ROW_NUMBER() OVER(PARTITION BY customer_id ORDER BY order_date DESC) as latest_order
FROM sales_table;

In this example, every customer gets their orders numbered from 1 (the most recent) upwards. In an ETL pipeline, you would simply filter for where latest_order = 1 to get only the most recent transaction per customer.

Common mistakes

  • Confusing PARTITION BY with GROUP BY: Remember that GROUP BY reduces the number of rows in your output, while PARTITION BY keeps every row intact.
  • Forgetting the ORDER BY in Ranking Functions: Functions like ROW_NUMBER() or RANK() require an ORDER BY clause inside the OVER statement to know which row should be "first." Without it, the numbering is unpredictable.
  • Overusing them on massive datasets: While powerful, window functions can be resource-heavy. If you are working with billions of rows, ensure the columns you use in your PARTITION BY and ORDER BY clauses are indexed where possible.

Practice task

Imagine you have a table called daily_revenue with columns store_id, sale_date, and amount.

Task: Write a query that shows every row from the table, but adds a fourth column called store_total that shows the sum of all revenue for that specific store, regardless of the date.

Hint: Use the SUM() function as a window function combined with PARTITION BY store_id.
