SQL Window Functions with Real ETL Use Cases

In the world of data engineering, SQL is more than just a tool for retrieving data; it is the engine that transforms raw information into actionable insights. One of the most powerful features for these transformations is the window function. Unlike standard aggregate functions-such as SUM or AVG-which collapse multiple rows into a single result, window functions perform calculations across a specific range of rows while maintaining the identity of each individual record. This allows you to see the "big picture" and the "fine detail" at the same time.

Why it Matters in ETL

In Extract, Transform, Load (ETL) pipelines, data often arrives in a messy or historical format. You might have duplicate records, or you might need to calculate how a metric changes over time. Window functions are essential for these tasks because:

  • They simplify deduplication: You can easily pick the "latest" version of a record based on a timestamp.
  • They enable trend analysis: Comparing today's sales to yesterday's is trivial with window functions.
  • They preserve row-level detail: You can calculate a department's average salary and display it next to every employee's individual salary without performing a complex JOIN.

Step-by-Step Walkthrough

To master window functions, you need to understand the OVER clause, which defines the "window" of data the function will look at.

1. The Basic Syntax

The standard structure of a window function looks like this:

FUNCTION_NAME() OVER (PARTITION BY column_a ORDER BY column_b)

  • PARTITION BY: This divides the rows into groups (like a GROUP BY).
  • ORDER BY: This sorts the rows within those groups.

2. Deduplication with ROW_NUMBER()

A common ETL task is removing duplicate entries. Imagine a table where a user's address is updated multiple times. To get only the most recent address, we use ROW_NUMBER().


SELECT user_id, address, updated_at
FROM (
    SELECT user_id, address, updated_at,
           ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY updated_at DESC) as row_num
    FROM user_updates
) ranked_updates
WHERE row_num = 1;

In this example, the window function assigns a "1" to the latest record for every user. We then filter for only those rows.

3. Running Totals with SUM()

If you need to track cumulative revenue over a month, you can use an aggregate function as a window function. By providing an ORDER BY inside the OVER clause without a PARTITION BY, SQL calculates a running total from the first row to the current one.

4. Comparing Rows with LAG() and LEAD()

In ETL, we often need to calculate the "time since the last event." LAG() looks at the previous row, while LEAD() looks at the next one. This is perfect for calculating the duration between a user logging in and logging out.

Common Mistakes

  • Forgetting ORDER BY in Ranking: Functions like ROW_NUMBER() or RANK() require an ORDER BY to know which row comes first. Without it, the results will be unpredictable.
  • Confusing GROUP BY with PARTITION BY: Remember that GROUP BY reduces the number of rows in your output. PARTITION BY does not; it simply changes how the calculation is calculated across existing rows.
  • Performance Overload: While powerful, running complex window functions on billions of rows without proper indexing or filtering can significantly slow down your ETL jobs. Always try to filter your data in a subquery before applying the window function.

Practice Task

Scenario: You have a table called store_sales with columns store_id, sale_date, and amount.

Task: Write a query that shows each sale alongside the total sales for that specific store to date (a running total).

Hint: You will need to use SUM(amount) combined with an OVER clause that partitions the data by the store and orders it by the date.
