SQL Window Functions with Real ETL Use Cases

In the world of data manipulation, window functions represent a bridge between simple row-level operations and complex group-level aggregations. While standard aggregate functions like SUM or AVG condense multiple rows into a single result, window functions allow you to perform calculations across a specific set of rows while still keeping each individual row in your output. This "window" of data is defined relative to the current row, making it possible to compare a specific record against its neighbors or its group without losing the detail of the original dataset.

Why It Matters in ETL

In Extract, Transform, Load (ETL) pipelines, window functions are essential for cleaning and organizing data. They solve several high-level problems that would otherwise require convoluted self-joins or temporary tables:

  • Deduplication: When you receive multiple versions of the same record, you can use window functions to rank them by timestamp and select only the most recent entry.
  • Trend Analysis: Calculating running totals or moving averages is straightforward when you can "look back" at previous rows.
  • Change Tracking: Comparing a value in the current row to the value in the previous row helps identify state changes, such as a customer moving from a "Basic" to a "Premium" subscription.
  • Performance: Because they are processed in a single pass over the data, window functions are often more efficient than subqueries or multiple joins.

Step-by-Step Walkthrough

To use a window function, you need to understand the three main components of its syntax: the function itself, the OVER clause, and the partitioning/ordering logic.

1. The Basic Syntax

The syntax follows this general pattern:

FUNCTION_NAME() OVER (PARTITION BY column_a ORDER BY column_b)

  • PARTITION BY: This divides the data into buckets (like GROUP BY). The calculation restarts for each bucket.
  • ORDER BY: This determines the sequence of rows within each bucket, which is crucial for ranking or running totals.

2. Ranking and Deduplication

The most common ETL use case is identifying the "first" or "latest" record. The ROW_NUMBER() function assigns a unique integer to each row within its partition based on the specified order.


SELECT 
    order_id, 
    customer_id, 
    order_date,
    ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY order_date DESC) as latest_order_rank
FROM orders;

In this example, for every customer, the most recent order will be assigned a rank of 1. In an ETL pipeline, you would wrap this in a subquery and filter for latest_order_rank = 1 to remove duplicates.

3. Comparing Records with LEAD and LAG

Navigational functions allow you to access data from other rows without joining the table to itself.

  • LAG(): Retrieves a value from a previous row.
  • LEAD(): Retrieves a value from a subsequent row.

This is perfect for calculating the time elapsed between two events or finding the price difference between two consecutive days.

Common Mistakes

  • Forgetting the ORDER BY: In ranking functions like ROW_NUMBER() or RANK(), forgetting the ORDER BY clause within the OVER() statement will result in an error or non-deterministic results. The database needs to know which row comes first to assign it a rank.
  • Confusing PARTITION BY with GROUP BY: Remember that PARTITION BY does not reduce the number of rows. If your source table has 1,000 rows, your output will still have 1,000 rows.
  • Using window functions in the WHERE clause: You cannot use a window function directly in a WHERE clause. Because of the order of execution in SQL, window functions are calculated after filtering. To filter based on a window result, you must use a Common Table Expression (CTE) or a subquery.

Practice Task

Imagine you have a table called monthly_sales with columns store_id, sale_month, and total_revenue.

The Task: Write a query that shows each store's revenue for each month, alongside a column showing the revenue from the previous month for that same store. If it is the first month on record for that store, the previous month's revenue should be null.

Hint: Use the LAG() function and partition your data by the store ID.
