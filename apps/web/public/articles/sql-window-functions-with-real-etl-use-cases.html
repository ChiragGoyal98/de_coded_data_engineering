SQL Window Functions with Real ETL Use Cases

If you have spent any time writing SQL, you are likely familiar with aggregate functions like SUM and AVG. While these tools are great for summarizing data, they have one major limitation: they collapse your rows into a single result. In the world of data engineering and ETL (Extract, Transform, Load), we often need to perform calculations across a set of rows while still keeping the individual details of every record. This is where window functions come into play. They allow you to look at a "window" of data related to the current row, performing calculations that would otherwise require complex and slow self-joins.

Why it Matters in ETL

Window functions are essential for modern data pipelines because they handle complex logic efficiently. In an ETL process, you aren't just moving data; you are often cleaning it and preparing it for analysis.

  • Deduplication: When data arrives from a source with duplicate entries, window functions help you identify and keep only the most recent record.
  • Data Quality: You can easily find outliers by comparing a specific row's value to the average of its category.
  • Performance: Traditional methods of calculating running totals or moving averages often involve joining a table to itself, which is computationally expensive. Window functions perform these calculations in a single pass over the data.

Step-by-Step Walkthrough

To use a window function, you need to understand the OVER clause. This clause defines the "window" of rows the function will look at.

1. The Basic Syntax

The standard structure looks like this:

FUNCTION() OVER (PARTITION BY column_a ORDER BY column_b)

  • PARTITION BY: This divides the result set into groups (like a GROUP BY, but without collapsing rows).
  • ORDER BY: This defines the sequence of rows within each partition.

2. Use Case: Deduplicating Records

Imagine you have a table of user logins where some users appear multiple times. You want to extract only the most recent login for each user. We use ROW_NUMBER() to assign a unique number to each row within a user group, ordered by time.


WITH RankedLogins AS (
    SELECT 
        user_id, 
        login_time, 
        ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_time DESC) as row_num
    FROM user_activity
)
SELECT user_id, login_time
FROM RankedLogins
WHERE row_num = 1;

3. Use Case: Calculating Running Totals

In a sales ETL pipeline, you might need to calculate a "Year-to-Date" (YTD) total. By using SUM() as a window function, you can add up sales row-by-row without losing the individual transaction details.

4. Ranking and Comparison

Functions like RANK() or DENSE_RANK() are used to assign positions. For example, if you need to find the top 3 products sold in every category, you would partition by category_id and order by sales_volume.

Common Mistakes

Using Window Functions in WHERE

You cannot use a window function directly in a WHERE clause. This is because the window function is calculated after the filtering happens. To filter based on a window result (like our deduplication example), you must use a Common Table Expression (CTE) or a subquery.

Confusing RANK() and DENSE_RANK()

If two rows have the same value, RANK() will skip the next number (e.g., 1, 2, 2, 4), whereas DENSE_RANK() will not (e.g., 1, 2, 2, 3). Choosing the wrong one can lead to incorrect reporting in your BI tools.

Forgetting the ORDER BY

For functions like ROW_NUMBER() or SUM() running totals, the order is critical. If you omit the ORDER BY inside the OVER clause, the database will treat the rows as an unordered pile, leading to unpredictable results.
