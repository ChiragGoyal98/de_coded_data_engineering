SQL window functions are often the bridge between being a basic SQL user and becoming a data professional. Unlike standard aggregate functions that collapse multiple rows into a single result, window functions allow you to perform calculations across a set of rows while still retaining the individual row data. In the world of ETL (Extract, Transform, Load), this ability to look across "windows" of data is essential for cleaning, transforming, and organizing raw information into usable insights.

Why it Matters in ETL

In data engineering and ETL pipelines, you rarely just "select" data. You have to clean it and prepare it for reporting. Window functions are the preferred tool for several critical tasks:

  • Deduplication: Identifying and removing duplicate records by assigning a unique number to each occurrence.
  • Data Quality: Comparing a value in the current row to a value in the previous row to find anomalies.
  • Cumulative Metrics: Calculating running totals or moving averages for financial reports.
  • Top-N Analysis: Finding the "latest" status or the "highest" sale within specific categories without losing the rest of the table.

Step-by-Step Walkthrough

To master window functions, you need to understand the basic syntax: FUNCTION() OVER (PARTITION BY column ORDER BY column).

1. The ROW_NUMBER() Function for Deduplication

This is perhaps the most used window function in ETL. It assigns a unique sequential integer to rows within a partition. If you have multiple records for the same transaction ID, you can use ROW_NUMBER() to identify the most recent one.


SELECT 
    order_id, 
    status, 
    updated_at,
    ROW_NUMBER() OVER (PARTITION BY order_id ORDER BY updated_at DESC) as row_num
FROM raw_orders;

In an ETL pipeline, you would wrap this in a subquery or a CTE and filter for where row_num = 1 to get the latest state of every order.

2. The SUM() OVER() for Running Totals

In many business intelligence cases, you need to see how revenue grows over time. By using SUM() as a window function, the data is not collapsed into one row per month; instead, every daily row shows the total revenue accumulated up to that date.

3. The LAG() and LEAD() Functions

These are used to "peek" at the previous or next row. This is vital for calculating the time difference between two events (like how long a user spent on a page) or identifying price changes between two consecutive records.

Common Mistakes

  • Using them in the WHERE clause: Window functions are processed late in the SQL execution order. You cannot filter by the result of a window function directly in the same SELECT statement. You must use a Common Table Expression (CTE) or a subquery.
  • Confusing RANK() and DENSE_RANK(): If two rows have the same value, RANK() will skip the next number in the sequence (1, 2, 2, 4), while DENSE_RANK() will not (1, 2, 2, 3).
  • Forgetting ORDER BY: For functions like ROW_NUMBER() or SUM(), the order of the rows within the window determines the result. Forgetting the ORDER BY clause inside the OVER parentheses often leads to unpredictable data.

Practice Task

Imagine you have a table called web_logs with columns user_id, page_url, and timestamp.

The Task: Write a query that shows every column in the table, but adds a new column called previous_page that displays the URL the user visited immediately before the current one.

Hint: Use the LAG() function and partition the data by user_id.
