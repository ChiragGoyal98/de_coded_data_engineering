SQL Window Functions with Real ETL Use Cases

SQL window functions are a powerful feature that allows developers to perform complex calculations over a specific range of rows related to the current row. Unlike aggregate functions that group multiple rows into a single output row, window functions maintain the identity of individual records while still providing summary data. This capability makes them indispensable for data engineering tasks where context and row-level detail are both required simultaneously.

Why it Matters in ETL

In the world of Data Engineering (ETL), we rarely just move data from point A to point B. We often need to clean it, rank it, or calculate trends. Window functions are essential for these tasks for three main reasons:

  • Efficiency: They often replace complex self-joins and subqueries, leading to more readable and performant code.
  • Deduplication: When data arrives with duplicates, window functions help us identify and keep only the "latest" version of a record.
  • Time-Series Analysis: They allow us to compare a current record with a previous one (e.g., "How much did sales grow since yesterday?") without losing the current row's data.

Step-by-Step Walkthrough

The core syntax of a window function follows this pattern: FUNCTION() OVER (PARTITION BY column_a ORDER BY column_b).

1. The ROW_NUMBER() Function for Deduplication

In many ETL pipelines, you might receive multiple updates for the same ID. To get the most recent record, you can use ROW_NUMBER(). This assigns a unique integer to rows within a specific partition.


SELECT 
    order_id, 
    status, 
    updated_at,
    ROW_NUMBER() OVER (PARTITION BY order_id ORDER BY updated_at DESC) as rank_desc
FROM orders_staging;

In this example, the rows are grouped by order_id and sorted by time. The row with rank_desc = 1 is your most recent update.

2. Calculating Running Totals

For financial reporting, you often need a running total of sales over time. Using SUM() as a window function allows you to add up values row-by-row.


SELECT 
    sale_date, 
    amount,
    SUM(amount) OVER (ORDER BY sale_date) as running_total
FROM sales;

Here, the ORDER BY inside the OVER clause tells SQL to add the current amount to the sum of all previous amounts in that order.

3. Comparing Current and Previous Values (LAG)

The LAG() function lets you look at the row immediately preceding the current one. This is perfect for calculating "Day-over-Day" changes.


SELECT 
    sale_date, 
    daily_revenue,
    LAG(daily_revenue) OVER (ORDER BY sale_date) as previous_day_revenue
FROM daily_metrics;

Common Mistakes

  • Confusing PARTITION BY with GROUP BY: Remember that PARTITION BY does not collapse rows. If you use it, you will still get the same number of rows in your output as you had in your input.
  • Forgetting ORDER BY in Ranking Functions: Functions like ROW_NUMBER(), RANK(), and LEAD/LAG require an ORDER BY clause to make sense. Without it, the results will be non-deterministic (random).
  • RANK() vs. DENSE_RANK(): If two items have the same value, RANK() will skip the next number (e.g., 1, 2, 2, 4), while DENSE_RANK() will not (e.g., 1, 2, 2, 3). Choosing the wrong one can lead to logic errors in your reporting.

Practice Task

Imagine you have a table called employee_salaries with columns department_id, employee_name, and salary.

The Task: Write a query to find the top-paid employee in each department.

Hint: Use ROW_NUMBER() or RANK(), partition the data by the department, and sort by salary in descending order. Then, wrap that query in a subquery or a Common Table Expression (CTE) to filter for only the rows where the rank is 1.
