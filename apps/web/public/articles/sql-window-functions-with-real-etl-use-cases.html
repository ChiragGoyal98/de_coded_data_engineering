SQL Window Functions with Real ETL Use Cases

Introduction

When you first start learning SQL, you likely get comfortable with aggregate functions like SUM, AVG, and COUNT. These functions are great for summarizing data, but they have a major limitation: they collapse your rows into a single result. If you want to see individual transaction details alongside a running total or a category rank, standard aggregation won't work. This is where window functions come in. A window function performs a calculation across a set of table rows that are somehow related to the current row. Unlike regular aggregate functions, window functions do not cause rows to become grouped into a single output row; the rows retain their separate identities.

Why it matters

In the world of Extract, Transform, Load (ETL), window functions are essential tools for cleaning and structuring data. They allow data engineers to handle complex logic without the need for multiple, expensive self-joins. For instance, if you are processing a stream of user activity logs, you might need to identify the "latest" status for each user or calculate the time difference between two consecutive events. Window functions make these tasks efficient and readable. They are particularly useful for deduplication, calculating month-over-month growth, and creating ranking systems, all of which are standard requirements in modern data pipelines.

Step-by-step walkthrough

To master window functions, you need to understand the syntax structure, specifically the OVER clause. This clause defines the "window" of data the function will look at.

1. The Core Syntax

The basic structure of a window function is:

FUNCTION_NAME() OVER (PARTITION BY column1 ORDER BY column2)

  • PARTITION BY: This divides the result set into partitions (groups). The function is applied to each partition separately.
  • ORDER BY: This defines the logical order in which the function operates within each partition.

2. Deduplicating Data with ROW_NUMBER()

One of the most common ETL use cases is removing duplicate records. Imagine a scenario where a system sends multiple updates for the same Order ID, and you only want the most recent one based on a timestamp.


SELECT order_id, status, updated_at
FROM (
    SELECT 
        order_id, 
        status, 
        updated_at,
        ROW_NUMBER() OVER (PARTITION BY order_id ORDER BY updated_at DESC) as row_num
    FROM raw_orders
) ranked_data
WHERE row_num = 1;

In this example, ROW_NUMBER() assigns a unique integer to rows within the same order_id group. Because we ordered by updated_at DESC, the most recent update gets the number 1.

3. Creating Running Totals

For financial ETL pipelines, calculating a cumulative sum is a frequent requirement. By using SUM() with the OVER clause, you can calculate a total that grows as you move down the rows.

4. Ranking and Percentiles

Functions like RANK() or DENSE_RANK() help in identifying top-performing products or customers. In an ETL process, this might be used to filter the "Top 10" records before loading them into a reporting dashboard.

Common mistakes

  • Using Window Functions in WHERE: You cannot use a window function directly in a WHERE clause. Because window functions are processed after the WHERE clause filters the data, you must wrap your query in a Subquery or a Common Table Expression (CTE) to filter by the window result (as shown in the deduplication example above).
  • Forgetting ORDER BY in Ranking: If you use ROW_NUMBER() or RANK() without an ORDER BY clause, the results will be non-deterministic. The database will assign numbers arbitrarily, which can lead to inconsistent data in your ETL pipeline.
  • Confusing RANK() and DENSE_RANK(): If two items are tied for 1st place, RANK() will skip the next number (1, 1, 3), whereas DENSE_RANK() will not (1, 1, 2). Choosing the wrong one can skew your reporting metrics.

One practice task

Suppose you have a table called monthly_sales with columns sales_rep, sale_month, and revenue. Write a query using a window function that calculates a running total of revenue for each sales representative, ordered by the month.

Hint: You will need to use SUM(revenue) combined with an OVER clause that partitions by the representative and orders by the month.
