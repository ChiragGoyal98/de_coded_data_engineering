SQL Window Functions with Real ETL Use Cases

SQL window functions are a powerful set of tools that allow you to perform calculations across a set of table rows that are somehow related to the current row. Unlike regular aggregate functions, which group multiple rows into a single output row, window functions keep the individual rows while adding the calculated result as a new column. This makes them indispensable for data engineering tasks where you need to maintain the original data structure while adding context or historical comparisons.

Why it matters in ETL

In the world of Extract, Transform, and Load (ETL), window functions are the "Swiss Army Knife" of data transformation. They allow you to handle complex logic without writing massive, nested subqueries or expensive self-joins.

  • Deduplication: When loading data from multiple sources, you often get duplicate records. Window functions can identify the latest version of a record so you can filter out the old ones.
  • Running Totals: They are used to create cumulative sums for financial reporting or inventory tracking.
  • Gap Analysis: You can easily compare a value in the current row to a value in the previous row to see how much a metric has changed over time.
  • Top-N Analysis: They help in identifying the top performers (like the top 3 sales per region) without losing the detail of individual sales.

Step-by-step walkthrough

The secret to window functions is the OVER clause. This clause tells SQL that you aren't just aggregating data; you are defining a "window" of rows to look at.

1. The Basic Syntax

Every window function follows this pattern:

FUNCTION() OVER (PARTITION BY column_a ORDER BY column_b)

2. Dividing the Data with PARTITION BY

Think of PARTITION BY as a "Group By" that doesn't collapse your rows. It divides the data into logical buckets. For example, if you partition by department_id, the function will reset its calculation every time it hits a new department.

3. Sorting within the Window with ORDER BY

The ORDER BY inside the OVER clause determines the sequence in which the function processes the rows. This is vital for rankings or running totals.

4. Real-World Example: Removing Duplicates

Imagine you have a table called raw_sales where some transactions were accidentally imported twice. You want to keep only the most recent entry for each transaction_id.


SELECT 
    transaction_id, 
    sale_amount, 
    load_timestamp,
    ROW_NUMBER() OVER (
        PARTITION BY transaction_id 
        ORDER BY load_timestamp DESC
    ) as row_num
FROM raw_sales;

In this example, ROW_NUMBER() assigns a '1' to the newest record for every unique transaction ID. In your ETL tool, you would simply filter for rows where row_num = 1.

Common mistakes

  • Using Window Functions in WHERE: You cannot use a window function directly in a WHERE clause. SQL processes the WHERE clause before the window function exists. To filter based on a window function, you must use a Subquery or a Common Table Expression (CTE).
  • Confusing RANK() and DENSE_RANK(): If two rows have the same value, RANK() will skip the next number (1, 2, 2, 4), while DENSE_RANK() will not skip a number (1, 2, 2, 3).
  • Forgetting ORDER BY: Many window functions, like LEAD() or ROW_NUMBER(), require an ORDER BY to produce logical results. Without it, the "first" row is essentially random.

Practice task

Scenario: You are working with a table called user_logins which contains user_id and login_date.

Goal: Write a query that shows each user's login date along with the date of their previous login.

Hint: Use the LAG() function. This function allows you to "pull" a value from the row above the current one.

  • Use PARTITION BY user_id to make sure you only look at logins for that specific user.
  • Use ORDER BY login_date to ensure the dates are in chronological order.
