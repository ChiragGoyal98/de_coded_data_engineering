SQL Window Functions with Real ETL Use Cases

In the world of data engineering, SQL window functions are often described as the "secret sauce" that separates beginners from intermediate practitioners. Unlike standard aggregate functions like SUM or AVG, which collapse multiple rows into a single result, window functions allow you to perform calculations across a set of rows while still keeping every individual row in your output. This unique ability makes them indispensable for building complex data pipelines and performing advanced analytics.

Why it Matters in ETL

ETL (Extract, Transform, Load) processes frequently require data cleaning and restructuring that basic SQL cannot handle efficiently. If you use a GROUP BY clause, you lose the granular details of your original records. Window functions solve this by creating a "window" over your data, allowing you to compare a specific row against other rows in the same category.

In real-world ETL scenarios, window functions are used for:

  • Deduplication: Identifying and removing duplicate records by ranking them based on a timestamp.
  • Trend Analysis: Comparing a current sale to the previous day's sale using offsets.
  • Running Totals: Calculating cumulative sums for financial reporting without self-joins.
  • Sessionization: Grouping user actions into distinct sessions based on time intervals.

Step-by-Step Walkthrough

To use a window function, you need to understand three primary components of the syntax: the Function, the OVER clause, and the PARTITION BY clause.

1. The OVER Clause

The OVER clause is what defines a window function. It tells the database, "Don't collapse these rows; instead, look across this specific range."

2. Partitioning Data

The PARTITION BY sub-clause acts like a "GROUP BY" inside the window. It divides the result set into partitions. For example, if you are processing sales data, you might partition by store_id so that the calculation starts over for every new store.

3. Ordering the Window

The ORDER BY sub-clause within the window defines the sequence in which the function processes the rows. This is critical for functions that rely on chronology, like ranking or running totals.

4. Common ETL Functions

  • ROW_NUMBER(): Assigns a unique sequential integer to rows. This is the gold standard for deduplication.
  • LEAD() and LAG(): These allow you to look at the "next" or "previous" row's value. This is perfect for calculating the time difference between two events.
  • RANK(): Assigns a rank to rows, where ties receive the same rank, but the next rank is skipped (e.g., 1, 2, 2, 4).

Code Example: Removing Duplicates

In ETL, we often receive multiple records for the same ID and only want the most recent one.


SELECT user_id, email, updated_at
FROM (
    SELECT 
        user_id, 
        email, 
        updated_at,
        ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY updated_at DESC) as row_num
    FROM raw_users_table
) ranked_data
WHERE row_num = 1;

Common Mistakes

  • Confusing RANK() and DENSE_RANK(): If you have two items tied for first place, RANK() will label the next item as "3," whereas DENSE_RANK() will label it as "2." Choosing the wrong one can lead to gaps in your data logic.
  • Performance Overheads: While powerful, window functions can be resource-intensive on massive datasets. Always ensure your "Partition By" columns are indexed when possible.
  • Forgetting the Subquery: You cannot use the result of a window function in a WHERE clause in the same query block (e.g., WHERE row_num = 1). You must wrap the window function in a subquery or a Common Table Expression (CTE) first.

Practice Task

Scenario: You have a table called monthly_revenue with columns year, month, and revenue.

The Goal: Write a query that shows each month's revenue alongside the revenue of the previous month to help stakeholders see month-over-month growth.

Hint: Use the LAG() function and order your window by year and month.
