SQL Window Functions with Real ETL Use Cases

SQL window functions are a powerful tool in SQL that allow you to perform calculations across a set of rows related to the current row. Unlike standard aggregate functions like SUM or AVG which collapse rows into a single result, window functions keep the individual rows intact while adding a new column containing the calculated value. This makes them indispensable for data analysis and complex data transformations where row-level detail is still required alongside summarized data.

Why it matters in ETL

In ETL (Extract, Transform, Load) pipelines, data is rarely perfect. We often encounter duplicate records, out-of-order timestamps, or the need to calculate running totals for financial reporting. Window functions allow data engineers to handle these challenges efficiently within the database.

  • Data Deduplication: Using functions like ROW_NUMBER() to identify and remove duplicate entries based on specific criteria.
  • Trend Analysis: Using LAG() or LEAD() to compare the current row's value with a previous or subsequent row (e.g., comparing today's sales to yesterday's).
  • Running Totals: Creating cumulative sums that grow as you move through a dataset.
  • Ranking: Assigning scores or positions to data points within specific categories.

Step-by-step walkthrough

The core of a window function is the OVER() clause. This clause defines the "window" of data the function will look at.

1. The Basic Syntax

A window function generally follows this structure:

SELECT column, FUNCTION() OVER (PARTITION BY col1 ORDER BY col2) FROM table

  • PARTITION BY: This divides the rows into groups (like a GROUP BY, but without collapsing them).
  • ORDER BY: This sorts the rows within each partition.

2. Identifying Duplicates with ROW_NUMBER()

In ETL, we often get "dirty" data with multiple entries for the same ID. We use ROW_NUMBER() to rank them by timestamp and pick the latest one.


SELECT 
    order_id, 
    status, 
    updated_at,
    ROW_NUMBER() OVER (PARTITION BY order_id ORDER BY updated_at DESC) as row_num
FROM orders_staging;

In this example, if order_id 101 appears three times, the most recent update will get row_num = 1. In your ETL script, you would then simply filter for rows where row_num = 1.

3. Comparing Rows with LEAD and LAG

If you want to calculate the difference in price between the current product update and the previous one, you use LAG(). This function "reaches back" to the previous row's value.

4. Running Totals with SUM

By using SUM(amount) OVER (ORDER BY date), SQL calculates a cumulative total. It adds the current row's amount to the sum of all previous rows, which is essential for building financial dashboards.

Common mistakes

  • Using Window Functions in WHERE: You cannot use a window function directly in a WHERE clause. Because of how SQL processes queries, the window calculation happens after filtering. To filter by a window result, you must wrap the query in a Subquery or a Common Table Expression (CTE).
  • Forgetting ORDER BY: For functions like ROW_NUMBER() or RANK(), the order is critical. If you omit ORDER BY, the ranking will be non-deterministic (essentially random).
  • Confusing PARTITION BY with GROUP BY: Remember that GROUP BY reduces the number of rows returned. PARTITION BY does not change the row count; it only changes how the calculation is grouped.

One practice task

The Scenario: You have a table called monthly_sales with columns sales_rep, month, and revenue.

The Task: Write a query that shows each sales representative's revenue for every month, but also includes a column showing their "Previous Month Revenue."

Hint: You will need to use the LAG() function and PARTITION BY the sales representative to ensure you aren't accidentally comparing one person's sales to a different person's sales.
