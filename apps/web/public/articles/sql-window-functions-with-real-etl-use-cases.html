SQL Window Functions with Real ETL Use Cases

Window functions are a specialized class of SQL operations that allow you to perform calculations across a set of table rows related to the current row. Unlike standard aggregate functions, which collapse multiple rows into a single result, window functions keep the individual rows intact while appending a calculated value to each one. This makes them incredibly useful for complex data transformations where you need to look at surrounding data without losing the detail of the record you are currently processing.

Why it matters in ETL

In Extract, Transform, Load (ETL) pipelines, data is rarely clean or perfectly structured. You often need to perform tasks like identifying the most recent record among duplicates, calculating running totals for financial reports, or comparing a current value to a previous one.

Without window functions, these tasks usually require complex self-joins or temporary tables, which are computationally expensive and hard to read. Window functions provide a "sliding window" view of your data, allowing you to perform advanced analytics directly within the transformation layer of your pipeline. This leads to faster execution times and more maintainable SQL code.

Step-by-step walkthrough

The core of a window function is the OVER clause. This clause defines the "window" of data the function will look at. There are three primary components you will use:

  • PARTITION BY: This divides the result set into groups (similar to GROUP BY).
  • ORDER BY: This sorts the rows within each partition.
  • Function: The actual calculation, such as ROW_NUMBER(), RANK(), or SUM().

Case 1: Deduplication with ROW_NUMBER()

A common ETL challenge is receiving duplicate records for the same ID. To keep only the most recent entry based on a timestamp, you can use ROW_NUMBER().


SELECT 
    user_id, 
    order_date, 
    status
FROM (
    SELECT 
        user_id, 
        order_date, 
        status,
        ROW_NUMBER() OVER(PARTITION BY user_id ORDER BY order_date DESC) as row_num
    FROM raw_orders
) ranked_orders
WHERE row_num = 1;

In this example, the window function partitions the data by user_id. Within each user group, it orders the records by date. The record with the newest date gets assigned a 1. By filtering for row_num = 1, we effectively remove all older duplicates.

Case 2: Running Totals with SUM()

ETL processes often require cumulative metrics. By using SUM() with an ORDER BY inside the OVER clause, SQL calculates a running total.


SELECT 
    sale_date, 
    amount,
    SUM(amount) OVER(ORDER BY sale_date) as running_total
FROM daily_sales;

As the engine processes each row, it adds the current amount to the sum of all previous amounts in the window, creating a continuous accumulation.

Common mistakes

  • Confusing RANK() and ROW_NUMBER(): ROW_NUMBER() always gives a unique number (1, 2, 3). RANK() gives the same number to tied values (1, 2, 2, 4), which can lead to unexpected results if you are trying to pick exactly one record.
  • Forgetting ORDER BY: For many window functions like LEAD(), LAG(), or running totals, forgetting the ORDER BY inside the OVER clause will result in non-deterministic or incorrect values because the "sequence" of data isn't defined.
  • Filtering in the same query: You cannot use a window function result in a WHERE clause in the same query block (e.g., WHERE row_num = 1). You must use a Subquery or a Common Table Expression (CTE) to filter the results, as shown in the deduplication example above.

Hint: Use the LAG() function, which fetches data from a previous row.
