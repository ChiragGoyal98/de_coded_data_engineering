SQL Window Functions with Real ETL Use Cases

SQL is a powerful tool for data transformation, but standard aggregation can sometimes feel limiting. Usually, when we use a GROUP BY clause, we collapse multiple rows into a single summary row. Window functions change the game by allowing us to perform calculations across a set of rows while still keeping every individual record visible in the final output. This makes them indispensable for data engineering tasks where we need to enrich data without losing detail.

Why it matters in ETL

In the world of Extract, Transform, Load (ETL), window functions are the "Swiss Army Knife" of data cleaning and enrichment. They allow data engineers to solve complex logic problems with readable, high-performance code.

  • Data Deduplication: Identifying and removing duplicate records by ranking them based on a timestamp.
  • Running Totals: Calculating cumulative sums for financial reporting or inventory tracking.
  • Trend Analysis: Comparing a current row's value to a previous row (e.g., month-over-month growth) using LEAD and LAG.
  • Sessionization: Grouping user events into distinct sessions based on time gaps.

Step-by-step walkthrough

To use a window function, you need to understand the OVER clause. This clause defines the "window" of data the function will look at.

1. The Basic Syntax

The standard structure looks like this:

FUNCTION() OVER (PARTITION BY column_a ORDER BY column_b)

  • PARTITION BY: This divides the result set into groups (like GROUP BY, but rows stay separate).
  • ORDER BY: This defines the sequence of rows within each partition.

2. Deduplicating Data with ROW_NUMBER()

A common ETL task is keeping only the most recent entry for a specific ID. Imagine a table where a user updated their profile multiple times, and we only want the latest version.


SELECT 
    user_id, 
    email, 
    updated_at
FROM (
    SELECT 
        user_id, 
        email, 
        updated_at,
        ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY updated_at DESC) as rank_order
    FROM raw_user_data
) 
WHERE rank_order = 1;

In this example, PARTITION BY user_id ensures the counting starts over for every user. ORDER BY updated_at DESC ensures the newest record gets the number 1.

3. Comparing Rows with LAG()

If you need to calculate the difference in sales between today and yesterday, you use LAG(). This function "reaches back" to a previous row within your defined window. This is much more efficient than performing a self-join on a massive table.

4. Running Totals with SUM()

By using SUM(amount) OVER (ORDER BY transaction_date), SQL calculates a cumulative sum. It adds the current row's value to the sum of all previous rows in the sequence.

Common mistakes

  • Mixing up RANK() and ROW_NUMBER(): ROW_NUMBER() always assigns a unique number (1, 2, 3). RANK() will give the same number to tied values (1, 2, 2, 4), which can lead to unexpected results if you are trying to pick exactly one record.
  • Forgetting the ORDER BY: Many window functions, like RANK or LEAD, require an ORDER BY clause to make sense. Without it, the "order" is non-deterministic, and your results will change every time you run the query.
  • Performance overhead: While window functions are efficient, applying them over millions of rows without a PARTITION BY clause can force the database to sort the entire dataset in memory, which may slow down your ETL pipeline.

One practice task

The Scenario: You have a table called website_traffic with columns visitor_id, page_view_time, and page_name.

The Task: Write a query that shows each page view alongside the name of the previous page that specific visitor viewed.

Hint: Use the LAG() function and partition by the visitor.
