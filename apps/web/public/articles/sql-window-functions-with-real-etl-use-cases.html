Introduction

SQL window functions are powerful tools that allow you to perform calculations across a set of table rows that are somehow related to the current row. Unlike a traditional GROUP BY clause, which collapses your result set into a single summary row for each group, window functions preserve the original row-level detail. This makes them indispensable in the world of Extract, Transform, and Load (ETL) processes, where you often need to enrich individual records with contextual data or perform rankings without losing the granularity of your dataset.

Why it matters

In data engineering and ETL pipelines, data often arrives in a raw, messy state. Window functions are the "Swiss Army Knife" for cleaning and transforming this data for several reasons:

  • Deduplication: They allow you to identify and remove duplicate records by ranking them based on timestamps.
  • Trend Analysis: You can calculate running totals, moving averages, or month-over-month growth easily.
  • Efficiency: They are often more performant than complex self-joins or correlated subqueries, especially on large datasets.
  • Data Integrity: Because they don't collapse rows, you can compare a specific record's value against its group average in a single step.

Step-by-step walkthrough

The basic syntax for a window function is FUNCTION() OVER (PARTITION BY column ORDER BY column). Let's break down the three most common ETL use cases.

1. Deduplicating Data with ROW_NUMBER()

In ETL, you often receive multiple updates for the same record. To keep only the most recent version, you use ROW_NUMBER(). This assigns a unique integer to rows within a partition.


SELECT 
    user_id, 
    email, 
    updated_at,
    ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY updated_at DESC) as rank
FROM raw_users;

By filtering for rank = 1 in a subquery, you effectively keep only the latest entry for each user.

2. Calculating Running Totals with SUM()

ETL processes often require transforming transaction logs into cumulative reports. By using an aggregate function with an ORDER BY clause inside the OVER() window, SQL creates a running calculation.


SELECT 
    sale_date, 
    amount,
    SUM(amount) OVER (ORDER BY sale_date) as cumulative_sales
FROM sales_data;

3. Finding Differences with LAG() and LEAD()

To detect changes between the current record and the previous one (like a price change), use LAG(). This "looks back" at the previous row without requiring a join.


SELECT 
    product_id, 
    price,
    LAG(price) OVER (PARTITION BY product_id ORDER BY effective_date) as previous_price
FROM product_history;

Common mistakes

  • Confusing RANK() and DENSE_RANK(): RANK() leaves gaps in the numbering if there is a tie (e.g., 1, 2, 2, 4), while DENSE_RANK() does not (e.g., 1, 2, 2, 3). In ETL, using the wrong one can lead to missing or extra records during filtering.
  • Forgetting PARTITION BY: If you omit the partition, the function treats the entire table as one giant group. This often leads to incorrect calculations when you meant to group by a specific ID or Category.
  • Filtering in the same step: You cannot use window function results in a WHERE clause in the same query block. You must wrap the query in a CTE (Common Table Expression) or a subquery to filter by the windowed value.

One practice task

Scenario: You have a table called web_sessions with columns session_id, user_id, and duration_seconds.

Task: Write a query that shows every session, but also adds a column showing the average session duration for that specific user next to every row.

Hint: Use the AVG() function combined with an OVER() clause and partition by the user.
