SQL Window Functions with Real ETL Use Cases

In the world of data engineering and analytics, we often need to perform calculations across a set of rows while still maintaining the identity of each individual row. Traditional aggregate functions like SUM or AVG used with a GROUP BY clause "collapse" your data, hiding the individual records to show only the summary. Window functions, however, allow you to have the best of both worlds: you can see the granular detail of every transaction while simultaneously seeing calculations like running totals, rankings, or moving averages right next to them.

Why Window Functions Matter in ETL

Data engineering involves Extract, Transform, and Load (ETL) processes where data quality and structure are paramount. Window functions are essential tools for these transformations for three main reasons:

  • Deduplication: When landing data from multiple sources, you often find duplicate records. Window functions help identify the "latest" version of a record based on a timestamp.
  • Performance: Instead of performing complex self-joins to compare a row to its predecessor, a window function can do this in a single pass over the data.
  • Data Enrichment: They allow you to add context to your data, such as calculating a customer's lifetime value or their rank in sales without losing the specific details of their individual purchases.

Step-by-Step Walkthrough

To master window functions, you need to understand the three components of the OVER() clause, which defines the "window" of data the function looks at.

1. The PARTITION BY Clause

This acts like a GROUP BY but for your window. It divides the rows into groups (partitions) that the function will be applied to. For example, if you partition by store_id, a ranking function will start over at "1" for every new store.

2. The ORDER BY Clause

This determines the sequence of rows within each partition. This is crucial for "running" calculations (like a running total) or for determining which record comes first in a ranking.

3. The Function Itself

Common functions include ROW_NUMBER() (for unique IDs), RANK() (for leaderboards), and SUM() (for running totals).

ETL Use Case: Deduplicating Records

In many ETL pipelines, you receive multiple updates for the same ID. To keep only the most recent record, you can use ROW_NUMBER().


SELECT 
    order_id, 
    customer_id, 
    status, 
    updated_at
FROM (
    SELECT 
        *,
        ROW_NUMBER() OVER(PARTITION BY order_id ORDER BY updated_at DESC) as row_num
    FROM raw_orders_table
) 
WHERE row_num = 1;

In this example, the window function assigns "1" to the most recent update for each order_id. By filtering for row_num = 1 in the outer query, we successfully deduplicate our dataset.

Common Mistakes

  • Forgetting the ORDER BY in Ranking: Functions like RANK() or ROW_NUMBER() require an ORDER BY clause. Without it, the database will assign numbers arbitrarily, leading to inconsistent results.
  • Overusing Window Functions on Huge Datasets: While powerful, window functions can be resource-intensive. If you are partitioning by a column with millions of unique values on a small server, it may slow down your ETL pipeline.
  • Confusing RANK() and DENSE_RANK(): If two rows have the same value, RANK() will skip the next number (1, 2, 2, 4), while DENSE_RANK() will not (1, 2, 2, 3). Choosing the wrong one can lead to reporting errors.

Practice Task

Suppose you have a table called monthly_sales with columns sales_rep, month, and revenue. Write a query that shows each sales representative's revenue for every month, alongside a column showing their "Running Total" revenue for the year so far.

Hint: Use SUM(revenue) combined with PARTITION BY sales_rep and ORDER BY month.
