SQL Window Functions with Real ETL Use Cases

In the world of data engineering and ETL (Extract, Transform, Load) processes, window functions are often the bridge between basic querying and advanced data transformation. While standard aggregate functions like SUM or AVG collapse multiple rows into a single result, window functions allow you to perform calculations across a set of rows while still maintaining the individual identity of every record. This makes them indispensable for tasks like identifying the most recent record in a dataset or calculating growth trends over time.

Why it matters

In a typical ETL pipeline, data arrives from various sources in a raw, often messy format. You might encounter duplicate records, or you might need to calculate cumulative values for a dashboard. Using standard SQL techniques like GROUP BY often forces you to lose the detail of individual rows.

Window functions solve this by creating a "window" of data for the calculation to look at. For data engineers, this is a lifesaver when performing:

  • Deduplication: Keeping only the latest version of a record.
  • Ranking: Finding the top-performing products or latest log entries.
  • Running Totals: Tracking how a metric accumulates over a period.
  • Lead/Lag Analysis: Comparing the current row to the previous or next row (e.g., measuring the time between two user clicks).

Step-by-step walkthrough

To master window functions, you need to understand the three main components of the syntax: the function itself, the partition, and the order.

1. The Function

Common functions include ROW_NUMBER() (to number rows), RANK() (to rank items), or SUM() (to aggregate).

2. PARTITION BY

This defines the group. If you want to calculate sales per "Category," you partition by Category. If you don't specify this, the function treats the entire table as one big group.

3. ORDER BY

This defines the sequence within the partition. For a running total, you would order by date. For finding the "latest" record, you would order by a timestamp in descending order.

Real ETL Case: Removing Duplicates

Imagine you have a table called raw_orders where some orders were sent twice by mistake. You want to keep only the most recent entry for each order_id.


WITH RankedOrders AS (
    SELECT 
        order_id, 
        status, 
        updated_at,
        ROW_NUMBER() OVER (PARTITION BY order_id ORDER BY updated_at DESC) as row_num
    FROM raw_orders
)
SELECT * 
FROM RankedOrders 
WHERE row_num = 1;

In this example, PARTITION BY order_id groups the rows by the ID, and ORDER BY updated_at DESC ensures the newest record gets the number 1. By filtering for row_num = 1, we effectively clean our data.

Common mistakes

  • Using Window Functions in WHERE: You cannot use a window function directly in a WHERE clause (e.g., WHERE ROW_NUMBER() = 1). You must use a Subquery or a Common Table Expression (CTE), as shown in the example above, because window functions are processed after the filtering stage.
  • Forgetting ORDER BY: For functions like ROW_NUMBER() or RANK(), the ORDER BY clause is mandatory. Forgetting it will often lead to an error or unpredictable results.
  • Confusion between RANK and DENSE_RANK: If two rows have the same value, RANK() will skip the next number (e.g., 1, 2, 2, 4), while DENSE_RANK() will not skip (e.g., 1, 2, 2, 3).

One practice task

Suppose you have a table named employee_salaries with columns department, employee_name, and salary. Write a query to find the highest-paid employee in each department.

Hint: Use ROW_NUMBER() or RANK(), partition by the department, and order by salary in descending order.
