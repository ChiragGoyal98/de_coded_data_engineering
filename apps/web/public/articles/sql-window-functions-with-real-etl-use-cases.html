SQL Window Functions with Real ETL Use Cases

SQL window functions perform calculations across a set of table rows that are related to the current row. Unlike standard aggregate functions, which collapse multiple rows into a single result, window functions allow each row to retain its individual identity while still accessing data from other rows in the result set. This capability makes them a foundational tool for data engineers who need to perform complex analytical calculations without losing the granular detail of their source data.

Why it matters

In the world of ETL (Extract, Transform, Load), window functions are essential for cleaning and organizing data. They solve specific problems that would otherwise require dozens of lines of complex joins or subqueries. For example, when processing data from multiple sources, you might encounter duplicate records. A window function can help you identify the "most recent" version of a record instantly. They are also crucial for calculating business metrics like running totals, year-over-year growth, or ranking items within specific categories, such as finding the top-selling product for every individual region in a global dataset.

Step-by-step walkthrough

To use a window function, you need to understand three main components: the function itself, the OVER clause, and optional modifiers like PARTITION BY and ORDER BY.

1. The Core Syntax

The basic structure looks like this: FUNCTION() OVER (PARTITION BY column_a ORDER BY column_b). The PARTITION BY clause acts like a group, telling the database where to start and stop the calculation. The ORDER BY clause determines the sequence in which the function processes the rows within those groups.

2. A Real ETL Use Case: Deduplication

Imagine an ETL pipeline where a "Users" table receives multiple updates for the same person. You only want to keep the most recent update based on a timestamp.


SELECT 
    user_id, 
    email, 
    updated_at,
    ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY updated_at DESC) as row_num
FROM raw_users_table;

In this example, ROW_NUMBER() assigns a '1' to the newest record for every unique user_id. In your next ETL step, you can simply filter for where row_num = 1 to get a clean, deduplicated dataset.

3. Understanding Ranking vs. Numbering

While ROW_NUMBER() gives every row a unique incrementing integer, functions like RANK() or DENSE_RANK() handle ties differently. If two rows have the exact same timestamp, RANK() might skip a number (1, 2, 2, 4), whereas ROW_NUMBER() will always provide a sequential list (1, 2, 3, 4).

Common mistakes

  • Confusing GROUP BY with PARTITION BY: Remember that GROUP BY reduces the number of rows returned by the query. PARTITION BY does not change the row count; it simply defines the "window" of rows the function looks at.
  • Forgetting the ORDER BY in Ranking: If you use ROW_NUMBER() without an ORDER BY clause, the database will assign numbers arbitrarily. This leads to non-deterministic results, meaning your ETL pipeline might produce different data every time it runs.
  • Performance Overload: Running window functions on millions of rows without proper indexing on the PARTITION BY columns can significantly slow down your database.

One practice task

Suppose you have a table called monthly_sales with three columns: region, sale_month, and revenue.

Task: Write a query that calculates a running total of revenue for each region, ordered by the month.

Hint: Use the SUM() function combined with OVER (PARTITION BY ... ORDER BY ...).
