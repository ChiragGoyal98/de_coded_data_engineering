SQL Window Functions with Real ETL Use Cases

SQL window functions are a powerful feature that allows you to perform calculations across a set of table rows that are somehow related to the current row. Unlike standard aggregate functions like SUM or AVG, which collapse multiple rows into a single result, window functions keep each row's identity intact. This makes them essential for data engineering tasks where you need to compare individual records against group statistics or manage chronological sequences without losing the original row-level detail.

Why it matters

In the world of ETL (Extract, Transform, Load), window functions are indispensable for data quality and reporting. They allow you to remove duplicate records by ranking them, calculate year-to-date totals for financial dashboards, and identify trends across time series. Without window functions, these tasks would require complex self-joins or multiple subqueries, which significantly slow down your pipelines and make your code harder to maintain. By using these functions, you can write cleaner, more efficient SQL that processes large datasets with ease.

Step-by-step walkthrough

To master window functions, you need to understand the syntax and the most common functions used in data pipelines.

1. The Basic Syntax

Every window function uses the OVER clause. Inside this clause, you define two main components:

  • PARTITION BY: This divides the rows into groups (or "windows") based on a column.
  • ORDER BY: This determines the sequence of rows within each partition.

2. Common Functions in ETL

  • ROW_NUMBER(): Assigns a unique sequential integer to rows.
  • RANK(): Assigns a rank to rows, but leaves gaps if there are ties.
  • SUM() OVER: Calculates a running total or a group total without collapsing the rows.

3. Use Case: Deduplicating Data

A frequent ETL challenge is receiving duplicate records for the same transaction. To keep only the most recent entry, you can use ROW_NUMBER().


WITH RankedOrders AS (
  SELECT 
    order_id, 
    status, 
    updated_at,
    ROW_NUMBER() OVER (PARTITION BY order_id ORDER BY updated_at DESC) as latest_record
  FROM raw_sales_data
)
SELECT * 
FROM RankedOrders 
WHERE latest_record = 1;

In this example, we group the data by order_id and sort it so the newest update comes first. By filtering for latest_record = 1, we effectively remove the older, stale entries.

Common mistakes

  • Using Window Functions in WHERE clauses: You cannot use a window function directly in a WHERE clause. SQL processes the WHERE clause before the window function. You must wrap the logic in a Common Table Expression (CTE) or a subquery first.
  • Confusing RANK() and DENSE_RANK(): RANK() will skip numbers if there is a tie (1, 2, 2, 4), while DENSE_RANK() will not (1, 2, 2, 3). Choosing the wrong one can lead to incorrect reporting logic.
  • Forgetting ORDER BY in Running Totals: If you use SUM(amount) OVER (PARTITION BY user_id), it will give you the total sum for the whole user. If you want a running total (row by row), you must include ORDER BY date.

One practice task

Imagine you have a table named monthly_revenue with columns region, month, and revenue. Write a query that calculates the running total of revenue for each region, ordered by the month.

Hint: Use SUM(revenue) combined with PARTITION BY region and ORDER BY month. This will allow you to see how revenue accumulates over time for each specific territory.
