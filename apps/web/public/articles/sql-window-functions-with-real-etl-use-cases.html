SQL Window Functions with Real ETL Use Cases

In the world of data manipulation, SQL window functions are often seen as an intermediate hurdle for developers, but they are actually straightforward tools that allow you to perform calculations across rows while still maintaining the details of each individual row. Unlike standard aggregate functions that group multiple rows into a single result, window functions use the OVER clause to define a "window" of data. This allows you to compute things like running totals or rankings without losing the context of the specific record you are looking at, making them indispensable for modern data transformation tasks.

Why it Matters in ETL

In Extract, Transform, Load (ETL) pipelines, we rarely just move data from point A to point B. We usually need to clean it, compare it to previous versions, or rank it.

Before window functions, developers had to use complex self-joins or subqueries to achieve these results. This was not only hard to read but also computationally expensive. Window functions solve this by:

  • Reducing Complexity: Accomplishing in one line what used to take ten.
  • Improving Performance: Processing data in a single pass rather than multiple scans.
  • Ensuring Data Integrity: Easily identifying and removing duplicate records in a landing zone.

Step-by-Step Walkthrough

The basic syntax of a window function follows this pattern:

FUNCTION_NAME() OVER (PARTITION BY column1 ORDER BY column2)

1. Removing Duplicates with ROW_NUMBER()

One of the most common ETL tasks is "deduplication." Imagine a scenario where a system sends multiple updates for the same order ID. You only want the most recent one.


SELECT order_id, status, update_time
FROM (
  SELECT *,
         ROW_NUMBER() OVER (PARTITION BY order_id ORDER BY update_time DESC) as row_num
  FROM raw_orders
) t
WHERE row_num = 1;

In this example, PARTITION BY order_id tells SQL to group the rows by the order ID, and ORDER BY update_time DESC ensures the latest update gets a row_num of 1.

2. Tracking Changes with LAG()

In ETL, we often need to see how a value changed compared to the previous record. LAG() looks at the row immediately before the current one.


SELECT 
    sensor_id, 
    reading_time, 
    temperature,
    LAG(temperature) OVER (PARTITION BY sensor_id ORDER BY reading_time) as previous_temp
FROM sensor_logs;

This is perfect for calculating the "delta" or difference between two data points in a time-series pipeline.

3. Calculating Running Totals with SUM()

Window functions aren't just for ranking; you can use aggregates too. By adding an ORDER BY inside the OVER clause, the aggregate becomes a "running" calculation.


SELECT 
    sale_date, 
    amount,
    SUM(amount) OVER (ORDER BY sale_date) as running_total
FROM sales_report;

Common Mistakes

  • Using Window Functions in WHERE: You cannot use a window function directly in a WHERE clause. SQL processes the WHERE clause before the window function. To filter based on a window result, you must use a Subquery or a Common Table Expression (CTE).
  • Forgetting the ORDER BY: For functions like ROW_NUMBER() or RANK(), the ORDER BY inside the OVER clause is mandatory. Without it, the database doesn't know how to assign the sequence.
  • Confusing RANK() and DENSE_RANK(): If two rows have the same value, RANK() will skip the next number (1, 2, 2, 4), while DENSE_RANK() will not skip (1, 2, 2, 3). Using the wrong one can lead to "missing" ranks in your reporting.

Practice Task

The Scenario: You have a table named web_traffic with columns user_id, session_id, and timestamp.

The Goal: Write a query that identifies the first page visit of every unique session for every user.

  • Use a CTE or Subquery.
  • Use ROW_NUMBER().
  • Filter for the records where the row number is equal to 1.
