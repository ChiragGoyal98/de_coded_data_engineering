SQL Window Functions with Real ETL Use Cases

Category: Programming Basics

Welcome to the DE-Coded Lab! If you've been working with SQL for a while, you've likely mastered GROUP BY and JOIN. But there comes a point in every data engineer's journey where these basic tools feel a bit clunky-especially when you need to perform calculations across rows without "collapsing" your data.

This is where Window Functions come in. Let's break down how they work and how they simplify complex ETL (Extract, Transform, Load) tasks.

Introduction

A Window Function performs a calculation across a set of table rows that are somehow related to the current row. Unlike regular aggregate functions (SUM, AVG), which group multiple rows into a single output row, window functions allow you to keep your original rows while adding a new column containing the calculation.

Think of it like a "sliding window" that moves through your dataset, looking at a specific neighborhood of rows to calculate a value for the one you are currently standing on.

Why it Matters

In the world of ETL and Data Engineering, Window Functions are your "Swiss Army Knife." They are essential because:

  • Row Detail Retention: You can calculate a total or an average without losing the individual transaction details.
  • Deduplication: They are the gold standard for identifying and removing duplicate records in a landing zone.
  • Trend Analysis: Calculating "Month-over-Month" growth or "Running Totals" is nearly impossible without them.
  • Data Cleaning: They help identify the "most recent" record in a history of changes (SCD Type 1/2 logic).

Step-by-step Walkthrough

To use a window function, you need three main components: the Function, the Partition, and the Order.

1. The Basic Syntax

The magic keyword is OVER.


SELECT 
    column_name,
    FUNCTION() OVER (PARTITION BY group_col ORDER BY sort_col) as alias
FROM table;

2. PARTITION BY (The Grouping)

This defines the "window." If you want to calculate sales per *Category*, you PARTITION BY category. If you leave this out, the window is the entire table.

3. ORDER BY (The Sequence)

This determines the order in which the function processes the rows. This is vital for "Running Totals" or "Rankings."

4. Real ETL Use Case: Deduplication

Imagine you have a sales table with duplicate entries. You want to keep only the latest entry for each order_id.


WITH RankedSales AS (
    SELECT 
        order_id, 
        sale_date, 
        amount,
        -- Assign a 1 to the most recent record per order
        ROW_NUMBER() OVER (PARTITION BY order_id ORDER BY sale_date DESC) as row_num
    FROM raw_sales_table
)
SELECT * 
FROM RankedSales 
WHERE row_num = 1;

5. Real ETL Use Case: Growth Tracking

ETL pipelines often require comparing today's value to yesterday's. The LAG() function looks back at the previous row.


SELECT 
    sale_date,
    daily_revenue,
    -- Get the revenue from the previous day
    LAG(daily_revenue) OVER (ORDER BY sale_date) as prev_day_revenue
FROM daily_metrics;

Common Mistakes

  • Forgetting the ORDER BY: For functions like RANK() or LEAD(), forgetting the ORDER BY inside the OVER clause will lead to unpredictable results or errors.
  • Filtering in the same SELECT: You cannot use a window function result in a WHERE clause in the same query block (e.g., WHERE row_num = 1). You must use a Subquery or a Common Table Expression (CTE).
  • Performance Overhead: Using window functions on massive datasets without proper indexing or partitioning can be slow, as the database has to sort the data in memory.
  • Confusing RANK() vs DENSERANK(): RANK() leaves gaps (1, 2, 2, 4), while DENSERANK() does not (1, 2, 2, 3). Choose the one that fits your business logic!

Practice Task

The Scenario: You have a table called userlogins with columns userid and login_timestamp.

The Goal: Write a query that shows each user's login time alongside the timestamp of their *previous* login. This is a common step for calculating "Session Duration" in ETL pipelines.

*(Hint: Use the LAG() function partitioned by the user and ordered by the time.)*
