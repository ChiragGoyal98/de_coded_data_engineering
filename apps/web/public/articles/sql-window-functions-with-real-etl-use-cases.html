SQL Window Functions with Real ETL Use Cases

In the world of data engineering, we often need to analyze a specific row in the context of the rows around it. Window functions allow you to perform calculations across a set of table rows that are somehow related to the current row. Unlike a standard GROUP BY, which collapses your data into a single summary row, window functions preserve the original rows while adding the calculation results as a new column. This unique behavior makes them a fundamental tool for building sophisticated data pipelines.

Why it matters in ETL

In Extract, Transform, Load (ETL) processes, window functions are the go-to solution for data cleaning and enrichment. They are particularly vital for:

  • Deduplication: Identifying the "most recent" version of a record in a raw landing zone by ranking entries by timestamp.
  • Trend Analysis: Calculating running totals or moving averages to provide business insights directly in the database layer.
  • Data Integrity: Comparing a value in the current row to the value in the preceding row to find gaps in sequence numbers or sudden spikes in sensor data.

By using window functions, you can handle these logic-heavy transformations directly in SQL, often resulting in better performance and more readable code than if you were to process them in an external script.

Step-by-step walkthrough

To understand how these functions work, you need to understand the three components of the OVER() clause: PARTITION BY, ORDER BY, and the Frame clause.

1. Defining the Group with PARTITION BY

Think of PARTITION BY as a "local" group by. It divides the result set into partitions. The window function is applied to each partition separately. For example, if you partition by department_id, the calculation resets every time a new department appears in the data.

2. Ordering within the Window

The ORDER BY clause within a window function defines the sequence in which the function processes the rows. This is essential for functions like RANK() or ROW_NUMBER(), where the "first" or "last" row depends entirely on the sort order.

3. Applying the Function

The most common ETL use case is identifying the latest record for a specific ID. We use ROW_NUMBER() for this.


SELECT 
    order_id, 
    customer_id, 
    order_date,
    ROW_NUMBER() OVER (
        PARTITION BY customer_id 
        ORDER BY order_date DESC
    ) as sequence_rank
FROM orders;

In this example, every customer's orders are grouped together. Within those groups, the orders are sorted from newest to oldest. The most recent order for every customer will have a sequence_rank of 1, allowing us to easily filter out older, duplicate, or irrelevant entries in a later step of our pipeline.

Common mistakes

  • Confusing RANK() and DENSE_RANK(): If two rows have the same value, RANK() will leave a gap in the numbering (e.g., 1, 2, 2, 4), while DENSE_RANK() will not (e.g., 1, 2, 2, 3). Using the wrong one can lead to "missing" data in your reports.
  • Filtering in the same step: You cannot use window function results in a WHERE clause in the same query. You must wrap the query in a subquery or a Common Table Expression (CTE) first.
  • Ignoring NULLs: By default, some window functions handle NULLs differently. Always verify how your specific SQL dialect (like Snowflake, BigQuery, or Postgres) treats NULL values in an ORDER BY clause within the window.

Practice task

Imagine you have a table called monthly_revenue with columns month and revenue_amount.

Task: Write a query that calculates a "Running Total" of revenue. The output should show the revenue for the current month alongside the total revenue accumulated from the beginning of the year up to that month.

Hint: Use the SUM() function combined with an OVER clause that orders by the month column.
