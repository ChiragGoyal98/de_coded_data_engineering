SQL Window Functions with Real ETL Use Cases

SQL window functions are a powerful feature that allow you to perform calculations across a set of rows while still retaining access to individual row details. Unlike traditional aggregate functions like SUM or AVG, which collapse multiple rows into a single result, window functions keep your data structure intact while adding extra context to each row. This makes them indispensable for data engineering tasks where you need to analyze trends or rank items without losing the underlying data granularity.

Why it matters

In the world of ETL (Extract, Transform, Load), data is rarely perfect or ready for analysis immediately. You often need to handle "stateful" transformations-tasks that require looking at one row in relation to others. Without window functions, developers are forced to use complex self-joins or multiple subqueries, which are difficult to read and slow to execute.

Window functions are essential for:

  • Deduplication: Identifying and removing duplicate records by keeping only the most recent entry.
  • Running Totals: Calculating cumulative sums for financial reporting.
  • Time-series Analysis: Comparing a current row's value to the previous day's value (e.g., month-over-month growth).
  • Ranking: Assigning priority to rows based on specific criteria like sales volume or timestamp.

Step-by-step walkthrough

To master window functions, you must understand the basic syntax structure: FUNCTION() OVER (PARTITION BY ... ORDER BY ...).

1. The Partition and Order

The PARTITION BY clause acts like a "group by" within the window; it tells SQL to reset the calculation for every new group. The ORDER BY clause determines the sequence in which the function processes the rows within those groups.

2. Common ETL Functions

  • ROW_NUMBER(): Assigns a unique integer to each row. This is the gold standard for deduplication.
  • RANK() vs DENSE_RANK(): Used for leaderboard-style calculations.
  • LAG() and LEAD(): Allow you to "reach" into previous or subsequent rows without a join.

3. Practical Code Example

Suppose you have a sales table and you need to calculate a running total of sales for each specific store. This allows the business to see how revenue accumulates over time.


SELECT 
    store_id, 
    sale_date, 
    amount,
    SUM(amount) OVER (PARTITION BY store_id ORDER BY sale_date) AS running_total
FROM sales_data;

In this example, the SUM resets every time a new store_id appears, and it adds the amounts in chronological order based on the sale_date.

Common mistakes

  • Using Window Functions in WHERE: You cannot use a window function directly in a WHERE clause because they are processed after the filtering phase. To filter based on a window function result (like selecting only row_number = 1), you must wrap the query in a Common Table Expression (CTE) or a subquery.
  • Forgetting the ORDER BY: For functions like ROW_NUMBER() or SUM() (running totals), forgetting the ORDER BY inside the OVER clause will lead to unpredictable or "flat" results where every row in the partition gets the same value.
  • RANK vs DENSE_RANK Confusion: If two items are tied for 1st place, RANK() will make the next item 3rd (skipping 2nd). DENSE_RANK() will make the next item 2nd. Using the wrong one can lead to "missing" ranks in your reports.

One practice task

Imagine you have a table called web_sessions with columns user_id, session_start, and pages_viewed.

The Task: Write a query that assigns a rank to each user's sessions, where the most recent session is ranked number 1. If a user has multiple sessions, the ranking should reset for each user.

Hint: Use the ROW_NUMBER() function and remember to partition by the user identification.
