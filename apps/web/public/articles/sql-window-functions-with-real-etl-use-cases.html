SQL Window Functions with Real ETL Use Cases

SQL window functions are a specialized tool that allow you to perform calculations across a set of table rows that are related to the current row. Unlike a traditional GROUP BY clause, which collapses your data into summary rows, window functions keep the individual rows visible while adding the calculated result as a new column. This unique ability to look at both the "big picture" and the "detail" simultaneously makes them essential for modern data processing.

Why it matters

In the world of ETL (Extract, Transform, Load), data is rarely perfect. You often encounter scenarios where you need to clean up duplicates, calculate running totals, or identify the most recent update in a series of events. Window functions provide a clean, readable way to handle these transformations without the need for complex subqueries or expensive self-joins.

Using window functions improves performance and maintainability. For a data engineer, they are the go-to solution for:

  • Deduplicating data in a landing zone.
  • Calculating month-over-month growth.
  • Assigning unique IDs or ranks based on specific criteria.
  • Comparing a single record against an average or total within its category.

Step-by-step walkthrough

To use a window function, you need to understand the three primary components of the OVER() clause: PARTITION BY, ORDER BY, and the function itself.

1. The Core Syntax

The basic structure looks like this: FUNCTION() OVER (PARTITION BY column_a ORDER BY column_b).

  • PARTITION BY: This divides the result set into groups (like "windows"). The calculation restarts for each group.
  • ORDER BY: This defines the logical sequence of rows within each partition.

2. Common ETL Functions

  • ROW_NUMBER(): Assigns a unique sequential integer to rows. Excellent for deduplication.
  • RANK(): Assigns a rank, but if there is a tie, it skips the next number.
  • SUM() or AVG(): When used with OVER, these calculate a running total or a moving average.

3. Real ETL Case: Removing Duplicates

Imagine you have a table of user logins where some entries are accidentally duplicated. You want to keep only the latest login for each user.


SELECT 
    user_id, 
    login_time, 
    ip_address
FROM (
    SELECT 
        user_id, 
        login_time, 
        ip_address,
        ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_time DESC) as row_num
    FROM raw_logins
) ranked_data
WHERE row_num = 1;

In this example, the data is partitioned by user_id. Within each user's group, we order by the login_time in descending order. The most recent login gets a row_num of 1. By filtering for row_num = 1 in the outer query, we effectively remove all older duplicates.

Common mistakes

  • Confusing PARTITION BY with GROUP BY: Remember that PARTITION BY does not reduce the number of rows in your output; it only defines how the calculation is scoped.
  • Forgetting ORDER BY in Ranking Functions: Functions like ROW_NUMBER() or RANK() require an ORDER BY clause to be meaningful. Without it, the database will assign numbers arbitrarily.
  • Performance on Large Windows: If you partition by a column with very low cardinality (e.g., partitioning a billion rows by a "Gender" column), the database might struggle to process the huge chunks of data in memory.
  • Using window functions in WHERE clauses: You cannot use a window function directly in a WHERE clause. You must use a subquery or a Common Table Expression (CTE) as shown in the code example above.

One practice task

Suppose you have a table called sales with three columns: sale_date, region, and amount. Write a query that returns every row from the table, but adds a fourth column called region_total which shows the sum of all sales for that specific region.

Hint: You will use SUM(amount) combined with an OVER clause, but you do not need an ORDER BY inside the window if you want the grand total for the whole region rather than a running total.
