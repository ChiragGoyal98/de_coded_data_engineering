SQL Window Functions with Real ETL Use Cases

In the world of data processing, you often need to perform calculations that involve multiple rows without losing the detail of individual records. Imagine you have a list of sales and you want to see each transaction's value alongside the total sales for that specific region. Normally, a GROUP BY clause would collapse those individual transactions into a single summary row. SQL window functions solve this problem by allowing you to "look across" a specific set of rows while keeping every single row in your result set visible.

Why Window Functions Matter in ETL

In Extract, Transform, Load (ETL) pipelines, window functions are the "Swiss Army Knife" for data cleaning and transformation. They are essential for three main reasons:

  • Data Deduplication: When landing raw data into a data warehouse, you often find duplicate records. Window functions help you identify and keep only the most recent version of a record.
  • Trend Analysis: Calculating running totals, moving averages, or month-over-month growth requires comparing the current row to previous or subsequent rows.
  • Data Quality Checks: You can easily identify gaps in sequences (like missing transaction IDs) or detect outliers by comparing individual values to a "windowed" average.

Step-by-Step Walkthrough

To use a window function, you need to understand the three primary components of its syntax: the function itself, the partition, and the order.

1. The Basic Syntax

The standard structure looks like this:

FUNCTION() OVER (PARTITION BY column_a ORDER BY column_b)

  • PARTITION BY: This divides the rows into groups (windows). The calculation restarts for each group.
  • ORDER BY: This determines the sequence of rows within each partition. This is vital for functions like ranking or calculating running totals.

2. Identifying Duplicates with ROW_NUMBER()

One of the most common ETL tasks is removing duplicates. If a source system sends the same order twice, you can use ROW_NUMBER() to rank them by their update timestamp and select the top one.


SELECT 
    order_id, 
    customer_id, 
    order_date,
    ROW_NUMBER() OVER (PARTITION BY order_id ORDER BY last_updated_at DESC) as rank_id
FROM raw_sales_table;

3. Calculating Running Totals

For a financial dashboard, you might need a daily cumulative sum of revenue. By using SUM() as a window function, you can add up values as you move down the list of dates.

4. Comparing Values with LAG and LEAD

In ETL, we often need to know how much a value has changed since the last record. LAG() looks at the row above, while LEAD() looks at the row below. This is perfect for calculating the time elapsed between two user actions.

Common Mistakes

  • Using Window Functions in the WHERE Clause: You cannot use a window function directly in a WHERE clause (e.g., WHERE ROW_NUMBER() = 1). Because window functions are processed after the WHERE clause, you must wrap your query in a Common Table Expression (CTE) or a subquery first.
  • Forgetting ORDER BY: For functions like RANK() or LEAD(), the order of rows is critical. If you omit the ORDER BY clause, the results will be unpredictable or return an error.
  • Over-Partitioning: If you partition by a column with too much cardinality (unique values), your "windows" might only contain one row each, making the function's calculation useless.

Practice Task

Suppose you have a table named monthly_revenue with columns store_id, report_month, and revenue.

Write a query that shows each store's revenue for every month, but also includes a column showing the revenue from the previous month for that same store. Use the LAG() function to achieve this.
