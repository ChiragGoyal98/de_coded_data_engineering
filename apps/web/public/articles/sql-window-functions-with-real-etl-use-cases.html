SQL Window Functions with Real ETL Use Cases

SQL window functions are a powerful feature in modern database management systems that allow you to perform calculations across a set of table rows that are somehow related to the current row. Unlike standard aggregate functions-like SUM or AVG-which collapse multiple rows into a single output row, window functions allow you to retain the identity of each individual row while still accessing data from other rows in the result set. This makes them indispensable for data engineering tasks where you need to look at trends, rankings, or cumulative values without losing the granular detail of your dataset.

Why it Matters in ETL

In the world of Extract, Transform, Load (ETL), window functions are essential for cleaning and shaping data. Data engineers frequently encounter "dirty" data or complex business requirements that standard SQL cannot handle efficiently. Window functions are the primary tool for:

  • Deduplication: Identifying the most recent record when multiple versions of the same entry exist in a landing zone.
  • Trend Analysis: Comparing today's sales to yesterday's without performing complex self-joins.
  • Sequence Generation: Assigning unique identifiers or order numbers to rows within specific categories.
  • Running Totals: Calculating year-to-date figures or inventory levels over time.

By using window functions, you reduce the need for multiple subqueries or temporary tables, leading to cleaner code and better performance on modern data warehouses like Snowflake, BigQuery, or Redshift.

Step-by-Step Walkthrough

1. Understanding the OVER Clause

The OVER clause is what defines the "window" of rows that the function will operate on. Without it, a function like SUM acts as a standard aggregate.


SELECT 
    order_id, 
    sale_amount, 
    SUM(sale_amount) OVER() as total_revenue
FROM sales_table;

In this example, every row will show the same total_revenue value alongside its specific sale_amount.

2. Dividing Data with PARTITION BY

The PARTITION BY sub-clause allows you to group your window into segments. This is vital for ETL tasks like finding the "latest status" for each user.


SELECT 
    user_id, 
    status, 
    ROW_NUMBER() OVER(PARTITION BY user_id ORDER BY updated_at DESC) as latest_rank
FROM user_logs;

Here, the row numbers restart at 1 for every unique user_id. In an ETL pipeline, you would then filter for rows where latest_rank = 1 to get the most recent record for every user.

3. Creating Sequence with ORDER BY

When used inside a window function, ORDER BY determines the sequence in which the function processes rows. This is how you create running totals.


SELECT 
    transaction_date, 
    amount, 
    SUM(amount) OVER(ORDER BY transaction_date) as running_total
FROM bank_transactions;

4. Navigating Rows with LAG and LEAD

In ETL, we often need to compare a value to the record immediately preceding it. The LAG function looks "backwards," while LEAD looks "forwards."


SELECT 
    reading_time, 
    temperature, 
    LAG(temperature) OVER(ORDER BY reading_time) as previous_temp
FROM sensor_data;

This is perfect for calculating the delta or change between two timestamps in a stream of data.

Common Mistakes

  • Filtering in the WHERE clause: You cannot use a window function directly in a WHERE clause. To filter based on a window function (like ROW_NUMBER), you must use a Subquery or a Common Table Expression (CTE).
  • Forgetting the ORDER BY: For functions like RANK() or LEAD(), the order of the window is mandatory. Forgetting it will either cause an error or yield unpredictable results.
  • Performance overhead: While window functions are efficient, applying them over millions of rows without a PARTITION BY can be slow because the database might have to move all data to a single compute node.
  • Confusing RANK() vs DENSE_RANK(): If two rows have the same value, RANK() will skip the next number (1, 2, 2, 4), while DENSE_RANK() will not skip (1, 2, 2, 3).

Practice Task

Scenario: You are working on an e-commerce ETL pipeline. You have a table called customer_orders with columns customer_id, order_date, and order_value.

Task: Write a query that shows each order, and for every row, include a column called previous_order_value which shows the order_value of that specific customer's previous order (based on order_date). If it is the customer's first order, the value should be NULL.

Hint: You will need to use PARTITION BY to group by customer and ORDER BY to ensure the dates are in the correct sequence.
