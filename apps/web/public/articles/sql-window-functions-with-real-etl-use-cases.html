SQL Window Functions with Real ETL Use Cases

In the world of data engineering and analysis, SQL is the primary tool for shaping raw data into meaningful insights. While basic commands like SELECT and GROUP BY are essential, they often fall short when you need to perform calculations across a specific set of rows without collapsing the entire dataset. This is where window functions come in. Unlike standard aggregate functions that reduce multiple rows into a single summary, window functions allow you to perform calculations across a "window" of rows while still retaining the individual row details.

Why Window Functions Matter in ETL

In Extract, Transform, Load (ETL) pipelines, window functions are indispensable for data cleansing and transformation. They allow engineers to solve complex problems with minimal code. For instance, when you receive a stream of data that contains duplicate records, a window function can help you identify and keep only the most recent entry.

Furthermore, these functions are vital for time-series analysis and tracking changes. If you need to calculate the difference in sales between today and yesterday, or find a user's running total of purchases over time, window functions provide a clean, performant way to do so without the need for messy self-joins.

Step-by-Step Walkthrough

To understand window functions, you need to master the OVER clause, which defines the "window" of data the function will look at.

1. The Basic Syntax

A window function typically looks like this:

FUNCTION_NAME() OVER (PARTITION BY column1 ORDER BY column2)

  • PARTITION BY: This divides your data into groups (like a GROUP BY, but rows stay separate).
  • ORDER BY: This sorts the data within those groups.

2. Deduplicating Data with ROW_NUMBER()

One of the most common ETL tasks is removing duplicates. Suppose you have a table where the same user ID appears multiple times due to a system glitch, and you only want the most recent record.


SELECT 
    user_id, 
    status, 
    updated_at,
    ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY updated_at DESC) as row_num
FROM user_updates;

In this example, the records are grouped by user_id and sorted by time. The newest record gets a row_num of 1. In your ETL script, you would simply filter for where row_num = 1.

3. Comparing Records with LEAD and LAG

In ETL, we often need to see the "previous" or "next" value in a sequence. LAG looks back at the previous row, while LEAD looks forward.

  • LAG: Used to calculate growth or change from the previous record.
  • LEAD: Used to see what happens next in a user journey.

4. Running Totals with SUM()

You can use standard aggregates as window functions by adding the OVER clause. This is perfect for calculating cumulative growth.


SELECT 
    sale_date, 
    amount,
    SUM(amount) OVER (ORDER BY sale_date) as running_total
FROM daily_sales;

Common Mistakes

  • Confusing RANK() and DENSE_RANK(): If two items have the same value, RANK() will skip the next number (1, 2, 2, 4), whereas DENSE_RANK() will not (1, 2, 2, 3). Using the wrong one can lead to calculation errors in reporting.
  • Filtering in the same query: You cannot use window function results in a WHERE clause in the same query block. You must use a Subquery or a Common Table Expression (CTE) to filter the results (e.g., to filter row_num = 1).
  • Forgetting ORDER BY: Many window functions, like ROW_NUMBER or LAG, require an ORDER BY inside the OVER clause to produce predictable results. Without it, the data is processed in a random order.

Practice Task

Imagine you have a table called website_visits with columns visitor_id, page_name, and visit_time.

The Task: Write a query that assigns a unique number to each page a visitor looked at, ordered from their first visit to their last. If a visitor saw the "Home" page first and "Contact" second, the "Home" row should have a 1 and "Contact" should have a 2.

Hint: Use ROW_NUMBER() and partition by the visitor.
