SQL Window Functions with Real ETL Use Cases

In the world of data engineering, the ability to analyze data without losing the context of individual records is a superpower. Window functions are a specialized class of SQL operations that allow you to perform calculations across a set of rows-a "window"-that are related to the current row. While standard aggregate functions like SUM or AVG collapse your data into a single summary row, window functions allow every single row to retain its identity while adding a calculated value alongside it. This makes them a vital tool for anyone moving from basic queries to building production-grade data pipelines.

Why it matters in ETL

Extract, Transform, Load (ETL) processes often require complex logic that goes beyond simple filtering. Window functions are essential for several reasons:

  • Data Cleaning: They are the gold standard for deduplication. By ranking duplicate records based on a timestamp, you can easily pick the "latest" version.
  • Trend Analysis: Calculating running totals or moving averages is trivial with window functions but incredibly difficult with standard SQL.
  • Delta Processing: Data engineers often need to see what changed between the current record and the previous one. Offsetting functions allow you to "look back" at a prior row to calculate growth or status changes.

Step-by-step walkthrough

To use a window function, you need the OVER clause. This clause defines the window of rows the function will look at.

1. The Ranking Pattern (Deduplication)

In ETL, you often receive duplicate records. To keep only the most recent entry for each user, we use ROW_NUMBER().


SELECT 
    user_id, 
    status, 
    updated_at,
    ROW_NUMBER() OVER(PARTITION BY user_id ORDER BY updated_at DESC) as row_num
FROM user_logs;

Here, PARTITION BY groups the data by user, and ORDER BY sorts them by time. The row with row_num = 1 is your most recent record.

2. The Accumulation Pattern (Running Totals)

If you need to show a customer their spending history over time, you use an aggregate function followed by the window clause.


SELECT 
    order_date, 
    amount,
    SUM(amount) OVER(ORDER BY order_date) as running_total
FROM sales;

By providing an ORDER BY inside the OVER clause without a partition, SQL calculates a cumulative sum from the first row down to the current one.

3. The Comparison Pattern (Lead and Lag)

To calculate the time elapsed between two events, you use LAG (to look at the previous row) or LEAD (to look at the next row).


SELECT 
    session_id, 
    event_time,
    LAG(event_time) OVER(PARTITION BY session_id ORDER BY event_time) as previous_event_time
FROM web_clicks;

This adds a column showing the timestamp of the click immediately preceding the current one, allowing you to calculate session duration.

Common mistakes

  • Filtering in the same query: You cannot use window function results in a WHERE clause of the same query block (e.g., WHERE row_num = 1). Because of the SQL order of operations, window functions are calculated after filtering. You must use a Common Table Expression (CTE) or a subquery to filter these results.
  • Forgetting the ORDER BY: For functions like ROW_NUMBER or LAG, the order of rows is critical. Omitting the ORDER BY inside the OVER clause will lead to unpredictable, non-deterministic results.
  • Performance overhead: While powerful, window functions can be resource-intensive on massive datasets. Always ensure your PARTITION BY columns are indexed if you are working with billions of rows.

Practice task

Imagine you have a table called monthly_revenue with columns month and revenue. Write a query that produces a result set showing:

  • The month.
  • The revenue for that month.
  • The revenue of the previous month in a third column titled prev_month_revenue.

Hint: Use the LAG() function and order by the month column to ensure you are looking at the correct chronological sequence.
