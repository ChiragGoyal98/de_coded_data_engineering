SQL Window Functions with Real ETL Use Cases

In the world of data engineering and analysis, SQL window functions act like a superpower for your queries. While standard aggregate functions like SUM or AVG group multiple rows into a single result, window functions allow you to perform calculations across a set of rows that are related to the current row without losing the detail of each individual record. This makes them indispensable for complex data transformations and reporting where you need to maintain the original row count while adding contextual information.

Why it matters

In ETL (Extract, Transform, Load) pipelines, data is rarely perfect. You often encounter duplicate records, need to calculate month-over-month growth, or determine the "current" status of a changing record. Without window functions, these tasks require complex self-joins or temporary tables that slow down performance and make code hard to read.

Window functions provide a cleaner, more efficient way to:

  • Deduplicate data by ranking records based on timestamps.
  • Create running totals for financial reporting.
  • Compare a value in the current row to a value in the previous row (delta analysis).
  • Calculate percentiles or moving averages for trend analysis.

Step-by-step walkthrough

1. Understanding the Syntax

The magic of a window function lies in the OVER clause. This clause defines the "window" of data the function will look at.


SELECT 
    column_name,
    FUNCTION() OVER (PARTITION BY group_col ORDER BY sort_col) as alias_name
FROM table_name;
  • PARTITION BY: This divides the rows into groups (like GROUP BY).
  • ORDER BY: This defines the sequence of rows within each partition.

2. Real-World Use Case: Deduplication

Imagine you have a landing table where a user's profile was updated multiple times, but you only want the most recent entry. Using ROW_NUMBER(), you can assign a unique rank to each entry per user, ordered by the update time.


SELECT user_id, email, updated_at
FROM (
    SELECT 
        user_id, email, updated_at,
        ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY updated_at DESC) as rank
    FROM raw_users
) ranked_data
WHERE rank = 1;

3. Real-World Use Case: Comparing Trends

ETL processes often require identifying changes over time. The LAG() function lets you look at the previous row's value. This is perfect for calculating how much a sales figure increased compared to the previous day without performing a complex join.

Common mistakes

  • Confusing RANK() and DENSE_RANK(): RANK() leaves gaps in the numbering if there is a tie (e.g., 1, 2, 2, 4), while DENSE_RANK() does not (e.g., 1, 2, 2, 3).
  • Forgetting ORDER BY: For functions like ROW_NUMBER() or LEAD(), the order is critical. If you omit it, the results will be unpredictable.
  • Using Window Functions in WHERE clauses: You cannot use a window function directly in a WHERE clause because they are processed after filtering. You must use a Subquery or a Common Table Expression (CTE) to filter the results.
  • Performance overhead: While powerful, partitioning over massive datasets with millions of unique keys can be memory-intensive. Always ensure your "ORDER BY" columns are indexed when possible.

Practice task

Suppose you have a table called monthly_sales with columns store_id, sale_month, and revenue.

Task: Write a query to show each store's revenue alongside a "Running Total" of that store's revenue as the months progress.

Hint: Use the SUM() function combined with the OVER clause, partitioning by the store and ordering by the month.
