SQL Window Functions with Real ETL Use Cases

Window functions are one of the most powerful tools in a data engineer's SQL toolkit. While traditional aggregate functions like SUM or AVG group multiple rows into a single output row, window functions allow you to perform calculations across a set of rows while still retaining the details of every individual record. This makes them indispensable for complex data transformations where you need to compare a specific row against its neighbors or a specific group without losing the original context of your data.

Why it matters in ETL

In the world of Extract, Transform, Load (ETL), data is rarely ready for analysis in its raw state. You often need to clean it, deduplicate it, or enrich it with historical context. Window functions solve several high-level problems that are otherwise difficult to handle:

  • Deduplication: When multiple versions of the same record exist, you can use window functions to pick the "latest" one based on a timestamp.
  • Running Totals: Essential for financial reporting, allowing you to see how a value accumulates over time (e.g., year-to-date revenue).
  • Trend Analysis: Calculating the difference between a current value and a previous value (like month-over-month growth) without performing a complex self-join.
  • Ranking: Assigning a priority or sequence to records within specific categories, such as finding the top three performing products in every region.

Step-by-step walkthrough

To use a window function, you need to understand the OVER() clause, which defines the "window" of data the function will look at.

1. The PARTITION BY Clause

Think of PARTITION BY as a GROUP BY that doesn't collapse your rows. It divides the result set into smaller chunks. For example, if you partition by department_id, the calculation starts over for every new department.

2. The ORDER BY Clause

Inside a window function, ORDER BY defines the sequence of the rows within the partition. This is vital for functions that rely on position, like calculating a running total or identifying the "first" or "last" record.

3. Common Functions

  • ROW_NUMBER(): Assigns a unique, sequential integer to rows.
  • RANK(): Assigns a rank, but if two values are the same, they get the same rank and the next number is skipped.
  • LAG() / LEAD(): Accesses data from a previous or subsequent row.

ETL Use Case: Deduplicating Records

Imagine you have a table where every time a user updates their profile, a new row is inserted. To get a clean list of the most recent profile for every user, you would use ROW_NUMBER().


SELECT 
    user_id, 
    email, 
    updated_at
FROM (
    SELECT 
        user_id, 
        email, 
        updated_at,
        ROW_NUMBER() OVER(PARTITION BY user_id ORDER BY updated_at DESC) as row_num
    FROM user_updates
) ranked_updates
WHERE row_num = 1;

In this example, the "window" is every unique user_id. Within that window, we sort by updated_at so the newest record is always number 1. We then simply filter for row_num = 1.

Common mistakes

  • Confusing RANK() and DENSE_RANK(): If two items are tied for 1st place, RANK() will make the next item 3rd. DENSE_RANK() will make the next item 2nd. Using the wrong one can lead to "missing" data in your reports.
  • Forgetting the ORDER BY: For functions like SUM() or ROW_NUMBER(), forgetting to sort the data inside the window often leads to unpredictable results or errors.
  • Performance on Large Datasets: Window functions can be resource-intensive. If you are partitioning by a column that isn't indexed or working with billions of rows, ensure your database has enough memory to handle the sort operations.
