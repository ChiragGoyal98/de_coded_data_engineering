SQL Window Functions with Real ETL Use Cases

In the world of data engineering and analysis, SQL is the foundational language that allows us to interact with databases. While basic commands like SELECT and WHERE are essential, window functions represent a significant leap in your ability to manipulate data. Unlike standard aggregate functions that group multiple rows into a single result, window functions allow you to perform calculations across a set of table rows while still maintaining the individual identity of each row. This makes them indispensable for building efficient Extract, Transform, Load (ETL) pipelines.

Why it matters

In ETL processes, we often deal with raw, messy data that needs to be cleaned or transformed before it reaches a data warehouse. Standard SQL aggregations (like GROUP BY) collapse your data, which means you lose the granular details of individual records. Window functions solve this by "looking through a window" at other rows to calculate values without merging them.

For a Data Engineer, window functions are essential for:

  • Deduplication: Removing duplicate records by identifying the most recent entry.
  • Running Totals: Calculating cumulative sums for financial reporting.
  • Ranking: Assigning grades or positions to users based on performance.
  • Trend Analysis: Comparing the current row's value to a previous day's value to calculate growth.

Step-by-step walkthrough

To master window functions, you need to understand the syntax that triggers them: the OVER() clause.

1. The Basic Syntax

Every window function follows this pattern: FUNCTION() OVER (PARTITION BY column ORDER BY column).

  • PARTITION BY: This divides the result set into groups (like a GROUP BY, but without collapsing rows).
  • ORDER BY: This determines the sequence in which the function is applied within each partition.

2. Common Functions

  • ROW_NUMBER(): Assigns a unique sequential integer to rows.
  • RANK(): Assigns a rank, but if two values are the same, they get the same rank and the next rank is skipped.
  • SUM() / AVG(): Performs a calculation over the defined window.

3. Real ETL Case: Deduplicating Data

Imagine you have a table of customer updates where each customer has multiple entries because their profile was updated several times. You only want the "latest" record for your final table.


WITH RankedUpdates AS (
    SELECT 
        customer_id, 
        email, 
        updated_at,
        ROW_NUMBER() OVER (
            PARTITION BY customer_id 
            ORDER BY updated_at DESC
        ) as update_rank
    FROM raw_customer_data
)
SELECT 
    customer_id, 
    email, 
    updated_at
FROM RankedUpdates
WHERE update_rank = 1;

In this example, PARTITION BY customer_id groups the rows by each unique user, and ORDER BY updated_at DESC ensures the newest record gets the number 1. The final WHERE clause filters out the old duplicates.

Common mistakes

  • Using Window Functions in WHERE: You cannot use a window function directly in a WHERE clause (e.g., WHERE ROW_NUMBER() = 1). You must use a Common Table Expression (CTE) or a subquery, as shown in the example above, because window functions are processed after the WHERE clause.
  • Confusing RANK() and DENSE_RANK(): If two items are tied for 1st place, RANK() will label the next item as 3rd. DENSE_RANK() will label the next item as 2nd. Using the wrong one can lead to gaps in your data reports.
  • Forgetting ORDER BY: For functions like ROW_NUMBER() or LAG(), forgetting the ORDER BY clause inside the OVER() brackets will lead to unpredictable results because the database won't know which row should come first.

One practice task

Suppose you have a table called daily_sales with columns sale_date and amount. Write a query using a window function to calculate a running total of sales ordered by date.

Hint: Use SUM(amount) OVER (...) and remember that you want the sum to accumulate as the days progress.
