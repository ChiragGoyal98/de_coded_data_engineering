SQL Window Functions with Real ETL Use Cases

SQL window functions are often seen as an advanced topic, but they are essential tools for anyone starting their journey in data engineering. Unlike standard aggregate functions like SUM or AVG which collapse many rows into one, window functions allow you to perform calculations across a specific set of rows while keeping every individual row visible in your result set. Think of it as looking through a magnifying glass at a specific "window" of your data without losing sight of the rest of the spreadsheet.

Why it matters

In ETL (Extract, Transform, Load) pipelines, window functions are lifesavers for data quality and transformation. When moving data from a raw source to a clean warehouse, you frequently encounter messy scenarios. You might need to remove duplicate records, calculate how much a metric has changed since yesterday, or create a running total of sales.

Without window functions, these tasks require complex subqueries or multiple self-joins, which are hard to read and slow to run. Window functions simplify these operations into a single line of code, making your ETL scripts more maintainable and efficient.

Step-by-step walkthrough

To use a window function, you need the OVER clause. This clause defines the "window" or the subset of data the function will look at. It usually contains two main parts: PARTITION BY (which groups the data) and ORDER BY (which sorts it within that group).

1. Removing Duplicates with ROW_NUMBER()

In many ETL processes, data arrives with duplicates. You can use ROW_NUMBER() to assign a unique ID to every row within a group and then filter for the first one.


SELECT 
    user_id, 
    email, 
    created_at,
    ROW_NUMBER() OVER(PARTITION BY email ORDER BY created_at DESC) as rank
FROM raw_users;

In this example, if there are three records with the same email, the newest one gets rank 1. In your ETL, you would simply filter for where rank = 1.

2. Calculating Changes with LAG() and LEAD()

In financial or sensor data, you often need to compare the current row to the previous one (e.g., "Did the temperature rise since the last reading?").


SELECT 
    timestamp, 
    temperature,
    LAG(temperature) OVER(ORDER BY timestamp) as previous_temp
FROM weather_logs;

The LAG function pulls the value from the previous row into the current row, allowing you to subtract one from the other to find the difference.

3. Running Totals with SUM()

If you want to track cumulative growth over time, you can use a standard aggregate function as a window function.


SELECT 
    sale_date, 
    amount,
    SUM(amount) OVER(ORDER BY sale_date) as running_total
FROM sales;

Common mistakes

  • Confusing RANK() and ROW_NUMBER(): ROW_NUMBER() always gives a unique number (1, 2, 3). RANK() will give the same number to tied values (1, 2, 2, 4), which can cause issues if you are trying to pick exactly one record.
  • Forgetting the ORDER BY: For functions like LAG or ROW_NUMBER, the order of the data is critical. If you omit the ORDER BY inside the OVER clause, the results will be unpredictable.
  • Performance Overload: While powerful, applying window functions to millions of rows without proper partitioning can slow down your database. Always try to PARTITION BY a column that limits the scope of the calculation.

Practice task

Imagine you have a table called employee_salaries with columns department, employee_name, and salary.

The Task: Write a query that shows each employee's name and salary, but also adds a column showing the highest salary in their specific department.

Hint: Use the MAX() function combined with an OVER clause and PARTITION BY.
