SQL Window Functions with Real ETL Use Cases

SQL window functions are a powerful feature that allows you to perform calculations across a set of table rows that are related to the current row. Unlike standard aggregate functions like SUM or AVG, which collapse multiple rows into a single output row, window functions maintain the identity of individual rows. This allows you to see both the original data and the calculated result side-by-side. Imagine looking through a sliding glass window that highlights a specific group of records while keeping the rest of the spreadsheet visible; that is the core concept of a "window."

Why Window Functions Matter in ETL

In Data Engineering and ETL (Extract, Transform, Load) processes, data is rarely perfect. You often need to clean, rank, or compare records as they move from a source system to a data warehouse. Window functions simplify these tasks significantly.

Instead of writing complex subqueries or multiple self-joins to find the "latest" record or calculate a running total, window functions allow you to do this in a single pass. This leads to more readable code, better performance, and easier maintenance of data pipelines. Whether you are deduplicating data or calculating month-over-month growth, window functions are the go-to tool for any data professional.

Step-by-Step Walkthrough

To use a window function, you need the OVER clause. This clause defines the "window" of rows the function will operate on.

1. The Basic Syntax

The standard structure looks like this:

FUNCTION() OVER (PARTITION BY column1 ORDER BY column2)

  • PARTITION BY: Groups the rows into subsets (like a "Group By" but without collapsing rows).
  • ORDER BY: Defines the physical order of rows within each partition.

2. Deduplicating Data with ROW_NUMBER()

One of the most common ETL use cases is removing duplicate records. If a source system sends the same user ID twice, you can use ROW_NUMBER() to identify the most recent entry.


SELECT 
    user_id, 
    signup_date,
    ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY signup_date DESC) as rank
FROM raw_users;

In this example, the row with rank = 1 is the latest record for each user.

3. Comparing Records with LAG() and LEAD()

In ETL, you often need to compare a value in the current row with a value in the previous or next row (e.g., comparing today's price to yesterday's).


SELECT 
    sale_date, 
    daily_revenue,
    LAG(daily_revenue) OVER (ORDER BY sale_date) as previous_day_revenue
FROM sales_table;

4. Running Totals with SUM()

Calculating a cumulative sum is useful for financial reporting and tracking growth over time.


SELECT 
    transaction_date, 
    amount,
    SUM(amount) OVER (ORDER BY transaction_date) as running_total
FROM transactions;

Common Mistakes to Avoid

  • Confusing PARTITION BY with GROUP BY: Remember that PARTITION BY does not reduce the number of rows in your output. If you have 100 rows going in, you will have 100 rows coming out.
  • Forgetting the ORDER BY clause: For functions like ROW_NUMBER() or LAG(), the order of the data is critical. Without a specified order, the results will be unpredictable.
  • Performance Overhead: While window functions are efficient, applying them over millions of rows with complex partitions can slow down your query. Always ensure your "Partition By" columns are indexed if possible.
  • Filtering on Window Results: You cannot use a window function result in a WHERE clause directly. You must wrap the query in a Subquery or a Common Table Expression (CTE) first.

Practice Task

Scenario: You have a table called store_sales with columns store_id, sale_date, and amount.

Your Task: Write a query that shows each sale alongside the total sales for that specific store (not the whole company).

Hint: Use the SUM() function combined with PARTITION BY.


-- Try to write your solution here
SELECT 
    store_id, 
    sale_date, 
    amount,
    SUM(amount) OVER (PARTITION BY store_id) as store_total
FROM store_sales;
