SQL Window Functions with Real ETL Use Cases

Window functions are one of the most powerful tools in a data engineer's toolkit. Unlike regular aggregate functions, which collapse multiple rows into a single summary row, window functions allow you to perform calculations across a set of rows while still maintaining the details of each individual record. Imagine you are looking at a spreadsheet of sales; a window function lets you calculate a running total in a new column while keeping every single transaction row visible.

Why it matters in ETL

In Extract, Transform, Load (ETL) pipelines, data is rarely clean or perfectly formatted. You often need to perform complex transformations before the data is ready for analysis. Window functions are essential for these specific ETL tasks:

  • Deduplication: Identifying and removing duplicate records by picking the "latest" version based on a timestamp.
  • Trend Analysis: Calculating moving averages or month-over-month growth.
  • Sessionization: Grouping user actions into specific time-bound sessions.
  • Ranking: Finding the top-performing products or the most recent customer interactions.

Using window functions is generally more performant and readable than using nested subqueries or complex self-joins to achieve the same results.

Step-by-step walkthrough

The secret to window functions is the OVER() clause. This clause defines the "window" of data the function will look at.

1. The Basic Syntax

A window function follows this pattern: FUNCTION() OVER (PARTITION BY column ORDER BY column).

2. Using PARTITION BY

Think of PARTITION BY as a "Group By" that doesn't shrink your data. If you partition by user_id, the function will reset its calculation every time it hits a new user.

3. Using ORDER BY

The ORDER BY inside the OVER() clause determines the sequence in which the function processes the rows. This is critical for calculations like running totals or identifying the first/last event.

4. Real ETL Example: Removing Duplicates

Suppose you have a table called raw_events where some events were accidentally sent twice. You want to keep only the most recent entry for each event_id.


WITH RankedEvents AS (
    SELECT 
        user_id,
        event_name,
        created_at,
        ROW_NUMBER() OVER (
            PARTITION BY event_id 
            ORDER BY created_at DESC
        ) as row_num
    FROM raw_events
)
SELECT * 
FROM RankedEvents 
WHERE row_num = 1;

In this example, ROW_NUMBER() assigns a 1 to the newest record for every unique event_id. By filtering for row_num = 1, we effectively clean our dataset.

Common mistakes

  • Confusing GROUP BY with PARTITION BY: Remember that GROUP BY reduces the number of rows returned, while PARTITION BY keeps all original rows intact.
  • Forgetting ORDER BY in Ranking: Functions like RANK() or ROW_NUMBER() require an ORDER BY to know which row comes "first." Without it, the results will be unpredictable.
  • Performance on Massive Windows: If you define a window that covers millions of rows without a specific partition, the database may struggle with memory. Always try to partition your data into smaller logical chunks.
  • Filtering in the same query: You cannot use a window function result in a WHERE clause in the same query level. You must use a Common Table Expression (CTE) or a subquery, as shown in the example above.

Practice task

You have a table named store_sales with the columns store_id, sale_date, and amount.

The Task: Write a query that returns every row from the table, but adds a fourth column called running_total that calculates the cumulative sum of sales for each store, ordered by the date.

Hint: Use the SUM(amount) function combined with OVER().
