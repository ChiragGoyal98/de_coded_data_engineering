SQL Window Functions with Real ETL Use Cases

SQL is the language of data, and mastering its basic operations like SELECT and WHERE is only the first step. As you move into data engineering and ETL processes, you will encounter scenarios where you need to perform calculations across groups of rows without collapsing them into a single summary row. This is where Window Functions come into play. Unlike traditional aggregate functions that group data together, window functions allow you to retain the individual identity of each row while still performing complex calculations like ranking, running totals, or comparing values between rows.

Why it Matters in ETL

In the world of Extract, Transform, Load (ETL), window functions are essential for cleaning and preparing data. They are the "Swiss Army Knife" for data engineers because they solve specific problems that are otherwise difficult to handle with basic SQL.

  • Deduplication: Identifying and removing duplicate records by assigning a unique number to each occurrence.
  • Sessionization: Tracking user behavior by looking at the time difference between consecutive events.
  • Trend Analysis: Calculating moving averages or running totals to understand growth over time.
  • Finding the "Latest" Record: Selecting the most recent status of an order or the latest update for a customer profile.

Step-by-Step Walkthrough

1. The Core Syntax: The OVER Clause

The defining feature of a window function is the OVER() clause. This tells the database to treat the function as a window operation rather than a standard aggregate.


SELECT 
    order_id, 
    sale_amount, 
    SUM(sale_amount) OVER() as total_sales
FROM sales;

In this example, total_sales will show the sum of all sales on every single row, rather than grouping the whole table into one row.

2. Organizing Data with PARTITION BY

Think of PARTITION BY as the "Group By" of window functions. It divides the result set into smaller buckets. If you want to see the total sales *per category* on every row, you partition by category.

3. Ordering within the Window

The ORDER BY clause inside the window function determines the sequence in which the function is applied. This is critical for tasks like ranking or running totals.

4. Ranking Rows

A common ETL task is finding the top record in a group. Use ROW_NUMBER() to give each row a unique incrementing integer.


SELECT 
    employee_id, 
    department, 
    salary,
    ROW_NUMBER() OVER(PARTITION BY department ORDER BY salary DESC) as salary_rank
FROM employees;

In this snippet, the highest-paid person in each department gets a salary_rank of 1.

5. Navigating Rows with LAG and LEAD

ETL pipelines often require comparing a value to the one before it. LAG() looks at the previous row, and LEAD() looks at the next one. This is perfect for calculating day-over-day growth.

Common Mistakes

  • Forgetting ORDER BY in Ranking: If you use ROW_NUMBER() or RANK() without an ORDER BY clause inside the window, the results will be non-deterministic (essentially random).
  • Confusing RANK() vs DENSERANK(): If two rows have the same value, RANK() will skip the next number (1, 2, 2, 4), while DENSERANK() will not (1, 2, 2, 3).
  • Performance Overload: Running complex window functions on billions of rows without proper indexing or partitioning can significantly slow down your ETL pipeline. Always try to filter your data using a WHERE clause before applying the window.
  • Misplacing the Window Function: Window functions are processed after the WHERE and GROUP BY clauses but before the final ORDER BY. You cannot use a window function directly in a WHERE clause; you must use a Subquery or a Common Table Expression (CTE) to filter by a windowed result.

Practice Task

Scenario: You have a table named userlogins with columns userid and login_timestamp. Some users have logged in multiple times.

Your Goal: Write a query that returns every column from the table, but adds a new column called previous_login that shows the timestamp of the login immediately preceding the current one for that specific user.

*Hint: You will need to use PARTITION BY to separate users and ORDER BY to ensure the timestamps are in the right sequence.*
