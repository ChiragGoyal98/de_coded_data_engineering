SQL Window Functions with Real ETL Use Cases

In the world of data engineering, SQL is the primary tool for transforming raw data into meaningful insights. One of the most advanced yet essential tools in the SQL toolkit is the window function. Unlike standard aggregate functions-such as SUM or AVG-which collapse multiple rows into a single result, window functions allow you to perform calculations across a set of rows while still preserving the details of every individual record. This capability is vital for creating complex data pipelines where context and row-level detail are both required.

Why Window Functions Matter in ETL

In Extract, Transform, Load (ETL) processes, we rarely just want to see a total sum of sales. More often, we need to know how a specific sale compares to the previous one, or we need to assign a rank to customers based on their spending.

  • Data Deduplication: ETL pipelines often receive duplicate records. Window functions help identify and keep only the latest version of a record.
  • Trend Analysis: Calculating month-over-month growth or moving averages is significantly easier with window functions than with complex self-joins.
  • Pagination and Ranking: If you are preparing data for an application, you often need to number rows or rank items within specific categories.

Without window functions, these tasks would require multiple subqueries or temporary tables, making your ETL scripts slow and difficult to maintain.

Step-by-Step Walkthrough

1. The Basic Syntax

The defining characteristic of a window function is the OVER clause. This clause tells SQL how to "frame" the data for the calculation. Within the OVER clause, you typically use PARTITION BY to group data and ORDER BY to sort it.


SELECT 
    employee_id, 
    department, 
    salary,
    AVG(salary) OVER(PARTITION BY department) as avg_dept_salary
FROM employees;

2. Deduplicating Data with ROW_NUMBER()

A common ETL use case is removing duplicates. If a source system sends the same record twice with different timestamps, you can use ROW_NUMBER() to identify the most recent one.


WITH RankedData AS (
    SELECT *,
           ROW_NUMBER() OVER(PARTITION BY user_id ORDER BY updated_at DESC) as rank
    FROM raw_user_logs
)
SELECT * FROM RankedData WHERE rank = 1;

3. Comparing Rows with LAG() and LEAD()

In time-series ETL, you often need to compare a value to the one that came before it. LAG() looks at the previous row, while LEAD() looks at the next one. This is perfect for calculating the time elapsed between user actions.


SELECT 
    user_id, 
    action_time,
    LAG(action_time) OVER(PARTITION BY user_id ORDER BY action_time) as previous_action_time
FROM user_activity;

Common Mistakes

  • Forgetting the PARTITION BY clause: If you omit this, the "window" becomes the entire table. While sometimes intentional, it often leads to incorrect calculations when you meant to group by a specific category like store_id or date.
  • Confusing RANK() vs DENSE_RANK(): RANK() leaves gaps in numbering if there is a tie (1, 2, 2, 4), whereas DENSE_RANK() does not (1, 2, 2, 3). Using the wrong one can lead to "missing" data in reports.
  • Performance overhead: While powerful, window functions can be resource-intensive on massive datasets. Always ensure your PARTITION BY and ORDER BY columns are indexed if performance starts to lag.

Practice Task

Imagine you are working with a table called monthly_sales with columns region, sale_month, and revenue.

The Goal: Write a query to calculate a Running Total of revenue for each region, ordered by the month.

Hint: Use the SUM() function combined with the OVER clause, partitioning by the region and ordering by the month. This will add the revenue of the current row to the sum of all previous rows in that partition.
