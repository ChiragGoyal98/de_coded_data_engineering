SQL Window Functions with Real ETL Use Cases

In the world of data engineering and ETL (Extract, Transform, Load) processes, the ability to analyze data in context is a superpower. Standard aggregate functions like SUM or AVG usually collapse your data into a single row. However, window functions allow you to perform complex calculations across a specific set of rows-a "window"-while still keeping all your individual records visible. This makes them indispensable for cleaning data, identifying trends, and handling duplicates.

Why it matters

For anyone working in ETL, window functions are the bridge between raw, messy data and clean, structured insights. Unlike a GROUP BY clause, which hides the individual details of your rows, a window function lets you compare a specific row against its neighbors or its group.

In real-world ETL pipelines, you will frequently use these functions to:

  • Identify the most recent record in a series of updates (deduplication).
  • Create running totals for financial reports.
  • Compare a current value to a previous day's value (delta analysis).
  • Rank records based on specific criteria like sales performance or timestamp.

Step-by-step walkthrough

To master window functions, you need to understand the syntax that defines the "window." This is always done using the OVER() clause.

1. The OVER() Clause

The OVER() clause tells the database you are using a window function. If you leave it empty, the window is the entire dataset.

2. PARTITION BY

This is similar to a GROUP BY but for windows. It divides the result set into partitions. For example, if you have a table of sales, PARTITION BY region ensures the calculation resets for every new region.

3. ORDER BY

Inside the window, the order matters. If you are calculating a running total or a rank, you need to tell the database which column defines the sequence (usually a date or an ID).

Real ETL Use Case: Deduplication

Imagine you have an ETL pipeline where a source system sends multiple updates for the same order. You only want to load the latest version of each order into your data warehouse. You can use the ROW_NUMBER() function to solve this.


SELECT 
    order_id, 
    status, 
    updated_at,
    ROW_NUMBER() OVER(PARTITION BY order_id ORDER BY updated_at DESC) as rank_id
FROM raw_orders_table;

In this example, PARTITION BY order_id groups all updates for the same order together. ORDER BY updated_at DESC puts the newest update at the top. The first row (where rank_id = 1) is the record you want to keep.

Common mistakes

  • Mixing up GROUP BY and PARTITION BY: Remember that GROUP BY reduces the number of rows returned, while PARTITION BY maintains the original row count.
  • Forgetting ORDER BY in ranking functions: Functions like RANK() or ROW_NUMBER() need a specific order to function correctly. Without it, the results will be non-deterministic (random).
  • Performance overhead: Applying complex window functions to millions of rows can be resource-intensive. Always try to filter your data (using a WHERE clause) before applying the window.
  • Filtering the results: You cannot use a window function result in a WHERE clause directly because of the SQL order of operations. You usually need to wrap your query in a Subquery or a Common Table Expression (CTE).

One practice task

You have a table called monthly_revenue with columns store_id, report_month, and revenue. Write a query using a window function that calculates a running total of revenue for each store, ordered by the month.

Hint: Use the SUM() function followed by an OVER() clause that partitions by the store and orders by the month.
