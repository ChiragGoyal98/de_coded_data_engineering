SQL Window Functions with Real ETL Use Cases

SQL window functions are often the bridge between being a beginner and an intermediate data professional. Unlike standard aggregate functions that collapse multiple rows into a single result, window functions allow you to perform calculations across a set of table rows that are somehow related to the current row. In the world of Extract, Transform, Load (ETL), these functions are indispensable for cleaning data, deduplicating records, and generating analytical insights during the transformation phase without losing the granularity of the original dataset.

Why Window Functions Matter in ETL

In a typical ETL pipeline, the "Transform" stage is where raw data is turned into actionable information. Standard SQL techniques like GROUP BY are useful, but they discard individual row data. Window functions provide three major advantages:

  • Data Deduplication: When loading data from multiple sources, you often find duplicate records. Window functions like ROW_NUMBER() help you identify and remove them based on timestamps.
  • Performance: They replace complex self-joins. A self-join requires the database to scan the table twice, whereas a window function can often achieve the same result in a single pass.
  • Complex Analytics: Tasks such as calculating a 7-day rolling average or identifying the "previous" value in a sequence (like a user's previous page view) are nearly impossible without window functions.

Step-by-Step Walkthrough

To use a window function, you need the OVER() clause. This clause defines the "window" of rows the function will look at.

1. The OVER() Clause

This is the foundation. It tells the database: "Run this function across these specific rows." If you leave it empty, the window is the entire dataset.

2. PARTITION BY

Think of this as the GROUP BY of window functions. It divides the result set into partitions. For example, if you want to rank sales, you might partition by Region so that the ranking restarts for every new location.

3. ORDER BY

Within each partition, you usually need to define a sequence. If you are calculating a running total of revenue, you must tell SQL to order the rows by Transaction_Date.

4. Real-World Example: Removing Duplicates

In ETL, you might receive multiple updates for the same Order ID. To keep only the most recent one, you can use the following logic:


SELECT order_id, status, updated_at
FROM (
    SELECT 
        order_id, 
        status, 
        updated_at,
        ROW_NUMBER() OVER(PARTITION BY order_id ORDER BY updated_at DESC) as row_num
    FROM raw_orders_table
) ranked_data
WHERE row_num = 1;

In this example, the PARTITION BY order_id ensures each order is treated as its own group, and ORDER BY updated_at DESC puts the newest record at the top (row number 1).

Common Mistakes

  • Confusing RANK() vs. ROW_NUMBER(): ROW_NUMBER() always gives a unique number (1, 2, 3). RANK() will give the same number to tied values (1, 2, 2, 4), which can lead to unexpected results if your ETL logic expects a single "winner."
  • Forgetting the ORDER BY: Many window functions, like LEAD() or LAG(), require a logical order. Without it, the "previous" or "next" row becomes random based on how the database stored the data.
  • Filtering in the same query: You cannot use window function results in a WHERE clause of the same query block (e.g., WHERE row_num = 1). You must use a Subquery or a Common Table Expression (CTE) to filter the results, as shown in the example above.

Practice Task

Imagine you have a table called monthly_revenue with columns month and revenue.

The Challenge: Write a query that shows each month's revenue alongside the revenue from the previous month (to calculate growth).

Hint: Use the LAG() function. This function "looks back" at a previous row based on the order you specify. Try to write this using a CTE for better readability!
