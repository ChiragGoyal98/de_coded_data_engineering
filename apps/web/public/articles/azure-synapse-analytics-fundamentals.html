Azure Synapse Analytics fundamentals

Azure Synapse Analytics is an enterprise-level analytics service designed to accelerate the time it takes to gain insights across data warehouses and big data systems. At its core, it brings together the best of SQL technologies used in enterprise data warehousing, Spark technologies used for big data, and Data Integration for ETL/ELT pipelines. By providing a single workspace for data preparation, management, and serving, it eliminates the traditional silos between data engineers and data scientists.

Why it matters

In the past, organizations had to manage separate services for their data pipelines, their data lakes, and their relational data warehouses. This fragmentation led to complex security configurations and delayed insights. Synapse Analytics solves this by offering a "single pane of glass" experience.

  • Unified Experience: You can write code, build pipelines, and create dashboards all within the Synapse Studio web interface.
  • Scalability: It allows you to scale compute resources independently from storage, meaning you only pay for what you use.
  • Versatility: Whether you prefer using SQL, Python, Scala, or Spark SQL, the platform supports multiple languages to suit different skill sets.
  • Deep Integration: It connects natively with other Azure services like Power BI for visualization and Azure Machine Learning for predictive modeling.

Step-by-step walkthrough

Getting started with Azure Synapse involves setting up your environment and understanding the primary components of the workspace.

1. Provisioning the Workspace

The first step is to create a Synapse Workspace in the Azure Portal. During setup, you will be asked to define a Data Lake Storage Gen2 account. This serves as the primary storage layer where your raw and processed data will live.

2. Exploring Synapse Studio

Once the workspace is ready, you launch Synapse Studio. This is where the work happens. The left-hand sidebar contains several key hubs:

  • Data: To browse your linked storage and databases.
  • Develop: To write SQL scripts, notebooks, and Power BI reports.
  • Integrate: To create pipelines (similar to Azure Data Factory).
  • Monitor: To check the status of your spark jobs and pipeline runs.
  • Manage: To configure SQL pools, Spark pools, and security.

3. Choosing a Compute Pool

Synapse offers different ways to process data:

  • Serverless SQL Pool: Used for ad-hoc data exploration. You pay per terabyte of data processed. It is ideal for querying data directly in the data lake.
  • Dedicated SQL Pool: Used for high-performance data warehousing. You reserve a specific amount of compute power (DWUs).
  • Apache Spark Pool: Used for big data processing, machine learning, and data engineering using Python or Scala.

4. Querying Data from the Lake

One of the most powerful features is the ability to query CSV or Parquet files directly from your data lake using standard SQL without moving the data into a database.


-- Querying a CSV file from the Data Lake using Serverless SQL
SELECT TOP 100 *
FROM OPENROWSET(
    BULK 'https://yourstorageaccount.dfs.core.windows.net/container/data/taxi_data.csv',
    FORMAT = 'CSV',
    PARSER_VERSION = '2.0',
    HEADER_ROW = TRUE
) AS [result]

Common mistakes

  • Leaving Dedicated Pools running: Dedicated SQL pools incur costs as long as they are "Online." Always pause them when they are not in use to save money.
  • Ignoring Partitioning: When dealing with massive datasets in the data lake, failing to partition your data (e.g., by Year/Month/Day) can lead to slow queries and higher costs in Serverless SQL.
  • Using the wrong tool for the job: Beginners often try to use Spark for small tasks that a Serverless SQL query could handle faster and cheaper, or vice-versa.
  • Overlooking Security: Not configuring Managed Identities or Role-Based Access Control (RBAC) properly can lead to "Access Denied" errors when Synapse tries to read from the storage account.

Practice task

To get hands-on experience, try the following exercise:

  • Create a free Azure account and provision a Synapse Workspace.
  • In the Data hub, go to the Linked tab and find the sample datasets provided by Azure (like the NYC Yellow Taxi data).
  • Right-click a Parquet file in the sample storage and select New SQL Script > Select TOP 100 rows.
  • Run the script using the Built-in (Serverless) SQL pool.
  • Modify the query to find the average trip distance grouped by the passenger count.
