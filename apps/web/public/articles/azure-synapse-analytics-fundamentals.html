Azure Synapse Analytics fundamentals

Azure Synapse Analytics is a comprehensive analytics service that brings together data integration, enterprise data warehousing, and big data analytics. It provides a single environment where data professionals can ingest, explore, prepare, manage, and serve data for immediate business intelligence and machine learning needs. By unifying these traditionally separate tasks, it streamlines the data lifecycle and allows teams to collaborate more effectively on a single platform.

Why it matters

In the past, data engineers and analysts had to stitch together multiple disconnected services to build a data platform. You might use Azure Data Factory for movement, Databricks for processing, and SQL Data Warehouse for storage. Synapse Analytics removes this friction by offering:

  • Unification: One workspace (Synapse Studio) to manage your entire data pipeline.
  • Flexibility: You can use T-SQL for relational data or Spark for big data processing within the same tool.
  • Scalability: It can handle petabytes of data, allowing your infrastructure to grow with your business.
  • Cost Management: With serverless SQL pools, you only pay for the queries you run, making it accessible for smaller projects.

Step-by-step walkthrough

Getting started with Azure Synapse involves understanding its core components and setting up your first workspace.

1. Create a Synapse Workspace

Log into the Azure Portal and search for "Azure Synapse Analytics." When creating a workspace, you will need to define a Resource Group and a Storage account (Data Lake Storage Gen2). This storage acts as the "primary" location where your data resides.

2. Explore Synapse Studio

Once the resource is deployed, launch Synapse Studio. This is your web-based command center. You will see several hubs on the left:

  • Data: Manage your databases and linked storage.
  • Develop: Write SQL scripts, Notebooks, and Power BI reports.
  • Integrate: Build pipelines to move data (similar to Azure Data Factory).
  • Monitor: Check the status of your jobs and resource usage.
  • Manage: Create and scale your SQL and Spark pools.

3. Understand the Analytical Engines

Synapse offers two main ways to process data:

  • SQL Pools: Use standard T-SQL. You can choose "Dedicated" (fixed resources) or "Serverless" (on-demand).
  • Apache Spark Pools: Use Python, Scala, or Spark SQL for big data processing and machine learning.

4. Link External Data

Synapse excels at querying data directly where it lives. You can "link" services like Azure Blob Storage or Cosmos DB. This allows you to query a CSV or Parquet file using SQL without actually importing it into a database table.


-- Querying a CSV file directly from a Data Lake using Serverless SQL
SELECT TOP 100 *
FROM OPENROWSET(
    BULK 'https://yourdatalake.dfs.core.windows.net/container/data/sales.csv',
    FORMAT = 'CSV',
    PARSER_VERSION = '2.0',
    HEADER_ROW = TRUE
) AS [result]

Common mistakes

  • Leaving Dedicated Pools Running: Dedicated SQL pools are billed hourly as long as they are active. If you aren't using them, pause them to save costs.
  • Ignoring Partitioning: When dealing with large datasets in the Data Lake, failing to partition your data (e.g., by Year/Month/Day) can lead to slow query performance and higher costs in serverless models.
  • Over-provisioning: Beginners often create large Spark pools or high-tier SQL pools for small tasks. Start small and scale up only when performance dictates.
  • Networking Configuration: Many users struggle with "Access Denied" errors because they haven't configured the Azure Firewall to allow their IP address or "Allow Azure services" to access the workspace.

Practice task

To get hands-on experience, follow these steps:

  • Create a Synapse Workspace in your Azure environment.
  • Upload a small CSV file to your primary ADLS Gen2 storage account.
  • In Synapse Studio, go to the Data hub, right-click your CSV file, and select New SQL Script > Select TOP 100 rows.
  • Run the script using the "Built-in" (Serverless) SQL pool and observe how Synapse interprets the flat file as a table.
