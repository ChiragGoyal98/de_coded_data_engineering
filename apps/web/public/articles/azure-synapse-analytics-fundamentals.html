Azure Synapse Analytics fundamentals

In the world of cloud data engineering, managing separate tools for data warehousing and big data processing often creates silos and complexity. Azure Synapse Analytics is Microsoft's response to this challenge, offering a unified platform that merges data integration, enterprise data warehousing, and big data analytics into a single environment. By providing a centralized workspace, it allows teams to ingest, explore, prepare, manage, and serve data for immediate business intelligence and machine learning needs without switching between multiple disconnected services.

Why it matters

Modern organizations deal with data that is both structured (like SQL tables) and unstructured (like JSON files or images). Traditionally, you would need an ETL tool like Informatica, a data warehouse like SQL Server, and a big data platform like Hadoop or Spark to manage this. Azure Synapse Analytics matters because it provides:

  • Unified Interface: The Synapse Studio provides a single "pane of glass" for developers, data engineers, and data scientists.
  • Limitless Scale: It can query petabytes of data using either on-demand (serverless) resources or provisioned (dedicated) resources.
  • Hybrid Data Processing: You can use T-SQL for standard warehousing and Python/Scala/Spark for big data processing within the same project.
  • Cost Efficiency: With serverless SQL pools, you only pay for the data processed by your queries, making it ideal for ad-hoc exploration.

Step-by-step walkthrough

1. Provisioning the Workspace

The first step is creating an Azure Synapse Workspace in the Azure Portal. During setup, you must define an Azure Data Lake Storage (ADLS) Gen2 account. This storage serves as the "primary" location where your raw data lives.

2. Navigating Synapse Studio

Once the workspace is ready, you enter Synapse Studio. The sidebar contains five main hubs:

  • Data: Access your linked databases and external data lakes.
  • Develop: Create SQL scripts, Spark notebooks, and Power BI reports.
  • Integrate: Build pipelines (similar to Azure Data Factory) to move and transform data.
  • Monitor: Check the status of your queries, pipeline runs, and resource usage.
  • Manage: Configure SQL pools, Spark pools, and security settings.

3. Choosing Your Analytical Engine

Synapse offers two main ways to process data:

  • SQL Pools: Use Dedicated SQL Pools for high-performance, persistent data warehousing. Use Serverless SQL Pools for quick data exploration of files in your data lake without needing to load them into a table.
  • Apache Spark Pools: Used for data engineering tasks like cleaning data, feature engineering for machine learning, or processing massive datasets using languages like Python or Scala.

4. Querying Data from the Lake

One of the most powerful features is the ability to query a CSV or Parquet file sitting in your storage account using standard SQL. This is known as "Data Lakehouse" architecture.


-- Querying a CSV file directly from Azure Data Lake using Serverless SQL
SELECT TOP 10 *
FROM OPENROWSET(
    BULK 'https://mystorage.dfs.core.windows.net/rawdata/sales_2023.csv',
    FORMAT = 'CSV',
    PARSER_VERSION = '2.0',
    FIRSTROW = 2
) AS [result]

Common mistakes

  • Leaving Dedicated Pools Running: Dedicated SQL pools are billed by the hour. If you aren't using them, pause them to avoid unnecessary costs.
  • Ignoring Partitioning: When storing data in a data lake, failing to partition your files (e.g., by /Year/Month/Day/) can lead to extremely slow query performance as the engine has to scan every single file.
  • Over-provisioning Spark: New users often create large Spark clusters for small tasks. Start small and use "Auto-scale" features to let Azure manage the resources for you.
  • Neglecting Security: Always use Managed Identities or Service Principals for data access instead of hardcoding credentials in notebooks or scripts.

One practice task

To get hands-on, try the following:

  • Upload a small CSV file to your Azure Data Lake Gen2 container.
  • Open Synapse Studio and go to the Data hub.
  • Find your file, right-click it, and select New SQL Script > Select TOP 100 rows.
  • Run the generated query using the Built-in (Serverless) SQL pool to see your data appear in the results grid without having to import it into a database.
