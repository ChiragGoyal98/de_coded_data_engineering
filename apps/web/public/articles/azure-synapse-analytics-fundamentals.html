Azure Synapse Analytics is a comprehensive, cloud-based analytics service that bridges the gap between data warehousing and big data analytics. In the past, data professionals had to use separate tools for storing structured data, processing unstructured big data, and orchestrating data movements. Synapse integrates these tasks into a single platform, allowing you to ingest, explore, prepare, manage, and serve data for immediate business intelligence and machine learning needs.

Why it matters

Before unified platforms like Synapse, a typical data architecture was fragmented. You might use Azure Data Factory for movement, a SQL database for storage, and Databricks for processing. This fragmentation created "data silos" and complicated security and governance.

Synapse matters because it provides:

  • Unified Experience: Through Synapse Studio, you can write SQL queries, develop Spark notebooks, and build ETL pipelines in one window.
  • Choice of Language: You can use T-SQL, Python, Scala, or Spark SQL depending on your expertise and the task at hand.
  • Scaling Flexibility: It offers both "Serverless" models (pay-per-query, great for quick exploration) and "Dedicated" models (reserved resources for high-performance workloads).
  • Deep Integration: It connects natively with Power BI, Azure Machine Learning, and Azure Data Lake Storage Gen2.

Step-by-step walkthrough

1. Creating the Synapse Workspace

To start, you need to create a Synapse Workspace in the Azure Portal. This is the central environment where all your data work happens. During setup, you will also define an Azure Data Lake Storage Gen2 (ADLS Gen2) account which acts as the "primary" storage for the workspace.

2. Navigating Synapse Studio

Once the workspace is ready, you open Synapse Studio. The interface is divided into several "Hubs":

  • Data: Where you browse your databases and linked data lakes.
  • Develop: Where you create SQL scripts, notebooks, and Power BI reports.
  • Integrate: Where you build pipelines to move data (similar to Azure Data Factory).
  • Monitor: Where you check the status of your queries and pipeline runs.
  • Manage: Where you control your compute pools and security.

3. Understanding SQL Pools

Synapse offers two ways to use SQL:

  • Serverless SQL Pool: This is always available. You don't need to set up a database; you can just write a query to read a CSV or Parquet file sitting in your data lake. You only pay for the data processed by the query.
  • Dedicated SQL Pool: This is for heavy-duty data warehousing. You "provision" a specific amount of power (measured in DWUs), and it stores data in high-performance relational tables.

4. Querying a File with Serverless SQL

A common first step in Synapse is querying "raw" data in the data lake without importing it into a database first. You can do this using the OPENROWSET function.


-- Querying a CSV file directly from the Data Lake
SELECT
    TOP 100 *
FROM
    OPENROWSET(
        BULK 'https://yourstorageaccount.dfs.core.windows.net/container/folder/data.csv',
        FORMAT = 'CSV',
        PARSER_VERSION = '2.0',
        FIRSTROW = 2
    ) AS [result]

5. Using Apache Spark Pools

If you prefer Python or need to handle massive, unstructured datasets, you can create a Spark Pool. This allows you to use Spark Notebooks to perform data engineering or machine learning tasks using managed clusters that scale up or down automatically.

Common mistakes

  • Leaving Dedicated Pools Running: Dedicated SQL pools charge you as long as they are "Online." Beginners often forget to pause them when they aren't working, leading to unexpected costs. Always pause your dedicated pools when they are not in use.
  • Ignoring Storage Formats: Using CSV for massive datasets in a data lake is inefficient. Converting your data to Parquet or Delta format can significantly speed up queries and reduce the cost of serverless SQL processing.
  • Over-provisioning: It is tempting to create the largest Spark or SQL pool available. Start small; Synapse is designed to scale up easily as your data volume grows.

One practice task

To get hands-on experience, try the following:

  • Upload a small CSV file (like a sample sales dataset) to your Azure Data Lake Storage Gen2.
  • Go to the Data Hub in Synapse Studio.
  • Right-click the CSV file and select New SQL Script > Select TOP 100 rows.
  • Run the generated script to see how the Serverless SQL pool reads the file.
  • Try modifying the script to calculate the average of one of your numeric columns using a GROUP BY clause.
