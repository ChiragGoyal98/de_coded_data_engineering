Azure Synapse Analytics fundamentals

Azure Synapse Analytics is a powerful, integrated service designed to handle large-scale data processing and analytics in a single environment. It combines the capabilities of SQL data warehousing, big data processing with Spark, and data integration through pipelines, all under one roof. By centralizing these tools, it allows teams to ingest, explore, prepare, manage, and serve data for immediate business intelligence and machine learning needs without switching between multiple disconnected platforms.

Why it matters

Before the advent of unified platforms, data professionals had to stitch together different services: one for data movement (like Azure Data Factory), one for big data processing (like Spark), and another for data warehousing (like SQL Server). This fragmentation created silos and high maintenance overhead.

Synapse Analytics matters because:

  • Unified Experience: It provides a single interface called Synapse Studio for all tasks.
  • Scaling Flexibility: You can scale compute and storage independently, ensuring you only pay for what you use.
  • Language Choice: You can work with SQL, Python, Scala, R, or .NET depending on your expertise and the specific task.
  • Hybrid Data Processing: It handles both structured data (from relational databases) and unstructured data (from data lakes) seamlessly.

Step-by-step walkthrough

To get started with Synapse, you need to understand the core workflow of setting up a workspace and choosing the right compute "pool."

1. Create a Synapse Workspace

The workspace is the top-level container for everything you do. When you create one in the Azure Portal, you will also be required to link an Azure Data Lake Storage (ADLS) Gen2 account. This storage serves as the primary location for your raw and processed files.

2. Launch Synapse Studio

Once the workspace is ready, you enter Synapse Studio. This is the web-based IDE where you write code and manage resources. On the left sidebar, you will find hubs for:

  • Data: Explore linked storage and databases.
  • Develop: Create SQL scripts, Notebooks, and Power BI reports.
  • Integrate: Build pipelines to move and transform data.
  • Monitor: Check the status of your jobs and resource usage.

3. Choose Your Analytical Engine

Synapse uses "Pools" to perform work. You need to pick the right one for your task:

  • Serverless SQL Pool: Used for ad-hoc exploration. You pay per query based on the amount of data processed.
  • Dedicated SQL Pool: Used for high-performance enterprise data warehousing. You pay for the compute resources you keep running.
  • Apache Spark Pool: Used for big data processing, machine learning, and data preparation using Python or Scala.

4. Querying Data

The fastest way to see the power of Synapse is to query a file sitting in your data lake using the Serverless SQL pool. You don't need to load the data into a table first; you can query it "in place."


-- Querying a CSV file directly from Azure Data Lake
SELECT TOP 100 *
FROM OPENROWSET(
    BULK 'https://youraccount.dfs.core.windows.net/container/data/sales.csv',
    FORMAT = 'CSV',
    PARSER_VERSION = '2.0',
    FIRSTROW = 2
) AS [result]

Common mistakes

  • Leaving Dedicated Pools Running: Dedicated SQL pools and Spark pools incur costs while they are active. Beginners often forget to pause dedicated pools or set up auto-pause for Spark pools, leading to unexpected bills.
  • Using the Wrong Pool for the Job: Don't use a Dedicated SQL pool for simple CSV exploration; a Serverless pool is much cheaper and faster for that specific task.
  • Ignoring Data Partitioning: If your data lake has millions of files, querying them without a proper folder structure (like Year/Month/Day) will make your queries slow and expensive.
  • Overlooking Security: By default, Synapse workspaces can be accessed publicly. Always ensure you configure firewall rules or Private Endpoints in production environments.

Practice task

Try this exercise to get comfortable with the environment:

  • Create an Azure Synapse Workspace and an ADLS Gen2 account.
  • Upload a small CSV file (like a sample sales dataset) to your storage container.
  • Open Synapse Studio and go to the Data hub.
  • Right-click your uploaded CSV file and select New SQL Script > Select TOP 100 rows.
  • Run the script using the "Built-in" (Serverless) SQL pool and observe how the data is displayed without any database setup.
