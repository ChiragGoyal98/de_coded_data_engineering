Azure Synapse Analytics fundamentals

Azure Synapse Analytics is a comprehensive data integration and analytics service provided by Microsoft. It bridges the gap between data warehousing and big data analytics by offering a unified workspace where data engineers and data scientists can collaborate. Essentially, it replaces the need for managing multiple separate services by combining data ingestion, processing, and visualization into a single interface.

Why it matters

In the past, organizations had to maintain separate silos for relational data (Data Warehouses) and non-relational data (Data Lakes). This led to complex data pipelines and high maintenance costs. Azure Synapse Analytics matters because it:

  • Provides a unified experience: The Synapse Studio serves as a single pane of glass for all data tasks.
  • Offers hybrid compute: You can choose between Serverless SQL pools (pay-per-query) for ad-hoc analysis or Dedicated SQL pools for high-performance warehousing.
  • Simplifies Big Data: It integrates Apache Spark natively, allowing users to process massive datasets using Python or Scala without leaving the environment.
  • Enhances collaboration: Data scientists can build machine learning models in the same environment where data engineers are cleaning and transforming data.

Step-by-step walkthrough

Setting up and using Azure Synapse involves a few core stages. Here is how to get started.

1. Create a Synapse Workspace

Search for "Azure Synapse Analytics" in the Azure Portal. You will need to provide a workspace name, select a region, and link it to an Azure Data Lake Storage (ADLS) Gen2 account. This storage account acts as the primary data repository for your workspace.

2. Navigate Synapse Studio

Once the workspace is deployed, open the Synapse Studio. On the left sidebar, you will see key hubs:

  • Data: Manage your databases and linked storage.
  • Develop: Create SQL scripts, Spark notebooks, and Data Flow.
  • Integrate: Build pipelines to move and transform data.
  • Monitor: Check the status of your compute resources and pipeline runs.
  • Manage: Configure SQL and Spark pools and manage access control.

3. Choose Your Compute Pool

Synapse offers different ways to process data:

  • Serverless SQL Pool: Always available and used for querying files in your data lake using T-SQL. You are charged only for the data processed.
  • Dedicated SQL Pool: Pre-provisioned resources used for enterprise-level data warehousing where performance must be predictable.
  • Apache Spark Pool: Used for big data processing, data preparation, and machine learning tasks.

4. Querying Data

One of the most powerful features is the ability to query files directly in the data lake without importing them into a database table first. Use the OPENROWSET function to read CSV, Parquet, or JSON files.


-- Querying a CSV file from the Data Lake using Serverless SQL
SELECT TOP 100 *
FROM OPENROWSET(
    BULK 'https://youraccount.dfs.core.windows.net/container/data/sales.csv',
    FORMAT = 'CSV',
    PARSER_VERSION = '2.0',
    FIRSTROW = 2
) AS [result]

Common mistakes

  • Neglecting Firewall Settings: Users often forget to allow "Azure services and resources to access this workspace" in the networking settings, resulting in connection errors.
  • Incorrect Compute Choice: Using a Dedicated SQL Pool for simple, occasional ad-hoc queries can lead to unnecessary costs. Serverless is usually the better choice for exploration.
  • Forgetting to Pause Dedicated Pools: Unlike Serverless pools, Dedicated SQL pools incur costs as long as they are running. Always pause them when not in use to save budget.
  • Overlooking Security: By default, the creator has access, but you must manually configure Synapse RBAC (Role-Based Access Control) to grant team members access to the Studio hubs.

One practice task

To get hands-on experience, try the following:

  • Upload a small CSV file (like a list of movies or products) to your linked ADLS Gen2 container.
  • Go to the "Data" hub in Synapse Studio.
  • Right-click the CSV file and select "New SQL Script" > "Select TOP 100 rows".
  • Run the script using the "Built-in" (Serverless) SQL pool and observe the results in the output grid.
