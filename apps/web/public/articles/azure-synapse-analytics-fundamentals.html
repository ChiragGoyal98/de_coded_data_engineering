Azure Synapse Analytics fundamentals

Azure Synapse Analytics acts as a unified platform that bridges the gap between big data systems and traditional data warehousing. It integrates various services like data integration pipelines, big data analytics, and enterprise data warehousing into a single environment called Synapse Studio. This allows data engineers, analysts, and data scientists to collaborate on the same datasets using different languages such as SQL, Python, or Scala, without the need to switch between multiple standalone cloud services.

Why it matters

In the past, organizations had to manage separate environments for their relational databases and their "big data" clusters (like Hadoop or Spark). This created data silos and complex moving parts. Azure Synapse Analytics solves this by providing:

  • Unified Experience: One interface (Synapse Studio) to ingest, explore, prepare, manage, and serve data for immediate BI and machine learning needs.
  • Flexible Compute: You can choose between serverless SQL pools for ad-hoc exploration (pay-per-query) or dedicated SQL pools for high-performance enterprise data warehousing.
  • Integrated Spark: It includes a built-in Apache Spark engine for big data processing and machine learning.
  • Deep Integration: It connects natively with Azure Data Lake Storage (ADLS) Gen2, Power BI, and Azure Purview for data governance.

Step-by-step walkthrough

1. Set up a Synapse Workspace

The workspace is your central hub. In the Azure Portal, search for "Azure Synapse Analytics" and create a new workspace. You will be required to create or select an Azure Data Lake Storage Gen2 account and a file system (container) during this process. This serves as the "primary" storage for your workspace metadata.

2. Launch Synapse Studio

Once the workspace is deployed, click on the "Open Synapse Studio" link. This web-based UI is where all the work happens. On the left sidebar, you will see sections for Data (linking to your storage), Develop (SQL scripts and notebooks), Integrate (pipelines), and Monitor.

3. Explore data with Serverless SQL

You don't need to load data into a table to query it. Go to the "Data" tab, navigate to your linked storage, right-click a CSV or Parquet file, and select "New SQL script" > "Select TOP 100 rows." This uses the Serverless SQL pool to read data directly from the lake.

4. Process data with Spark

If you need to perform complex transformations, create a "Spark Pool" under the Manage tab. You can then create a Notebook in the Develop tab, attach it to your Spark pool, and use Python (PySpark) to clean or aggregate your data.

5. Visualize with Power BI

You can link a Power BI workspace directly to Synapse. This allows you to create visualizations based on your Synapse SQL pools without ever leaving the Synapse interface.

Code Example: Querying a CSV file

This SQL snippet demonstrates how to use the built-in Serverless SQL pool to query a file sitting in your Data Lake. Replace the URL with your specific file path.


SELECT
    TOP 100 *
FROM
    OPENROWSET(
        BULK 'https://mystorageaccount.dfs.core.windows.net/mycontainer/rawdata/sales.csv',
        FORMAT = 'CSV',
        PARSER_VERSION = '2.0',
        HEADER_ROW = TRUE
    ) AS [result]

Common mistakes

  • Leaving Dedicated Pools Running: Unlike Serverless pools, Dedicated SQL pools charge you as long as they are "Running." Always pause them when not in use to save costs.
  • Ignoring Security Firewalls: By default, the Synapse workspace might block all incoming traffic. You must configure the "Networking" settings to allow your IP address and enable "Allow Azure services" to connect.
  • Over-provisioning Spark: Beginners often create large Spark clusters for small tasks. Start with "Small" node sizes and enable "Auto-pause" to ensure you don't burn through your budget.
  • Choosing the Wrong Pool: Use Serverless SQL for ad-hoc data exploration and Dedicated SQL for predictable, high-concurrency reporting workloads.

Practice task

To get hands-on experience, follow these steps:

  • Upload a small CSV file (like a sample "Sales" or "Weather" dataset) to your Azure Data Lake Storage Gen2 container.
  • In Synapse Studio, use the "Data" tab to find that file.
  • Right-click the file and use a Serverless SQL script to view the data.
  • Try to modify the SQL script to filter the data (e.g., WHERE Price > 100).
  • Create a "New Notebook" and try to load the same file into a Spark dataframe using PySpark.
