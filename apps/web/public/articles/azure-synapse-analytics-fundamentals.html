Azure Synapse Analytics fundamentals

In the world of data engineering, tools often exist in silos. You might use one service for data integration, another for big data processing, and a third for data warehousing. Azure Synapse Analytics changes this landscape by providing a unified platform that brings these three worlds together into a single workspace. It is essentially an evolution of Azure SQL Data Warehouse, but with a much broader scope, allowing you to ingest, explore, prepare, manage, and serve data for immediate business intelligence and machine learning needs.

Why it matters

Before Synapse, data teams often struggled with "glue code"-the scripts and manual processes required to move data between different services. For example, moving data from a Spark cluster to a SQL database often meant managing complex pipelines.

Azure Synapse Analytics removes this friction by offering:

  • A unified UI (Synapse Studio) where developers, data scientists, and analysts can work together.
  • Versatile processing options, allowing you to choose between SQL (T-SQL) or Spark (Python, Scala, Spark SQL) depending on the task.
  • Seamless integration with other Azure services like Power BI and Azure Machine Learning.
  • Scalability that separates compute from storage, meaning you only pay for what you use when you use it.

Step-by-step walkthrough

Getting started with Azure Synapse involves understanding the environment and setting up your first "pool."

1. Create a Synapse Workspace

To start, you need to provision a Synapse Workspace in the Azure Portal. During setup, you will be asked to create or select an Azure Data Lake Storage (ADLS) Gen2 account. This storage serves as the primary "home" for your data.

2. Understand the Analytical Pools

Synapse uses "pools" to provide compute power. There are three main types:

  • Serverless SQL Pool: This is always available. You are charged based on the amount of data processed per query. It is perfect for exploring data sitting in your Data Lake without moving it.
  • Dedicated SQL Pool: This is for high-performance enterprise data warehousing. You reserve compute power (measured in Data Warehouse Units or DWUs) and pay for it as long as the pool is running.
  • Apache Spark Pool: This is used for big data processing, data preparation, and machine learning using languages like Python or Scala.

3. Explore Synapse Studio

Once your workspace is ready, you open Synapse Studio. This is the web-based hub where the magic happens. On the left sidebar, you will find:

  • Data: To browse your linked storage accounts and databases.
  • Develop: To write SQL scripts, notebooks, and Spark jobs.
  • Integrate: To build ETL pipelines (similar to Azure Data Factory).
  • Monitor: To check the status of your queries and pipeline runs.

4. Querying Data

The fastest way to see the power of Synapse is to query a file in your Data Lake using the Serverless SQL pool. You don't need to load the data into a table first; you can query it directly using the OPENROWSET function.


-- Querying a CSV file directly from the Data Lake
SELECT TOP 10 *
FROM OPENROWSET(
    BULK 'https://youraccount.dfs.core.windows.net/container/folder/data.csv',
    FORMAT = 'CSV',
    PARSER_VERSION = '2.0',
    HEADER_ROW = TRUE
) AS rows;

Common mistakes

  • Leaving Dedicated Pools running: Unlike Serverless pools, Dedicated SQL pools and Spark pools (if not configured for auto-pause) incur costs even when not in use. Always pause your Dedicated pools when they are not needed.
  • Over-provisioning: Beginners often start with a large node size for Spark or high DWUs for SQL. Start small and scale up only when performance dictates it.
  • Ignoring Primary Keys: In Dedicated SQL pools, the way data is distributed across nodes is crucial. Using the wrong distribution method (like using a unique ID for a Round Robin distribution) can lead to slow query performance.
  • Not using the Data Lake: Many users treat Synapse like a standard SQL server and ignore the Data Lake. The real power lies in the "Lakehouse" approach-keeping raw data in the lake and using SQL/Spark to process it.

Practice task

To get hands-on experience, follow these steps:

  • Create a free Azure account if you don't have one.
  • Provision a Synapse Workspace with a default ADLS Gen2 account.
  • Upload a sample CSV file (like a public weather dataset or sales data) to your ADLS Gen2 container using the "Data" tab.
  • Right-click the file and select "New SQL Script" -> "Select TOP 100 rows."
  • Run the generated script to see how the Serverless SQL pool interacts with your file instantly.
