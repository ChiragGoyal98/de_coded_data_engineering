Azure Synapse Analytics fundamentals

Azure Synapse Analytics is an integrated analytics service that accelerates time to insight across data warehouses and big data systems. It brings together the best of SQL technologies used in enterprise data warehousing, Spark technologies used for big data, Pipelines for data integration and ETL/ELT, and deep integration with other Azure services like Power BI and Azure Machine Learning. Essentially, it provides a single workspace for data engineers, data scientists, and analysts to collaborate without needing to switch between multiple disconnected tools.

Why it matters

In traditional data architectures, you often have to manage a separate data warehouse for structured data and a separate "data lake" for unstructured data. This creates silos, complicates security, and requires complex pipelines to move data back and forth.

Synapse solves this by providing:

  • Unified Experience: Through the Synapse Studio, you can write code, build pipelines, and create visualizations in one interface.
  • Limitless Scale: It can handle petabytes of data using distributed processing.
  • Cost Flexibility: You can choose between "Serverless" SQL pools (pay-per-query, great for ad-hoc analysis) or "Dedicated" SQL pools (provisioned resources for high-performance warehousing).
  • Hybrid Data Integration: It includes the same engine found in Azure Data Factory, allowing you to ingest data from over 90+ sources.

Step-by-step walkthrough

To get started with Synapse, you need to understand the core components of the Synapse Studio workspace.

1. Provisioning the Workspace

First, you create a Synapse Workspace in the Azure Portal. Every workspace requires an Azure Data Lake Storage Gen2 (ADLS Gen2) account to serve as the primary storage layer. This is where your raw files (CSV, Parquet, JSON) will live.

2. Exploring the Analytical Engines

Once inside Synapse Studio, you have three main ways to process data:

  • SQL Pools: Use T-SQL to query data. If you have a CSV file in your data lake, you can use the Serverless SQL pool to query it immediately without moving the data into a database.
  • Apache Spark Pools: Use Python, Scala, or Spark SQL for big data processing, machine learning, and data engineering tasks.
  • Data Explorer (Preview): Optimized for log and time-series data using KQL (Kusto Query Language).

3. Data Integration

Navigate to the "Integrate" tab to create Pipelines. These are similar to Azure Data Factory. You can create "Copy Data" activities to move data from an on-premises SQL Server or a cloud API into your Azure Data Lake.

4. Querying Data

You don't always need to "load" data to see it. Under the "Data" tab, you can right-click any file in your linked storage and select "New SQL Script" > "Select top 100 rows."

Here is a short example of a T-SQL query used in a Serverless SQL Pool to read a CSV file directly from the Data Lake:


SELECT
    TOP 100 *
FROM
    OPENROWSET(
        BULK 'https://youraccount.dfs.core.windows.net/container/rawdata/sales.csv',
        FORMAT = 'CSV',
        PARSER_VERSION = '2.0',
        HEADER_ROW = TRUE
    ) AS [result]

Common mistakes

  • Leaving Dedicated Pools Running: Dedicated SQL pools are billed hourly as long as they are "Online." Always pause them when not in use to save costs.
  • Neglecting File Formats: While Synapse can read CSVs, it is much faster and cheaper to query Parquet files. Parquet is a columnar format that reduces the amount of data the engine needs to scan.
  • Storage Permissions: Beginners often forget that the Synapse Workspace needs "Storage Blob Data Contributor" permissions on the ADLS Gen2 account to actually read and write data.
  • Over-provisioning Spark: Creating a large Spark pool for small tasks leads to unnecessary costs due to the minimum "node" count and start-up time.

One practice task

To get hands-on experience, try the following:

  • Upload a small CSV file (like a sample sales dataset) to your Azure Data Lake Gen2.
  • Open Synapse Studio and go to the Data hub.
  • Locate your file under the Linked tab.
  • Right-click the file and select New SQL Script > Select TOP 100 rows.
  • Run the script using the "Built-in" (Serverless) SQL pool and observe how Synapse treats a flat file like a database table.
