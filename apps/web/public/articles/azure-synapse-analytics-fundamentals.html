Azure Synapse Analytics fundamentals

Azure Synapse Analytics is an integrated service designed to accelerate the time it takes to get insights from data across warehouses and big data systems. It brings together the best of SQL technologies used in enterprise data warehousing, Spark technologies used for big data, and Pipelines for data integration and ETL/ELT. By providing a single workspace for these diverse tasks, it simplifies the complex landscape of modern data engineering and allows different personas to collaborate in a single environment.

Why it matters

In the past, organizations had to maintain separate environments for data warehousing (like SQL Server) and big data processing (like Hadoop or Spark). This created silos where data moved slowly and engineers spent more time managing infrastructure than analyzing data.

Azure Synapse Analytics solves this by offering a "unified experience." It allows you to query relational and non-relational data using the same service. Whether you are a data engineer building pipelines, a data scientist training machine learning models, or a business analyst creating Power BI reports, Synapse provides the tools to do all three in one place. Its ability to scale compute resources independently from storage makes it both cost-effective and powerful for handling petabytes of data.

Step-by-step walkthrough

1. Provisioning the Workspace

The first step is creating a Synapse Workspace in the Azure Portal. During setup, you must define an Azure Data Lake Storage Gen2 (ADLS Gen2) account. This acts as the "primary" storage for your workspace, where all your raw files and data logs will live.

2. Navigating Synapse Studio

Once the workspace is ready, you enter Synapse Studio. This is the web-based interface where the work happens. It is divided into several hubs:

  • Data: Manage your databases and linked storage accounts.
  • Develop: Write SQL scripts, KQL queries, notebooks (Spark), and Power BI reports.
  • Integrate: Build pipelines (similar to Azure Data Factory) to move and transform data.
  • Monitor: Check the status of your jobs, pipeline runs, and resource usage.
  • Manage: Create and manage SQL and Spark pools.

3. Choosing Your Analytics Engine

Synapse offers two main types of SQL pools to process your data:

  • Serverless SQL Pool: Always available, you pay only for the data processed per query. It is ideal for "data discovery" or querying files sitting in the Data Lake.
  • Dedicated SQL Pool: You reserve a specific amount of processing power (measured in DWUs). This is best for high-performance data warehousing and production workloads.

4. Exploring Data with SQL

To see data without moving it into a database, you can use the Serverless SQL pool. This allows you to run SQL queries directly against CSV, Parquet, or JSON files stored in your Data Lake.


-- Querying a CSV file directly from Data Lake
SELECT TOP 100 *
FROM OPENROWSET(
    BULK 'https://yourdatalake.dfs.core.windows.net/rawdata/sales_2023.csv',
    FORMAT = 'CSV',
    PARSER_VERSION = '2.0',
    HEADER_ROW = TRUE
) AS [result];

Common mistakes

  • Leaving Dedicated Pools Running: Dedicated SQL pools charge by the hour as long as they are "Active." Beginners often forget to pause these pools when not in use, leading to high bills. Always pause them if they aren't processing data.
  • Overlooking Data Partitioning: When querying large datasets in the Data Lake, performance can be slow if your data isn't partitioned (e.g., by Year/Month/Day). Without partitioning, the engine has to scan every file to find the relevant data.
  • Using the Wrong Engine: Don't use a Spark pool for simple SQL transformations that a Serverless SQL pool could do faster and cheaper. Choose Spark only when you need complex data science libraries or heavy-duty data shuffling.

One practice task

To get hands-on experience, try the following:

  • Upload a small CSV file containing any public dataset to your primary ADLS Gen2 container.
  • In Synapse Studio, go to the Data hub and find your file.
  • Right-click the file and select New SQL Script > Select TOP 100 rows.
  • Run the script using the Built-in (Serverless) pool and observe how the data is displayed in the results pane without being imported into a table.
