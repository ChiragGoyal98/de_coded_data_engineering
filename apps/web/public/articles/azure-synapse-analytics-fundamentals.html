Introduction

Azure Synapse Analytics is an integrated analytics service designed to accelerate time to insight across data warehouses and big data systems. At its core, it brings together the best of SQL technologies used in enterprise data warehousing, Spark technologies used for big data, and pipelines for data integration and ETL/ELT. Rather than managing multiple disconnected services, Synapse provides a single workspace for data engineers, data scientists, and analysts to collaborate. It allows you to query data on your own terms, using either serverless or dedicated resources, depending on your project needs.

Why it matters

In the past, building a complete data platform required stitching together several distinct tools: Azure Data Factory for moving data, Azure Databricks for processing, and Azure SQL Data Warehouse for storage. This created "data silos" and complex management overhead.

Synapse matters because it unifies these capabilities into a single pane of glass called the Synapse Studio. This consolidation allows for:

  • Unified Security: Manage access to data and resources in one place.
  • Lower Latency: Since the compute and storage are tightly integrated, moving data between components is significantly faster.
  • Cost Flexibility: You can use the "Serverless SQL" pool for unplanned or ad-hoc analysis, paying only per query, or use "Dedicated SQL" pools for high-performance, predictable workloads.

Step-by-step walkthrough

1. Provisioning a Synapse Workspace

To get started, search for "Azure Synapse Analytics" in the Azure Portal. When creating the workspace, you will need to define a primary Azure Data Lake Storage (ADLS) Gen2 account and a file system. This acts as the "storage backbone" where all your raw files and logs will reside.

2. Exploring the Synapse Studio

Once the resource is deployed, open the Synapse Studio. You will see several "Hubs" on the left-hand sidebar:

  • Data Hub: Where you browse your linked databases and data lakes.
  • Develop Hub: Where you write SQL scripts, notebooks, and Power BI reports.
  • Integrate Hub: Where you create "Pipelines" (similar to Azure Data Factory) to move data.
  • Monitor Hub: Where you check the status of your queries and pipeline runs.
  • Manage Hub: Where you manage compute pools (SQL and Spark) and security.

3. Choosing Your Compute Pool

Before running a query, you must decide which engine to use:

  • Serverless SQL Pool: Always available. Great for exploring files in the Data Lake using T-SQL without moving them into a database.
  • Dedicated SQL Pool: Must be started manually. Best for heavy, production-grade reporting where high performance is required.
  • Apache Spark Pool: Used for data engineering tasks like data cleaning or machine learning using Python, Scala, or Spark SQL.

4. Querying Data with SQL

One of the most powerful features is the ability to query a CSV or Parquet file sitting in your storage account using standard SQL. You don't need to "import" the data; you simply point to the file path.


-- Querying a CSV file directly from the Data Lake
SELECT TOP 100 *
FROM OPENROWSET(
    BULK 'https://youraccount.dfs.core.windows.net/container/data/orders.csv',
    FORMAT = 'CSV',
    PARSER_VERSION = '2.0',
    HEADER_ROW = TRUE
) AS [result];

Common mistakes

  • Leaving Dedicated Pools Running: Dedicated SQL pools charge by the hour as long as they are "Online." Always pause your dedicated pools when they are not in use to avoid unexpected costs.
  • Over-provisioning Spark: New users often create Spark clusters that are too large for simple data cleaning tasks. Start with small "Node sizes" and enable "Auto-pause" to save credits.
  • Using the Wrong Tool for the Job: Using a Dedicated SQL Pool for a simple one-time exploration of a 10MB file is overkill. For ad-hoc file exploration, always use the Serverless SQL pool.
  • Ignoring Data Partitioning: When storing data in the Data Lake, failing to organize files into folders (e.g., by Year/Month/Day) will make your queries significantly slower and more expensive as the system has to scan every single file.

One practice task

To get hands-on experience, try the following:

  • Upload a small CSV file (like a sample sales record) to your linked ADLS Gen2 storage container.
  • Go to the Data Hub, right-click the file, and select New SQL Script > Select TOP 100 rows.
  • Run the script using the Built-in (Serverless) SQL pool.
  • Modify the generated query to add a WHERE clause to filter the data, then click Run again to see how quickly Synapse can process "data at rest."
