Azure Synapse Analytics fundamentals

Azure Synapse Analytics is a unified platform designed to bridge the gap between data warehousing and big data analytics. In the past, organizations had to manage separate systems for relational data (like SQL Server) and non-relational data (like Hadoop or Spark). Synapse brings these worlds together into a single workspace, allowing data engineers and analysts to ingest, explore, prepare, manage, and serve data for immediate business intelligence and machine learning needs. It is essentially a limitless analytics service that provides a single UI for every stage of the data lifecycle.

Why it matters

Before the advent of unified platforms, data teams spent a significant amount of time "stitching" together different services. You might have used Azure Data Factory for ingestion, Azure Databricks for processing, and Azure SQL Data Warehouse for storage. Synapse simplifies this by offering:

  • Unified Experience: Through Synapse Studio, you can perform all tasks-from writing SQL scripts and Spark notebooks to building ETL pipelines-in one place.
  • Choice of Runtimes: You can use T-SQL for standard data warehousing or Python/Scala/Spark for big data processing, depending on the task.
  • Scaling on Demand: It separates storage from compute, meaning you only pay for the processing power you use, whether you choose a serverless model or a dedicated pool.
  • Deep Integration: It works natively with other Azure services like Power BI and Azure Machine Learning, streamlining the path from raw data to visual insights.

Step-by-step walkthrough

To get started with Azure Synapse Analytics, you need to understand the core components and how they interact. Follow these steps to set up your first environment.

1. Create a Synapse Workspace

The Workspace is your central hub. In the Azure Portal, search for "Azure Synapse Analytics" and create a new resource. During setup, you will be asked to create an Azure Data Lake Storage (ADLS) Gen2 account. This serves as the primary storage "sink" where your data files will reside.

2. Explore Synapse Studio

Once the resource is deployed, click "Open Synapse Studio." This is the web-based IDE where the work happens. You will see several hubs on the left sidebar:

  • Data: To browse your linked storage and databases.
  • Develop: To write SQL scripts, Spark notebooks, and Power BI reports.
  • Integrate: To build data pipelines (similar to Azure Data Factory).
  • Monitor: To check the status of your jobs.
  • Manage: To create and manage your compute pools (SQL and Spark).

3. Choose your SQL Pool

Synapse offers two types of SQL pools:

  • Serverless SQL Pool: Always available and billed per TB of data processed. It is perfect for exploring files in the Data Lake using T-SQL.
  • Dedicated SQL Pool: For high-performance data warehousing. You provision a specific amount of power (DWUs) and it is billed hourly.

4. Querying Data

You don't always need to load data into a table to read it. Using the Serverless SQL pool, you can query CSV or Parquet files directly from your Data Lake using the OPENROWSET function.


-- Querying a CSV file directly from the Data Lake
SELECT TOP 100 *
FROM OPENROWSET(
    BULK 'https://yourdatalake.dfs.core.windows.net/container/folder/data.csv',
    FORMAT = 'CSV',
    PARSER_VERSION = '2.0',
    FIRSTROW = 2
) AS [result]

5. Transform with Spark

If you prefer coding over SQL, you can create an Apache Spark pool. This allows you to create Notebooks to transform data using Python (PySpark) or Scala. This is ideal for complex data engineering or preparing data for machine learning models.

Common mistakes

  • Leaving Dedicated Pools Running: Dedicated SQL pools are billed as long as they are "Online." Always pause your dedicated pools when they aren't in use to avoid unnecessary costs.
  • Ignoring Partitioning: When storing large amounts of data in the Data Lake, failing to partition your files (e.g., by Year/Month/Day) can lead to slow query performance and higher costs in Serverless SQL.
  • Identity and Access Management (IAM) Confusion: Users often forget that they need permissions in two places: the Synapse Workspace itself and the underlying Data Lake storage. If you can access the workspace but can't see data, check your "Storage Blob Data Contributor" role.
  • Over-provisioning: Don't start with the highest performance tier. Start small, monitor your workload in the "Monitor" hub, and scale up only when you hit performance bottlenecks.

Practice task

To reinforce what you have learned, try this simple workflow:

  • Upload a small CSV file (like a sample sales dataset) to your ADLS Gen2 storage container.
  • In Synapse Studio, go to the Data hub, right-click the file, and select New SQL Script > Select TOP 100 rows.
  • Run the script using the Built-in (Serverless) SQL pool.
  • Modify the script to filter the data (e.g., WHERE Price > 100) and see how quickly the serverless engine returns results without you having to set up a database.
