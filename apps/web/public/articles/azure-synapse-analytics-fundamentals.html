Azure Synapse Analytics fundamentals

Azure Synapse Analytics is an integrated analytics service that brings together enterprise data warehousing and Big Data analytics. It offers a single environment where data professionals can ingest, explore, prepare, manage, and serve data for immediate business intelligence and machine learning needs. By unifying different technologies that were previously separate, it provides a cohesive platform for the entire data pipeline, allowing users to query data on their own terms using either serverless or dedicated resources at scale.

Why it Matters

In the past, data engineers had to jump between multiple tools to handle different parts of the data lifecycle. You might have used Azure Data Factory for ingestion, Azure Databricks for processing, and Azure SQL Data Warehouse for storage. Synapse Analytics eliminates this fragmentation by providing:

  • Unified Experience: Through Synapse Studio, you can write code, build pipelines, and create visualizations in one interface.
  • Choice of Language: Whether you prefer T-SQL for structured data or Python/Scala (Spark) for big data processing, Synapse supports both natively.
  • Cost Flexibility: You can choose between "Serverless SQL" (pay-per-query) for ad-hoc exploration and "Dedicated SQL pools" (reserved capacity) for high-performance warehousing.
  • Deep Integration: It connects seamlessly with Azure Data Lake Storage Gen2, Power BI, and Azure Machine Learning.

Step-by-Step Walkthrough

Getting started with Azure Synapse involves setting up your environment and understanding how to navigate the workspace.

1. Provision the Workspace

Go to the Azure Portal and search for "Azure Synapse Analytics." When creating a workspace, you will need to specify a subscription, a resource group, and a name. Crucially, you must also link it to an Azure Data Lake Storage Gen2 account, which acts as the "primary" storage for your workspace data.

2. Enter Synapse Studio

Once your resource is deployed, click "Open Synapse Studio." This is the web-based IDE where all your work happens. On the left sidebar, you will see several hubs:

  • Data: Manage your databases and linked storage.
  • Develop: Write SQL scripts, KQL scripts, and Notebooks.
  • Integrate: Build ETL pipelines (similar to Azure Data Factory).
  • Monitor: Check the status of your jobs and resource usage.
  • Manage: Configure SQL pools, Spark pools, and security.

3. Choose Your Analytical Engine

You need to decide how to process your data:

  • Serverless SQL Pool: Always available. Use this for querying CSV, Parquet, or JSON files directly in the data lake using SQL.
  • Dedicated SQL Pool: Must be started manually. Use this for high-performance reporting and data warehousing.
  • Apache Spark Pool: Use this for data engineering tasks like cleaning large datasets or training ML models using Spark notebooks.

4. Querying Data Lake Files

One of the most powerful features is the ability to query "files" as if they were "tables" without importing them. You can right-click a Parquet file in the Data hub and select "New SQL script > Select TOP 100 rows."


-- Example: Querying a Parquet file using the Serverless SQL pool
SELECT
    TOP 100 *
FROM
    OPENROWSET(
        BULK 'https://yourdatalake.dfs.core.windows.net/raw/data.parquet',
        FORMAT = 'PARQUET'
    ) AS [result]

Common Mistakes

  • Leaving Dedicated Pools Running: Unlike Serverless pools, Dedicated SQL pools charge you as long as they are "Running," even if you aren't querying them. Always pause them when not in use.
  • Using Dedicated Pools for Small Data: If your dataset is only a few gigabytes, the overhead of a Dedicated SQL pool might actually be slower and more expensive than using the Serverless option.
  • Ignoring Partitioning: When storing data in a Data Lake for Synapse to query, failing to partition your data (e.g., by /year/month/day/) will result in much slower queries and higher costs in Serverless mode, as the engine has to scan every file.
  • Over-provisioning Spark: Creating massive Spark clusters for simple data cleaning tasks can drain your Azure credit quickly. Start small and scale up only when necessary.

Practice Task

To get hands-on experience, try the following exercise:

  • Upload a small CSV file (like a public weather or sales dataset) to your Azure Data Lake Gen2 container.
  • In Synapse Studio, go to the Data hub and find your file under "Linked."
  • Right-click the file and select "New SQL Script" -> "Select TOP 100 rows."
  • Change the file format settings in the generated script to handle headers (e.g., PARSER_VERSION = '2.0', HEADER_ROW = TRUE).
  • Run the script and observe how the Serverless SQL pool displays your file contents in a table format.
