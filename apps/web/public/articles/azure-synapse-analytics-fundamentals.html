Azure Synapse Analytics fundamentals

Azure Synapse Analytics is a comprehensive enterprise analytics service that accelerates time to insight across data warehouses and big data systems. It brings together the best of SQL technologies used in enterprise data warehousing, Spark technologies used for big data, and Pipelines for data integration and ETL/ELT. By offering a single environment to ingest, explore, prepare, manage, and serve data, it simplifies the complex landscape of modern data architecture.

Why it matters

In the past, data engineers had to manage separate services for data warehousing (like SQL Server), big data processing (like Spark), and data integration (like Data Factory). This fragmented approach led to "data silos" and complex maintenance.

Azure Synapse Analytics changes the game by providing:

  • Unified Experience: A single UI called Synapse Studio where you can write code, build pipelines, and create dashboards.
  • Scalability: The ability to scale compute resources up or down depending on the workload, ensuring you only pay for what you use.
  • Hybrid Data Processing: It allows you to query data sitting in your Data Lake (unstructured) using familiar SQL (structured) languages without moving the data.
  • Deep Integration: It works natively with Azure Purview for governance and Power BI for visualization.

Step-by-step walkthrough

1. Create a Synapse Workspace

The workspace is your top-level container. To start, search for "Azure Synapse Analytics" in the Azure Portal and create a new workspace. You will be required to link it to an Azure Data Lake Storage (ADLS) Gen2 account, which acts as the "storage layer" for your data.

2. Explore Synapse Studio

Once your workspace is deployed, launch Synapse Studio. This is the web-based hub where all the work happens. The left-hand menu is divided into:

  • Data: Where you see your databases and linked storage.
  • Develop: Where you write SQL scripts, Spark notebooks, and Power BI reports.
  • Integrate: Where you build ETL pipelines (similar to Azure Data Factory).
  • Monitor: To track the health of your jobs and resource usage.

3. Choose Your Analytical Engine

Synapse provides two main ways to process data:

  • SQL Pools: Use Serverless SQL for unplanned, ad-hoc data exploration (you pay per TB processed). Use Dedicated SQL for high-performance, predictable data warehousing workloads.
  • Apache Spark Pools: Use these for big data processing, machine learning, and data preparation using Python, Scala, or Spark SQL.

4. Querying Data from the Lake

One of the most powerful features is the ability to query files in your Data Lake using SQL. You don't need to "import" the data; you simply point the SQL engine at the file.


-- Querying a CSV file directly from Azure Data Lake
SELECT TOP 100 *
FROM OPENROWSET(
    BULK 'https://<your-storage-account>.dfs.core.windows.net/<container>/data/sales.csv',
    FORMAT = 'CSV',
    PARSER_VERSION = '2.0',
    FIRSTROW = 2
) AS [result]

Common mistakes

  • Leaving Dedicated Pools Running: Dedicated SQL pools are billed hourly as long as they are active. If you aren't using them, pause them to save costs.
  • Ignoring Firewall Settings: By default, Synapse workspaces are secure. Beginners often forget to allow their client IP address or "Allow Azure services" in the Networking tab, leading to connection errors.
  • Over-provisioning Spark: Creating a Large Spark pool for a small data transformation task results in unnecessary costs. Start small and scale up only when performance dictates.
  • Not using Parquet: While Synapse can read CSVs, it is optimized for Parquet files. Using Parquet reduces the amount of data scanned, making queries faster and cheaper (especially in Serverless SQL).

Practice task

To get hands-on experience, follow these steps:

  • Upload a small CSV file (like a sample dataset of weather or sales) to your linked Azure Data Lake Storage account.
  • Open Synapse Studio and go to the Data tab.
  • Browse to your linked storage, right-click the CSV file, and select New SQL script > Select TOP 100 rows.
  • Run the generated script using the Built-in (Serverless) SQL pool.
  • Try modifying the script to add a WHERE clause to filter the data.
