Azure Data Lake design for analytics teams

Azure Data Lake Storage (ADLS) Gen2 is the foundation for modern data architectures on the Microsoft cloud. It combines the scalability of object storage with the hierarchical file system capabilities required for high-performance analytics. For an analytics team, a well-designed data lake ensures that data is organized, secure, and ready for processing by tools like Azure Databricks, Synapse Analytics, or Power BI. By setting up the storage layer correctly from the start, you prevent the lake from turning into a data swamp where information is lost or inaccessible.

Why it matters

Designing a data lake with intent is crucial for three main reasons:

  • Performance: A logical folder structure allows analytics engines to "prune" data, meaning they only read the specific files needed for a query rather than scanning the entire lake.
  • Security: In Azure, permissions can be inherited. A structured design allows you to grant a data scientist access to "processed" data while keeping "raw" sensitive data restricted to a small group of data engineers.
  • Cost Efficiency: ADLS Gen2 allows for lifecycle management policies. You can automatically move older, less-frequently accessed data to "Cool" or "Archive" storage tiers to save money.

Step-by-step walkthrough

1. Enable Hierarchical Namespace (HNS)

When creating your Storage Account in the Azure Portal, you must enable the Hierarchical Namespace setting under the "Advanced" tab. This transforms the storage from a flat object store into a true file system with directories, which is essential for the performance of big data workloads.

2. Implement the Medallion Architecture

The industry standard for organizing a data lake is the Medallion (or multi-hop) architecture. You should create three primary containers:

  • Bronze (Raw): This is the landing zone. Data is stored in its original format (JSON, CSV, etc.) exactly as it arrived from the source. It is immutable-never change the data here.
  • Silver (Cleansed): Data is filtered, joined, and standardized. For example, date formats are unified, and null values are handled. This is usually stored in Delta or Parquet format for faster reading.
  • Gold (Curated): This contains business-level aggregates. This data is "clean" and ready for consumption by Power BI or executive dashboards.

3. Organize by Subject and Time

Inside your containers, use a naming convention that prioritizes subject area and then time-based partitioning. A common pattern looks like this:

container/subject_area/source_system/year/month/day/

Example:

bronze/sales/sap_erp/2023/10/24/data.json

4. Manage Security with ACLs

While Azure Role-Based Access Control (RBAC) works at the account or container level, Access Control Lists (ACLs) allow you to set permissions on specific folders. Always use Azure Active Directory (Entra ID) groups rather than assigning permissions to individual users.

Common mistakes

  • The Small File Problem: Storing thousands of 1KB files significantly slows down analytics engines. Aim for file sizes between 256MB and 1GB.
  • Mixing Environments: Never put Dev, Test, and Prod data in the same Storage Account. Use separate accounts to prevent accidental deletions and to manage costs independently.
  • Ignoring Lifecycle Management: Teams often forget to set up policies that delete temporary "staging" files, leading to bloated storage costs over time.

Code Example: Creating a Data Lake via CLI

You can automate the creation of a properly configured Data Lake using the Azure CLI. The following command creates a storage account with the Hierarchical Namespace enabled.


az storage account create \
    --name myanalyticsdatalake \
    --resource-group rg-analytics-prod \
    --location eastus \
    --sku Standard_LRS \
    --kind StorageV2 \
    --enable-inter-tier-copying true \
    --enable-hns true

Practice task

Try to set up a basic data lake structure for a "Weather Data" project:

  • Create a Storage Account in your Azure sandbox with Hierarchical Namespace enabled.
  • Create three containers: 01-bronze, 02-silver, and 03-gold.
  • Create a folder path in 01-bronze for a weather sensor in London, partitioned by the current year and month.
  • Upload a dummy CSV file to that folder and practice setting an "Access Control" permission that gives a teammate "Reader" access to only the 03-gold container.
