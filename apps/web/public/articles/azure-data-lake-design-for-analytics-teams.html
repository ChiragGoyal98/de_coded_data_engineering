Azure Data Lake design for analytics teams

Azure Data Lake Storage (ADLS) Gen2 is the foundational storage layer for building an analytics platform on Microsoft Azure. It combines the scalability of object storage with the organizational capabilities of a hierarchical file system, allowing teams to store massive amounts of structured, semi-structured, and unstructured data. For an analytics team, the data lake is more than just a repository; it is a structured environment where raw information is transformed into actionable insights through a series of logical stages.

Why it matters

A well-designed data lake prevents the common pitfall of creating a "data swamp," where files are uploaded without organization and eventually become impossible to find or use. By following a structured design, teams can achieve:

  • Cost Efficiency: Storing data in a lake is significantly cheaper than storing it in a relational database.
  • Decoupled Compute: Multiple tools like Power BI, Azure Databricks, and Synapse Analytics can all read from the same data source simultaneously.
  • Scalability: You can start with gigabytes of data and grow to petabytes without needing to re-architect your storage.
  • Standardized Governance: A consistent folder structure makes it easier to apply security policies and lifecycle management rules.

Step-by-step walkthrough

1. Enable Hierarchical Namespace

When creating your Storage Account in Azure, you must enable the Hierarchical Namespace (HNS) feature. This is what turns a basic blob store into a true data lake. HNS allows you to create folders and subfolders, which makes data access and security much faster and more intuitive for analytics engines.

2. Implement the Medallion Architecture

The most common design pattern for data lakes is the Medallion Architecture. This divides your data into three distinct containers:

  • Bronze (Raw): This layer stores data exactly as it comes from the source. No transformations are allowed here. If a data pipeline fails, you can always restart from this layer.
  • Silver (Cleansed/Enriched): Data is filtered, cleaned, and joined. This is where you remove duplicates and fix formatting issues.
  • Gold (Curated): Data is aggregated and organized into a business-friendly format, often optimized for reporting tools like Power BI.

3. Organize Folders by Subject and Date

Inside your containers, you should follow a predictable naming convention. A common pattern is:

SubjectArea/Entity/Year/Month/Day/File

For example, a sales file would live at:

/silver/sales/orders/2023/10/24/orders_transformed.parquet

4. Choose the Right File Format

While CSVs are easy to read, they are inefficient for big data. For the Silver and Gold layers, use Parquet or Delta formats. These are columnar formats that compress data heavily and allow analytics tools to read only the columns they need, saving time and money.

Below is an example of how you might save a cleaned dataset into your Silver layer using PySpark:


# Saving a Spark DataFrame to the Silver layer in Parquet format
storage_path = "abfss://silver@yourdatalake.dfs.core.windows.net/sales/orders/2023/10/"

df_cleaned.write \
    .mode("overwrite") \
    .partitionBy("day") \
    .parquet(storage_path)

5. Manage Security with ACLs

Instead of giving every user the "Account Key," use Azure Active Directory (Microsoft Entra ID). You can apply Access Control Lists (ACLs) to specific folders. For instance, the Finance team can have access to the /gold/finance folder but remain restricted from the /bronze raw data.

Common mistakes

  • Using the "Flat" Namespace: If you don't enable Hierarchical Namespace during setup, you cannot change it later without migrating all your data.
  • Poor Naming Conventions: Using spaces or special characters in folder names can break some analytics tools. Stick to lowercase and underscores.
  • Over-partitioning: Creating too many small folders (e.g., partitioning by hour and minute) can slow down performance because the system has to open too many small files.
  • Ignoring Lifecycle Management: Forgetting to set up rules to move old data to "Cool" or "Archive" storage tiers leads to unnecessarily high monthly bills.

One practice task

Imagine you are designing a data lake for a retail company that tracks website clicks. Your task is to sketch out the folder structure for the Bronze and Silver layers.

  • Create a container named bronze.
  • Inside bronze, create a folder path for website clicks originating from a "Marketing" source for the date December 12, 2023.
  • Decide which file format you would use to save the processed version of this data in the silver container.

Answer Hint: Your path should look like /bronze/marketing/web_clicks/year=2023/month=12/day=12/ and the Silver format should ideally be Parquet or Delta.
