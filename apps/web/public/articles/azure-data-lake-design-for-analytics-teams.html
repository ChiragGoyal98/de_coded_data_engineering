Azure Data Lake design for analytics teams

Setting up a data lake is often the first major hurdle for a data team building on Azure. At its core, Azure Data Lake Storage (ADLS) Gen2 is a highly scalable, cost-effective storage solution designed specifically for big data analytics. Unlike a traditional database that stores data in rigid tables, a data lake allows you to store structured, semi-structured, and unstructured data in a hierarchical folder structure. For analytics teams, the goal of a well-designed data lake is to provide a single source of truth that is organized enough for data scientists to find what they need, but flexible enough for data engineers to ingest data quickly.

Why it matters

Without a deliberate design, a data lake quickly transforms into a data swamp. This happens when files are uploaded without naming conventions, consistent formats, or security controls. A well-designed data lake matters because:

  • It reduces data discovery time: Analysts can find the data they need without asking engineers where it is.
  • It optimizes costs: By using different storage tiers (Hot, Cool, Archive) based on the folder structure, you save money on data that isn't accessed frequently.
  • It ensures security: Proper design allows you to apply fine-grained access control, ensuring that sensitive HR or financial data is only visible to authorized users.
  • It scales performance: Good partitioning strategies (how you group files) speed up query performance for tools like Synapse, Databricks, and Power BI.

Step-by-step walkthrough

1. Adopt the Medallion Architecture

The most common design pattern is the Medallion Architecture, which organizes data into three distinct layers based on its quality and readiness for use.

  • Bronze (Raw): This is where data arrives in its original format. No transformations are allowed here. It serves as a historical record.
  • Silver (Cleansed/Enriched): Data is converted to a performant format like Parquet, cleaned of duplicates, and standardized (e.g., all dates in the same format).
  • Gold (Curated/Business): This layer contains data that is ready for consumption. It is usually organized by business department (Sales, Finance) and is often aggregated for reporting.

2. Implement a Consistent Naming Convention

Folders should follow a predictable pattern. A common standard is:

/{layer}/{source_system}/{entity_name}/{year}/{month}/{day}/

For example:

/bronze/sap_erp/orders/2023/10/24/

3. Choose the Right File Format

While the Bronze layer can store CSVs or JSONs, the Silver and Gold layers should almost always use Apache Parquet or Delta format. These formats are compressed and "columnar," meaning tools like Spark or SQL Server can skip over columns they don't need, making queries significantly faster and cheaper.

4. Configure Security and Access

Use Azure Active Directory (now Microsoft Entra ID) for authentication. Avoid using Account Keys, which give full control. Instead:

  • Use Role-Based Access Control (RBAC) for broad permissions (e.g., who can manage the storage account).
  • Use Access Control Lists (ACLs) for granular permissions (e.g., who can read a specific folder in the Silver layer).

5. Automated Directory Creation

When setting up your environment, you can use the Azure CLI to programmatically create your base structure. This ensures consistency across your Dev, Test, and Prod environments.


# Create the main containers for the Medallion layers
az storage container create --name bronze --account-name mydatalakeaccount
az storage container create --name silver --account-name mydatalakeaccount
az storage container create --name gold --account-name mydatalakeaccount

# Create a sub-directory for a specific source system in Bronze
az storage fs directory create --name raw-sales-data --file-system bronze --account-name mydatalakeaccount

Common mistakes

  • Treating the lake like a local folder: Avoid using spaces or special characters in folder names. Use underscores or hyphens instead.
  • Managing users individually: Always assign permissions to Security Groups rather than individual users. If an employee leaves the company, you only have to remove them from the group once.
  • Ignoring Lifecycle Management: Teams often forget to set rules that automatically move old Bronze data to "Cool" or "Archive" storage tiers after 30 or 90 days, leading to unnecessarily high monthly bills.
  • Creating too many small files: Thousands of 1KB files will kill the performance of your analytics engines. Aim for larger files (generally 128MB to 1GB) by compacting data in the Silver layer.

Practice task

Imagine you are the Lead Data Engineer for a global retail chain. You need to design a structure for the "Bronze" layer that will receive daily sales data from three different regions: North America (NA), Europe (EU), and Asia (AS).

  • Sketch out a folder hierarchy that includes the region, the year, and the month.
  • Decide which folder should have restricted access to comply with GDPR (hint: focus on the EU region).
  • Write down a sample file path for a sales file arriving from Europe on Christmas Day, 2023.
