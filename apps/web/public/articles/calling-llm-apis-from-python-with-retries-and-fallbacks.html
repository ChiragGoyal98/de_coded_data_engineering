Calling LLM APIs from Python with retries and fallbacks

When you start building with Large Language Models, the first thing you learn is how to send a prompt and get a response. However, moving from a script that works once to an application that works every time requires handling the unpredictable nature of the internet. APIs can be slow, hit rate limits, or experience temporary downtime. Learning how to build resilient connections is a fundamental skill for any developer working with AI.

Why it matters

Building "resiliency" into your code means your application can survive a hiccup without crashing. This is crucial for LLM applications for three main reasons:

  • Rate Limiting: Popular providers like OpenAI or Anthropic limit how many requests you can make per minute. If you exceed this, the API simply says "no" for a few seconds.
  • Network Flakiness: Requests can time out or fail due to a weak internet connection or server-side congestion.
  • Cost and Performance: If a high-end model (like GPT-4) is down or too slow, falling back to a faster, cheaper model (like GPT-3.5) keeps your app functional for the user.

Step-by-step walkthrough

To handle these issues, we use two main strategies: Retries (trying the same request again after a short wait) and Fallbacks (trying a different model or provider if the first one fails).

1. Setting up the environment

You will need the openai library and a library called tenacity, which is the industry standard for adding retry logic to Python functions.


pip install openai tenacity

2. Implementing Retries

A "retry" shouldn't just happen immediately. If the server is busy, hitting it again instantly will just cause another error. We use Exponential Backoff, which means we wait a little longer after each failed attempt.


from openai import OpenAI
from tenacity import retry, stop_after_attempt, wait_exponential

client = OpenAI(api_key="your_api_key_here")

@retry(wait=wait_exponential(min=1, max=10), stop=stop_after_attempt(3))
def call_llm_with_retry(prompt):
    response = client.chat.completions.create(
        model="gpt-3.5-turbo",
        messages=[{"role": "user", "content": prompt}]
    )
    return response.choices[0].message.content

In the code above, the @retry decorator tells Python to try the function up to 3 times. It starts by waiting 1 second, then doubles the wait time, up to a maximum of 10 seconds.

3. Implementing Fallbacks

A fallback is your "Plan B." If the primary model fails after all retry attempts, we catch the error and try a different model.


def robust_llm_call(prompt):
    try:
        # Attempt Plan A (The preferred model)
        return call_llm_with_retry(prompt)
    except Exception as e:
        print(f"Primary model failed: {e}. Switching to fallback...")
        # Attempt Plan B (The backup model)
        response = client.chat.completions.create(
            model="gpt-3.5-turbo-instruct", # A different model
            messages=[{"role": "user", "content": prompt}]
        )
        return response.choices[0].message.content

Common mistakes

  • Retrying on the wrong errors: Do not retry if the error is "Invalid API Key" or "Bad Request." Those are permanent errors that won't fix themselves. Only retry on 500-level (server) errors or rate limits.
  • Infinite loops: Always set a stop_after_attempt limit. Otherwise, a dead API could keep your script running (and potentially costing money) forever.
  • Ignoring timeouts: Sometimes an API doesn't fail; it just hangs. Always set a timeout parameter in your API call so the code knows when to give up and trigger a retry.

One practice task

Create a Python script that attempts to summarize a paragraph of text. Implement a retry strategy that tries 5 times, and if it still fails, returns a hardcoded string saying "The service is currently overwhelmed, please try again later" instead of letting the program crash. Bonus: Log the number of attempts to the console so you can see the retries happening in real-time.
