Calling LLM APIs from Python with retries and fallbacks

Integrating Large Language Models (LLMs) into your Python applications is an exciting step in software development. However, relying on a cloud-based API means your application is at the mercy of network stability, provider uptime, and rate limits. To build a production-ready application, you need to move beyond simple requests and implement strategies that make your code resilient to common errors. This tutorial will show you how to handle these challenges using retries and fallbacks.

Why it matters

API calls can fail for many reasons that are outside of your control. The most common issues include rate limiting (where you have sent too many requests in a short window), temporary server overloads, or unexpected network drops. If your code does not account for these, your application will crash or return an error to the user.

Implementing retries allows your code to automatically try the request again after a brief pause, which often solves temporary "hiccups." Fallbacks take this a step further by providing a backup plan-such as switching to a different, more stable model-if the primary model remains unavailable.

Step-by-step walkthrough

1. Setting up your environment

First, you will need a library to handle the API calls and a specialized library for retry logic. The tenacity library is the industry standard for adding retry behavior to Python functions.


pip install openai tenacity

2. Implementing basic retries

A retry strategy should not just spam the API immediately after a failure. Instead, it should use "exponential backoff," which means waiting longer between each successive attempt. This gives the API provider time to recover.

In the example below, we use the @retry decorator from Tenacity to automatically retry a function if it encounters an error.


from openai import OpenAI
from tenacity import retry, stop_after_attempt, wait_exponential

client = OpenAI(api_key="your_api_key_here")

@retry(wait=wait_exponential(min=1, max=10), stop=stop_after_attempt(3))
def get_completion(prompt):
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}]
    )
    return response.choices[0].message.content

In this code, if the API call fails, Tenacity will wait 1 second, then 2, then 4, up to a maximum of 3 attempts before finally giving up.

3. Adding a fallback mechanism

Sometimes, retrying the same model isn't enough. If a specific high-end model is experiencing a service outage, you may want to fall back to a smaller, more reliable model to keep your app running. You can achieve this using a standard try-except block.


def robust_llm_call(prompt):
    try:
        # Attempt the primary, high-quality model
        return get_completion(prompt)
    except Exception as e:
        print(f"Primary model failed: {e}. Switching to fallback...")
        # Fallback to a faster, more available model
        response = client.chat.completions.create(
            model="gpt-3.5-turbo",
            messages=[{"role": "user", "content": prompt}]
        )
        return response.choices[0].message.content

Common mistakes

  • Retrying on every error: You should only retry on "retriable" errors like 429 (Rate Limit) or 500/503 (Server Error). Do not retry on 401 (Unauthorized) or 400 (Bad Request), as these usually mean your code or API key is wrong and won't be fixed by trying again.
  • Infinite retries: Never set your retry logic to run indefinitely. This can lead to massive API bills or your IP address being blocked by the provider.
  • Ignoring timeouts: By default, some requests can hang for a long time. Always set a timeout parameter in your API call to ensure your application doesn't stay frozen.
