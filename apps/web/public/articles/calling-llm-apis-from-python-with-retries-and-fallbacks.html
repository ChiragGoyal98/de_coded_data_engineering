Calling LLM APIs from Python with retries and fallbacks

Integrating Large Language Models (LLMs) into your Python applications opens up a world of possibilities, from automated customer support to intelligent data analysis. However, moving from a local script to a production-ready tool requires more than just a simple API request. Internet connections flicker, servers experience high traffic, and APIs occasionally hit their rate limits. To build a robust application, you need to handle these interruptions gracefully.

Why it matters

When you rely on a third-party service like OpenAI or Anthropic, you are at the mercy of their uptime and your own network stability. Without a strategy for failures, a single "503 Service Unavailable" error can crash your entire program. Implementing retries ensures that temporary glitches don't stop your code, while fallbacks provide a "Plan B"-such as switching to a smaller, cheaper model-if your primary choice is unavailable. This leads to a better user experience and higher system reliability.

Step-by-step walkthrough

To handle errors effectively, we use a combination of the tenacity library for retries and standard Python logic for fallbacks.

1. Install required libraries

You will need the official API client and a retry handler.

pip install openai tenacity

2. Implement Retry Logic

The goal of a retry is to wait a few seconds and try again when a "transient" error occurs (like a network timeout). We use "exponential backoff," which means we wait longer after each failed attempt to avoid spamming the server.

3. Set up the Fallback

A fallback is your safety net. If your primary model (e.g., GPT-4o) fails after multiple retries, your code should automatically try a different model (e.g., GPT-4o-mini) to ensure the task is completed.


import openai
from tenacity import retry, stop_after_attempt, wait_random_exponential

client = openai.OpenAI(api_key="your_api_key")

# Retry decorator: tries 3 times with increasing wait times
@retry(wait=wait_random_exponential(min=1, max=60), stop=stop_after_attempt(3))
def call_llm(model_name, prompt):
    return client.chat.completions.create(
        model=model_name,
        messages=[{"role": "user", "content": prompt}],
        timeout=10 # Always set a timeout
    )

def safe_generate(prompt):
    try:
        # Primary attempt with your best model
        return call_llm("gpt-4o", prompt)
    except Exception as e:
        print(f"Primary model failed: {e}. Switching to fallback...")
        # Fallback attempt with a faster/cheaper model
        return call_llm("gpt-4o-mini", prompt)

Common mistakes

  • Retrying on every error: You should only retry on "retryable" errors like 500 (Server Error) or 429 (Rate Limit). Retrying a 401 (Unauthorized) error is useless because your API key won't magically become valid on the second try.
  • Infinite retries: Never set your retry count to infinite. If the service is down for maintenance, your script will hang forever and potentially consume unnecessary resources.
  • Ignoring timeouts: If the API hangs without sending an error, your code will stay stuck. Always define a timeout parameter in your request.

One practice task

Modify the code provided above to include a third "Final Safety" option. If both the primary and fallback models fail, make the function return a pre-written string response like "The system is currently overwhelmed, please try again in a few minutes" instead of raising an error.
