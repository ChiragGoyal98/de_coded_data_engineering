Calling LLM APIs from Python with retries and fallbacks

Connecting to a Large Language Model (LLM) through an API is often the first step in building an AI-powered application. While these APIs are powerful, they are not always reliable. Servers can become overloaded, network connections can drop, and rate limits can be reached. To build a professional application, you need to write code that can handle these hiccups gracefully without crashing the entire system for the user.

Why it matters

In a production environment, "it worked on my machine" isn't enough. LLM providers like OpenAI or Anthropic often enforce rate limits, which restrict how many requests you can send per minute. Additionally, cloud services occasionally experience "500 Internal Server Errors."

If your code simply stops when an error occurs, the user experience is ruined. Implementing retries allows your code to pause and try again automatically when a temporary error occurs. Fallbacks go a step further: if your primary model (like GPT-4) is down or too busy, your code can automatically switch to a secondary model (like GPT-3.5 or a local Llama model) to ensure the service remains available.

Step-by-step walkthrough

Building a resilient API caller involves two main layers: a retry loop for temporary glitches and a fallback block for total failures.

1. Setting up the environment

First, you will need the openai library and a library called tenacity, which is the industry standard for adding retry logic to Python functions.


pip install openai tenacity

2. Implementing Retries

The tenacity library uses "decorators"-special tags starting with @-to tell Python how to handle a function if it fails. We want to use "Exponential Backoff," which means the code waits longer and longer between each attempt so it doesn't overwhelm the API.

3. Creating the Fallback

A fallback is usually managed with a standard try-except block. If the retries for your main model fail after several attempts, the except block catches that failure and triggers a call to a different model.

4. The Complete Implementation

Below is a concise example showing how to combine these concepts.


import openai
from tenacity import retry, stop_after_attempt, wait_exponential

client = openai.OpenAI(api_key="your_api_key")

# This decorator tells the function to retry 3 times with increasing wait times
@retry(stop=stop_after_attempt(3), wait=wait_exponential(multiplier=1, min=2, max=10))
def call_primary_llm(prompt):
    return client.chat.completions.create(
        model="gpt-4",
        messages=[{"role": "user", "content": prompt}]
    )

def robust_llm_call(prompt):
    try:
        # Attempt the primary model with retries
        return call_primary_llm(prompt)
    except Exception as e:
        print(f"Primary model failed: {e}. Switching to fallback...")
        # Fallback to a cheaper/faster model
        return client.chat.completions.create(
            model="gpt-3.5-turbo",
            messages=[{"role": "user", "content": prompt}]
        )

Common mistakes

  • Retrying on every error: You should only retry on "retryable" errors like timeouts or rate limits (HTTP 429). Do not retry if the error is "Invalid API Key" (HTTP 401), as that will never succeed no matter how many times you try.
  • No maximum limit: Never set infinite retries. If the service is truly down, your code will get stuck in a loop forever.
  • Ignoring the wait time: If you hit a rate limit and immediately try again, you will likely hit it again. Always use a delay (like wait_exponential) to give the API "room to breathe."
  • Hardcoding keys: Beginners often leave their API keys directly in the code. Always use environment variables or a .env file to keep your credentials safe.

One practice task

Write a Python script that attempts to summarize a short paragraph using a "Premium" model. If that call fails after 2 retries, have the script print a message saying "Switching to Backup" and then successfully print the summary using a "Standard" model instead. To simulate a failure, you can temporarily change the model name in your primary function to something that doesn't exist, like gpt-fake-model.
