Calling LLM APIs from Python with retries and fallbacks

When building applications powered by Large Language Models (LLMs), the connection between your code and the AI provider is the most critical link. However, this link is often fragile. APIs can experience downtime, rate limits might be triggered by too many requests, or a network connection could simply drop. If your script crashes the moment an API returns an error, your application becomes unreliable. To solve this, developers use two main strategies: retries, which attempt the request again after a failure, and fallbacks, which switch to an alternative model if the first one continues to fail.

Why it matters

  • Resilience: It prevents minor network hiccups from breaking the entire application experience for the user.
  • Rate Limit Management: LLM providers enforce limits on how many requests you can send per minute. Retrying with a delay helps your script "wait its turn."
  • Cost Control and Availability: If a high-end model (like GPT-4) is experiencing a service outage, falling back to a smaller, cheaper model (like GPT-3.5 or an open-source model) keeps your service running.
  • Professionalism: Production-grade software is defined by how it handles failure, not just how it handles success.

Step-by-step walkthrough

1. Install necessary libraries

While you can write your own retry loops, the Python library tenacity is the industry standard for handling retries gracefully.


pip install openai tenacity

2. Implement Retries with Exponential Backoff

When an API fails, you shouldn't hammer it with requests immediately. "Exponential Backoff" means you wait a short time after the first failure, and longer after each subsequent failure.


import openai
from tenacity import retry, stop_after_attempt, wait_random_exponential

client = openai.OpenAI(api_key="your_api_key")

@retry(wait=wait_random_exponential(min=1, max=60), stop=stop_after_attempt(3))
def call_primary_llm(prompt):
    # This function will retry up to 3 times if it fails
    return client.chat.completions.create(
        model="gpt-4",
        messages=[{"role": "user", "content": prompt}]
    )

3. Create a Fallback Logic

A fallback acts as your safety net. You wrap your primary function in a try-except block. If the primary function exceeds its retries, the except block catches the error and tries a different model.


def robust_llm_call(prompt):
    try:
        # Try the expensive/primary model first
        return call_primary_llm(prompt)
    except Exception as e:
        print(f"Primary model failed after retries: {e}")
        print("Switching to fallback model...")
        # Fallback to a faster, more available model
        return client.chat.completions.create(
            model="gpt-3.5-turbo",
            messages=[{"role": "user", "content": prompt}]
        )

Common mistakes

  • Retrying on User Errors: Do not retry if the API returns a 400-level error (like "Invalid API Key" or "Prompt too long"). These will never succeed on a second try and will only waste time.
  • Missing Stop Conditions: Never create an infinite retry loop. Always set a stop_after_attempt or a timeout.
  • Not Logging Failures: If your code is constantly hitting its fallback model, you need to know. Always log when a fallback is triggered so you can investigate if the primary model's settings need adjustment.
  • Hardcoding Secrets: Never hardcode your API keys directly in the script. Use environment variables or a .env file.

One practice task

Write a Python function using tenacity that attempts to call an LLM API. Set the retry logic to attempt the call exactly 4 times. If all 4 attempts fail, catch the final exception and instead of letting the program crash, return a pre-written "canned response" such as: "I'm having trouble connecting to my brain right now, please try again later."
