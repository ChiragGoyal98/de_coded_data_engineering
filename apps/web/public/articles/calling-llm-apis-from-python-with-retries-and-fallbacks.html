Calling LLM APIs from Python with retries and fallbacks

When building applications that rely on Large Language Models (LLMs), developers often encounter a frustrating reality: APIs are not 100% reliable. Whether you are using OpenAI, Anthropic, or Google Gemini, you will eventually face rate limits, temporary server glitches, or network timeouts. If your code isn't prepared to handle these interruptions, your entire application might crash or hang, leading to a poor experience for your users. Learning how to build resilience into your Python scripts is a fundamental skill for any AI developer.

Why it matters

Building resilient API calls is about moving from a "happy path" script to a production-ready tool. Here is why retries and fallbacks are essential:

  • Maximizing Uptime: Temporary glitches (500-level errors) usually resolve in seconds. Retrying automatically ensures your script keeps running without manual intervention.
  • Handling Rate Limits: LLM providers impose limits on how many requests you can send per minute. Strategic retrying with "exponential backoff" lets your script wait just long enough for the limit to reset.
  • Cost and Reliability: If a high-end model like GPT-4o is down or too slow, a fallback to a faster, cheaper model like GPT-4o-mini ensures your application remains functional, even if the response quality is slightly lower.

Step-by-step walkthrough

To implement these features effectively, we will use the tenacity library for retries and standard Python try-except blocks for fallbacks.

1. Install necessary libraries

You will need the official API client and a retry library.

pip install openai tenacity

2. Implement Retries with Tenacity

The tenacity library uses decorators to wrap your functions. You can specify how many times to try and how long to wait between attempts. Exponential backoff is the best practice here, as it increases the wait time after each failure to avoid spamming the server.

3. Adding Fallback Logic

A fallback is your "Plan B." If the primary model fails after all retry attempts, you catch the error and try a different model or provider.

Code Example: Resilient LLM Call


import openai
from tenacity import retry, stop_after_attempt, wait_exponential

client = openai.OpenAI(api_key="your_api_key")

@retry(wait=wait_exponential(multiplier=1, min=4, max=10), stop=stop_after_attempt(3))
def call_primary_llm(prompt):
    # This will retry up to 3 times if it fails
    return client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}]
    )

def smart_llm_request(prompt):
    try:
        return call_primary_llm(prompt)
    except Exception as e:
        print(f"Primary model failed: {e}. Switching to fallback...")
        # Fallback to a smaller, more reliable model
        return client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": prompt}]
        )

Common mistakes

  • Retrying on Auth Errors: Never retry if the API returns a 401 (Unauthorized) or 403 (Forbidden) error. These are not temporary glitches; your API key is likely wrong, and retrying will only waste time.
  • Infinite Loops: Always set a stop_after_attempt limit. Without it, a persistent outage could cause your script to run forever, potentially racking up costs or consuming system resources.
  • Not Logging Failures: If your script silently switches to a fallback model, you might never realize your primary model configuration is broken. Always log or print when a retry or fallback occurs.
  • Tight Wait Times: Don't retry every 0.1 seconds. Give the server time to breathe by using at least a few seconds of delay.

One practice task

Modify the code example provided above to include a second fallback. If the "gpt-4o-mini" model also fails, the function should return a hardcoded string: "The service is currently unavailable, please try again later." instead of letting the program crash.
