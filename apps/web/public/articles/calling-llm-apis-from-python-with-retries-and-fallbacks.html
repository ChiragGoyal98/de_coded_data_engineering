Calling LLM APIs from Python with retries and fallbacks

When building applications powered by Large Language Models (LLMs), developers quickly realize that API calls are not always reliable. Whether it is a temporary network glitch, a sudden rate limit, or the provider being overwhelmed by traffic, these calls can fail at any moment. To build a production-ready application that feels seamless to the user, you need to handle these failures gracefully using two specific techniques: retries and fallbacks.

Why it matters

In a local environment, a single failed API call is a minor annoyance. In a live product, it results in a broken user experience.

  • Reliability: LLM providers like OpenAI or Anthropic occasionally experience "503 Service Unavailable" errors during peak times.
  • Rate Limiting: Most APIs have a limit on how many requests you can send per minute. If you exceed this, the API will reject your request.
  • Cost Management: A fallback allows you to switch from a high-cost model (like GPT-4) to a lower-cost model (like GPT-3.5) if the primary service is struggling or if the task doesn't require high intelligence.

Step-by-step walkthrough

The most efficient way to handle these issues in Python is by using a library called tenacity for retries and standard try-except blocks for fallbacks.

1. Setting up your environment

First, install the necessary libraries. We will use openai for the API and tenacity for the retry logic.


pip install openai tenacity

2. Implementing Retries

A retry policy tells your code to try the request again if it fails. However, you shouldn't just retry immediately; you should use "Exponential Backoff." This means the wait time increases between each attempt, giving the server time to recover.

3. Implementing Fallbacks

A fallback is your "Plan B." If the retries for your primary model (e.g., GPT-4) still fail, the code should automatically switch to a different model or provider to ensure the user gets a response.

Code Example: Combined Strategy


import openai
from tenacity import retry, stop_after_attempt, wait_random_exponential, retry_if_exception_type

client = openai.OpenAI(api_key="YOUR_API_KEY")

# Retry logic: Wait 1-20s between tries, stop after 3 attempts
@retry(
    wait=wait_random_exponential(min=1, max=20), 
    stop=stop_after_attempt(3),
    retry=retry_if_exception_type(openai.RateLimitError)
)
def call_primary_model(prompt):
    return client.chat.completions.create(
        model="gpt-4",
        messages=[{"role": "user", "content": prompt}]
    )

def smart_llm_call(prompt):
    try:
        # Try the primary model with retries
        return call_primary_model(prompt)
    except Exception as e:
        print(f"Primary failed after retries. Switching to fallback. Error: {e}")
        # Fallback to a faster, more available model
        return client.chat.completions.create(
            model="gpt-3.5-turbo",
            messages=[{"role": "user", "content": prompt}]
        )

# Usage
response = smart_llm_call("Explain quantum physics in one sentence.")
print(response.choices[0].message.content)

Common mistakes

  • Retrying on the wrong errors: Never retry on a "401 Unauthorized" or "400 Bad Request" error. These mean your API key is wrong or your prompt is formatted incorrectly; retrying will never fix that.
  • Infinite loops: Always set a stop_after_attempt limit. Without it, your code could run forever, draining your credits or crashing your server.
  • Missing timeouts: If the API hangs without sending an error, your code might sit waiting forever. Always set a timeout parameter in your API call.
