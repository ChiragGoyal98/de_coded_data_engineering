Interacting with Large Language Models (LLMs) through APIs is a core skill for modern developers. Whether you are using OpenAI, Anthropic, or Google Gemini, your application sends a request over the internet and waits for a response. However, unlike traditional databases, these APIs frequently encounter issues like rate limits, server overloads, or temporary connectivity blips. Learning how to handle these interruptions gracefully ensures your application remains stable even when the API provider is having a bad day.

Why it matters

When building production-ready applications, you cannot assume an API will always return a "200 OK" status. LLM providers often impose rate limits (how many requests you can send per minute) and can experience high latency during peak hours.

  • Reliability: Retries prevent your application from crashing due to a one-second network flicker.
  • User Experience: Instead of showing an error message, your app can try again in the background or switch to a faster model.
  • Cost Management: Fallbacks allow you to use a high-end model (like GPT-4) as a primary choice, but switch to a cheaper model (like GPT-3.5 or Haiku) if the primary one is unavailable or too slow.

Step-by-step walkthrough

1. Setting up the environment

To handle retries effectively in Python, the library tenacity is the industry standard. It allows you to add decorators to your functions to retry them under specific conditions. You will also need the library of your chosen LLM provider.


pip install openai tenacity

2. Implementing Retries

A "Retry" logic tells your code: "If this fails, wait a moment and try again." We use "Exponential Backoff," which means we wait longer between each successive attempt to avoid spamming the server.

3. Implementing Fallbacks

A "Fallback" is your Plan B. If the primary model fails after all retry attempts, your code should catch that error and attempt the request using a different model or provider.

Code Example: Retries and Fallbacks


import openai
from tenacity import retry, stop_after_attempt, wait_random_exponential

client = openai.OpenAI(api_key="your_api_key")

# The retry decorator handles temporary API errors
@retry(wait=wait_random_exponential(min=1, max=60), stop=stop_after_attempt(3))
def call_llm(model_name, prompt):
    response = client.chat.completions.create(
        model=model_name,
        messages=[{"role": "user", "content": prompt}]
    )
    return response.choices[0].message.content

def safe_generate_text(prompt):
    try:
        # Primary attempt with a powerful model
        return call_llm("gpt-4", prompt)
    except Exception as e:
        print(f"Primary model failed: {e}. Switching to fallback...")
        # Fallback attempt with a smaller, more available model
        return call_llm("gpt-3.5-turbo", prompt)

result = safe_generate_text("Explain quantum physics in one sentence.")
print(result)

Common mistakes

  • Retrying on 401 Errors: Do not retry if the error is "Unauthorized" or "Invalid API Key." Retrying will not fix a wrong password; it only wastes time.
  • Infinite Retries: Always set a stop_after_attempt limit. Without it, your code could get stuck in an infinite loop, consuming resources and potentially locking your account.
  • No Timeouts: LLM requests can sometimes "hang." Always set a timeout in your API call so the code doesn't wait forever for a response that is never coming.
  • Ignoring Local Errors: Sometimes the failure is in your code (like a logic error) rather than the API. Retrying won't help if the prompt itself is formatted incorrectly.

One practice task

Create a Python script that attempts to summarize a paragraph using an LLM. Use the tenacity library to retry the request 5 times with exponential backoff. If all 5 attempts fail, the script should print a message saying "Service currently unavailable, please try again later" instead of crashing.
