Calling LLM APIs from Python with retries and fallbacks

Building applications that rely on Large Language Models requires more than just sending a prompt and receiving a response. In a real-world environment, network connections can drop, API providers can experience downtime, and rate limits can be triggered by high traffic. If your code assumes every request will succeed on the first try, your application will be fragile and prone to crashing. Learning how to manage these disruptions through automated retries and fallback models is a core skill for any developer working in the AI space.

Why it matters

Reliability is the primary reason to implement these patterns. LLM APIs are managed services, meaning they are subject to "flaky" behavior. You might encounter a 429 error (Too Many Requests) because you exceeded your quota, or a 500 error (Internal Server Error) because the provider's server is momentarily overwhelmed.

By implementing a retry strategy, your code can automatically wait a few seconds and try again, which often resolves temporary issues. Fallbacks go a step further; if your primary model (like GPT-4) is completely down, your code can automatically switch to a secondary model (like GPT-3.5 or a local Llama model) to ensure the user still gets a response, even if it is from a slightly less capable engine.

Step-by-step walkthrough

To handle these scenarios in Python, the most efficient way is to use a library called tenacity for retries, combined with standard conditional logic for fallbacks.

1. Install the necessary libraries

You will need the OpenAI Python library (or your provider of choice) and Tenacity.


pip install openai tenacity

2. Setting up the Retry Logic

The tenacity library uses "decorators" to wrap your functions. You can define how many times to retry and how long to wait between attempts using "exponential backoff"-a method where the wait time increases after each failure to avoid spamming the server.

3. Implementing the Code

In this example, we will attempt to call a primary model. If it fails after three attempts, we will catch the error and call a fallback model instead.


import os
from openai import OpenAI
from tenacity import retry, stop_after_attempt, wait_random_exponential, retry_if_exception_type

client = OpenAI(api_key="YOUR_API_KEY")

# Define which errors should trigger a retry (e.g., Rate Limits or Server Errors)
@retry(
    wait=wait_random_exponential(min=1, max=60), 
    stop=stop_after_attempt(3)
)
def call_llm_with_retry(model_name, prompt):
    response = client.chat.completions.create(
        model=model_name,
        messages=[{"role": "user", "content": prompt}]
    )
    return response.choices[0].message.content

def safe_llm_call(prompt):
    try:
        # Try the expensive/primary model first
        return call_llm_with_retry("gpt-4", prompt)
    except Exception as e:
        print(f"Primary model failed: {e}. Switching to fallback.")
        # Fallback to a cheaper/faster model
        return call_llm_with_retry("gpt-3.5-turbo", prompt)

# Usage
result = safe_llm_call("Explain quantum physics in one sentence.")
print(result)

Common mistakes

  • Retrying on Authentication Errors: Do not configure your code to retry if the error is a 401 (Unauthorized). If your API key is wrong, retrying 10 times will not fix it and may lead to your account being flagged.
  • Infinite Loops: Always set a stop_after_attempt limit. Without a cap, a sustained outage could cause your script to run forever, consuming local resources.
  • Ignoring Backoff: If you hit a rate limit and retry immediately (0 seconds delay), you will likely hit the limit again. Always use exponential backoff to give the API "room to breathe."
  • Hardcoding API Keys: Beginner developers often leave their keys in the code. Always use environment variables (os.getenv) to keep your credentials secure.

Use a print statement inside the function so you can see the retries happening in your terminal before the final error message appears.
