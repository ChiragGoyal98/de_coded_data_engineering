Calling LLM APIs from Python with retries and fallbacks

Interacting with Large Language Models (LLMs) via APIs is a cornerstone of modern AI development. However, relying on external services means dealing with unpredictable network latencies, rate limits, and occasional server downtime. In a production environment, a simple script that crashes when an API is busy is not viable. Building resilient code ensures that your application remains functional even when the service provider experiences hiccups.

Why it matters

When you call an API like OpenAI or Anthropic, several things can go wrong. The server might be overloaded (HTTP 503), you might have sent too many requests (HTTP 429), or your internet connection might flicker.

Without a strategy to handle these events:

  • User Experience suffers: Your app shows an error message instead of an answer.
  • Data Loss: If you are processing a large dataset, a single failure might stop the entire script.
  • High Costs: Failing to handle specific errors might lead to unnecessary repeated requests that still count against your quota.

Implementing retries allows your code to "try again" after a brief pause, while fallbacks allow your code to switch to a different model or service if the primary one is completely unavailable.

Step-by-step walkthrough

1. Setting up the environment

First, you need the official library for the LLM and a dedicated retry library. While you can write your own while loops, the library tenacity is the industry standard for handling retries in Python.


pip install openai tenacity

2. Implementing Retries

The goal of a retry is to wait and try again when a transient error occurs. We use "exponential backoff," which means we wait longer after each subsequent failure to give the API time to recover.


from openai import OpenAI
from tenacity import retry, stop_after_attempt, wait_random_exponential

client = OpenAI(api_key="your_api_key")

@retry(wait=wait_random_exponential(min=1, max=60), stop=stop_after_attempt(3))
def call_llm_with_retry(prompt):
    return client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}]
    )

In this snippet, tenacity will catch errors and retry up to 3 times, waiting a random amount of time between 1 and 60 seconds between tries.

3. Implementing Fallbacks

A fallback is your "Plan B." If GPT-4o is down or hitting rate limits consistently, you might want to switch to a faster, cheaper, or more available model like GPT-4o-mini.


def robust_llm_call(prompt):
    try:
        # Attempt primary model with retries
        return call_llm_with_retry(prompt)
    except Exception as e:
        print(f"Primary model failed: {e}. Switching to fallback...")
        # Fallback to a different model
        return client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": prompt}]
        )

Common mistakes

  • Retrying on every error: Do not retry if the error is a "401 Unauthorized" (wrong API key) or "400 Bad Request" (invalid prompt). Retrying these will never work and only wastes time.
  • Fixed wait times: If you and 1,000 other developers all retry exactly 2 seconds after a crash, the API server will be hit by a "thundering herd," causing it to crash again. Always use "jitter" (randomized wait times).
  • Infinite loops: Always set a stop_after_attempt limit. You don't want your script running for hours because an API is down for maintenance.
  • Ignoring logs: If your fallback kicks in, you should log that event. Otherwise, you might be using a lower-quality model for days without realizing your primary model is failing.

One practice task

Create a Python script that attempts to summarize a paragraph of text.

  • Use the tenacity library to attempt the call 3 times.
  • If all 3 attempts fail, catch the exception and print: "Switching to backup system."
  • In the backup block, instead of calling an API, simply return the first 50 characters of the text as a "dummy" summary.

This exercise will help you visualize the flow from a primary attempt to a local safety net.
