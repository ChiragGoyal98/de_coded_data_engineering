Calling LLM APIs from Python with retries and fallbacks

When building applications with Large Language Models (LLMs), your code spends a lot of time waiting for data to travel across the internet. Unlike local functions that execute instantly, API calls are subject to external factors like server outages, network hiccups, and rate limits. Learning how to handle these interruptions gracefully is the difference between a fragile script that crashes and a production-ready application that stays running even when things go wrong.

Why it matters

Reliability is the cornerstone of any software. When you connect to an LLM provider like OpenAI or Anthropic, you are dealing with a shared resource. If too many people use the service at once, you might receive a "Rate Limit" error.

Without a retry strategy, a single failed request terminates your entire program. Without a fallback strategy, you are entirely dependent on one specific model being available. By implementing these patterns, you ensure that your application can self-heal from temporary glitches and switch to a secondary model if the primary one experiences a prolonged outage.

Step-by-step walkthrough

Handling these errors manually with if statements and while loops can make your code messy. The most professional way to handle this in Python is by using a library called tenacity for retries and standard try-except blocks for fallbacks.

1. Install necessary libraries

You will need the official API client and the retry library.

  • pip install openai tenacity

2. Define the Retry Logic

The tenacity library uses "decorators." These are labels you put above a function to tell Python to run it multiple times if it fails. You can set a maximum number of attempts and a "wait" time that increases (exponential backoff) so you don't overwhelm the server.

3. Implement the Fallback

A fallback is your "Plan B." If the expensive or high-performance model (like GPT-4) fails consistently, you can catch that error and attempt the same request using a faster, more available model (like GPT-3.5 or a local model).

Code Example: Robust LLM Call


import openai
from tenacity import retry, stop_after_attempt, wait_random_exponential

client = openai.OpenAI(api_key="your_api_key_here")

# This decorator will retry the function up to 3 times with a random delay
@retry(wait=wait_random_exponential(min=1, max=60), stop=stop_after_attempt(3))
def get_completion(model_name, prompt):
    return client.chat.completions.create(
        model=model_name,
        messages=[{"role": "user", "content": prompt}]
    )

def safe_llm_call(prompt):
    try:
        # Attempt primary model
        return get_completion("gpt-4", prompt)
    except Exception as e:
        print(f"Primary model failed: {e}. Switching to fallback...")
        # Fallback to a different model
        return get_completion("gpt-3.5-turbo", prompt)

Common mistakes

  • Retrying indefinitely: Never set your retries to infinite. If the API is down for maintenance, your code will get stuck in a loop forever, potentially costing you money or compute resources.
  • Ignoring the error type: Not all errors should be retried. If you have a "Syntax Error" or an "Invalid API Key," retrying 10 times won't fix it. Only retry on network timeouts or rate limits (HTTP 429).
  • Hardcoding API Keys: Beginner developers often leave their keys in the code. Always use environment variables or a .env file to keep your credentials safe while testing your retry logic.
  • No logging: If your fallback triggers, you should log it. Otherwise, you might not realize your primary model has been failing for days.

One practice task

Create a Python script that uses the structure above to summarize a paragraph of text. To simulate a failure, write a custom function that purposefully throws a ConnectionError the first two times it is called, but succeeds on the third. Use the tenacity library to ensure your script finishes successfully despite those initial "fake" failures.
