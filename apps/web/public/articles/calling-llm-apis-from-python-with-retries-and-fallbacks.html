Calling LLM APIs from Python with retries and fallbacks

When you start building applications with Large Language Models, the first thing you learn is how to send a prompt and get a response. However, the real world is messy. Internet connections flicker, AI providers experience sudden surges in traffic, and sometimes you hit "rate limits" because you are sending too many requests too fast. If your code isn't prepared for these hiccups, your entire application will crash just because of a temporary blip.

Why it matters

Building a production-ready application requires "resilience." This means your code should be smart enough to try again if a failure is temporary (Retries) or switch to a backup plan if a specific model is completely unavailable (Fallbacks). Without these patterns, a single "503 Service Unavailable" error from an AI provider results in a broken experience for your users. By implementing these strategies, you ensure that your app stays functional even when the underlying infrastructure is having a bad day.

Step-by-step walkthrough

To handle these issues efficiently in Python, the most popular tool is a library called tenacity. It allows you to add retry logic using simple "decorators" that sit on top of your functions.

1. Setting up the environment

First, you will need to install the necessary libraries. We will use the OpenAI library for the API calls and Tenacity for the logic.


pip install openai tenacity

2. Implementing Retries

A retry policy tells your code: "If this fails with a specific error, wait a moment and try again." We use "exponential backoff," which means the code waits longer between each attempt to avoid overwhelming the server.


import openai
from tenacity import retry, stop_after_attempt, wait_random_exponential, retry_if_exception_type

client = openai.OpenAI(api_key="your-api-key")

@retry(
    stop=stop_after_attempt(3), 
    wait=wait_random_exponential(min=1, max=60),
    retry=retry_if_exception_type(openai.RateLimitError)
)
def get_completion(prompt):
    return client.chat.completions.create(
        model="gpt-3.5-turbo",
        messages=[{"role": "user", "content": prompt}]
    )

In this example, if we hit a Rate Limit, the code will try up to 3 times, waiting a random amount of time between attempts.

3. Implementing Fallbacks

A fallback is your "Plan B." If your primary model (like GPT-4) is down or too expensive, you can catch the error and try a different, more reliable model (like GPT-3.5 or a local Llama model).


def safe_ai_call(prompt):
    try:
        # Try the premium model first
        return get_completion(prompt, model="gpt-4")
    except Exception as e:
        print(f"Primary model failed: {e}. Switching to fallback...")
        # Fallback to a cheaper/faster model
        return get_completion(prompt, model="gpt-3.5-turbo")

Common mistakes

  • Retrying on the wrong errors: Never retry if the error is a "401 Unauthorized" (your API key is wrong) or a "400 Bad Request" (your prompt is formatted incorrectly). Retrying these will never fix the problem and will just waste time.
  • Infinite loops: Always set a stop_after_attempt limit. Without it, your code might loop forever if the API provider has a major multi-hour outage.
  • Hardcoding API Keys: Beginners often leave their keys in the code. Always use environment variables or a .env file to keep your credentials safe while testing retries.

One practice task

Create a Python script that attempts to call an LLM API. Wrap the call in a try/except block. If the call fails, make the script print "Attempting fallback..." and then call a dummy function that returns a hardcoded string like "This is a backup response." This simulates a fallback for when the internet is completely offline.
