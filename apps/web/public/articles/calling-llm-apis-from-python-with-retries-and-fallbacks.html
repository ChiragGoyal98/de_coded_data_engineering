Calling LLM APIs from Python with retries and fallbacks

Building production-ready applications with Large Language Models (LLMs) requires moving beyond simple script execution. While it is easy to send a single request to an API like OpenAI or Anthropic, the real world is messy. Network flickers, rate limits, and temporary server outages can cause your application to crash if you are not prepared. To build a resilient system, you need to implement strategies that allow your code to recover automatically from these hiccups.

Why it matters

Reliability is the foundation of any professional software. When using LLM APIs, you are relying on a third-party service over a network, which introduces several points of failure.

  • Rate Limiting: Most providers restrict how many requests you can send per minute. Without retries, a single busy second could break your entire workflow.
  • Service Availability: Even the largest providers experience downtime or "overloaded" states.
  • Cost and Performance: A fallback mechanism allows you to switch to a cheaper or faster model if your primary, high-end model is currently unavailable or failing.
  • User Experience: Users prefer a slight delay (caused by a retry) over a "Something went wrong" error message.

Step-by-step walkthrough

To handle these issues effectively, we will use a popular Python library called tenacity for retries and a simple try-except logic for fallbacks.

1. Setting up the environment

First, you need to install the necessary libraries. We will use openai as our example provider and tenacity for our retry logic.


pip install openai tenacity

2. Implementing Retries with Tenacity

The tenacity library uses decorators to wrap functions. This allows you to define exactly how many times to retry and how long to wait between attempts using "exponential backoff"-waiting longer after each subsequent failure to give the API time to recover.

3. Adding Fallback Logic

A fallback is your "Plan B." If the primary model (e.g., GPT-4) fails even after multiple retries, your code should automatically attempt the request using a different model (e.g., GPT-3.5 or a local model).

Code Example: Resilient API Call


import openai
from tenacity import retry, stop_after_attempt, wait_random_exponential

client = openai.OpenAI(api_key="your_api_key_here")

@retry(wait=wait_random_exponential(min=1, max=60), stop=stop_after_attempt(3))
def call_llm_with_retry(model, prompt):
    # This function will retry up to 3 times if an API error occurs
    return client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}]
    )

def smart_llm_request(prompt):
    try:
        # Attempt Plan A: High-quality model
        print("Attempting primary model...")
        return call_llm_with_retry("gpt-4", prompt)
    except Exception as e:
        print(f"Primary model failed: {e}. Switching to fallback...")
        # Attempt Plan B: Faster/Cheaper fallback model
        return call_llm_with_retry("gpt-3.5-turbo", prompt)

# Usage
response = smart_llm_request("Explain quantum physics in one sentence.")
print(response.choices[0].message.content)

Common mistakes

  • Retrying on user errors: Do not retry if the error is a 400 Bad Request (like a prompt being too long). Retries should only happen for 429 (Rate Limit) or 500+ (Server Error) codes.
  • Infinite loops: Always set a stop_after_attempt limit. Retrying forever will just hang your application and potentially waste money.
  • Hardcoding API keys: Beginners often leave keys in the code. Always use environment variables or a .env file.
  • Ignoring the Thundering Herd: If you have 100 users all retrying at the exact same second, you will stay rate-limited. Using wait_random_exponential adds "jitter," which spreads out the requests.

One practice task

Create a Python script that attempts to summarize a paragraph of text. Implement a retry strategy that triggers only if a RateLimitError occurs. If the summary fails after two retries, have the script "fallback" by simply returning the first 50 words of the original text with a disclaimer that the AI was unavailable.
