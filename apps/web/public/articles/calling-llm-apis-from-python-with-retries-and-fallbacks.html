Calling LLM APIs from Python with retries and fallbacks

When building applications with Large Language Models, you quickly realize that the internet and remote servers can be unpredictable. You might write perfect Python code, but the API you are calling might be busy, or your internet connection might flicker for a split second. To build a production-ready application, you need to ensure your code can handle these hiccups gracefully without crashing or leaving the user hanging.

Why it matters

Reliability is the difference between a toy project and a professional tool. LLM APIs often face three main challenges:

  • Rate Limiting: Providers limit how many requests you can send per minute. If you exceed this, the API will temporarily reject your calls.
  • Server Downtime: Even the biggest providers like OpenAI or Anthropic experience occasional outages or high-latency periods.
  • Transient Errors: Random network blips can cause a request to fail once, but work perfectly if attempted a second later.

By implementing retries, your application stays resilient against temporary network issues. By implementing fallbacks, your application stays functional even if your primary model provider goes offline entirely.

Step-by-step walkthrough

To handle these issues, we will use the openai library for the API calls and a popular library called tenacity for the retry logic.

1. Setting up your environment

First, you need to install the necessary libraries. Open your terminal and run:


pip install openai tenacity

2. Implementing Retries

The tenacity library allows us to wrap our functions with "decorators" that automatically retry the code if it fails. We want to use exponential backoff, which means the code waits longer between each attempt (e.g., 1 second, then 2, then 4) to avoid overwhelming the API.

3. Implementing Fallbacks

A fallback is a "Plan B." If the primary model (like GPT-4) fails repeatedly, we catch the error and try a different model (like GPT-3.5) or a different provider entirely.


import openai
from tenacity import retry, wait_random_exponential, stop_after_attempt

client = openai.OpenAI(api_key="YOUR_API_KEY")

@retry(wait=wait_random_exponential(min=1, max=60), stop=stop_after_attempt(3))
def call_llm_with_retry(model, prompt):
    # This function will automatically retry up to 3 times if it fails
    response = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}]
    )
    return response.choices[0].message.content

def safe_llm_call(prompt):
    try:
        # Attempt 1: The primary, high-quality model
        print("Attempting primary model...")
        return call_llm_with_retry("gpt-4", prompt)
    except Exception as e:
        print(f"Primary model failed: {e}")
        # Fallback: A faster, cheaper model
        print("Attempting fallback model...")
        return call_llm_with_retry("gpt-3.5-turbo", prompt)

# Usage
result = safe_llm_call("Explain how a battery works in one sentence.")
print(result)

Common mistakes

  • Retrying on the wrong errors: Do not retry if the error is a "401 Unauthorized" (wrong API key). Retries only help with "500" series server errors or "429" Rate Limit errors.
  • Infinite Loops: Always set a stop_after_attempt limit. Retrying forever will just burn through your computer's resources and potentially get your IP address flagged by the provider.
  • Ignoring Costs: If your fallback model is significantly more expensive than your primary model, you might get a surprise bill. Always know the pricing of your backup options.

One practice task

Create a Python script that attempts to summarize a paragraph of text. Implement a retry strategy that waits exactly 2 seconds between attempts and tries a maximum of 5 times. If all 5 attempts fail, instead of letting the program crash, the script should return a string that says: "The summary is currently unavailable. Please try again later."
