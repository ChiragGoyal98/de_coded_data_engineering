Calling LLM APIs from Python with retries and fallbacks

Published: May 31, 2026 • 3 min read

DE-Coded Lab: Building Bulletproof LLM Apps with Retries and Fallbacks

Welcome back to DE-Coded Lab! If you've started building apps with Large Language Models (LLMs), you've likely encountered a frustrating reality: APIs are not 100% reliable. Sometimes the server is busy, sometimes you hit a rate limit, and sometimes the connection just drops.

In this tutorial, we are going to learn how to move past "fragile" code and build a robust Python setup that handles errors gracefully using Retries and Fallbacks.

Why It Matters

When you call an API like OpenAI, Anthropic, or Google Gemini, several things can go wrong:

  • Rate Limiting: You've sent too many requests too quickly.
  • Server Overload: The AI provider is experiencing high traffic.
  • Network Glitches: Your internet connection flickers for a second.

If your code isn't prepared, your entire application will crash. Retries allow your code to "try again" automatically after a short wait. Fallbacks provide a "Plan B," such as switching to a cheaper or faster model if the primary one is unavailable.

Step-by-Step Walkthrough

1. The Setup

We will use the openai library for the API and a popular library called tenacity to handle our retry logic.


pip install openai tenacity

2. Implementing Retries

A "Retry" should usually follow an Exponential Backoff strategy. This means if the first attempt fails, the code waits 1 second; if it fails again, it waits 2 seconds, then 4, and so on. This prevents you from "spamming" a server that is already struggling.

3. Implementing Fallbacks

A "Fallback" is a secondary function. If GPT-4o fails after all retry attempts, your code should automatically try a different model (like GPT-4o-mini) to ensure the user still gets an answer.

4. The Code Example

Here is a robust script that combines both concepts.


import openai
from tenacity import retry, stop_after_attempt, wait_exponential, retry_if_exception_type

client = openai.OpenAI(api_key="YOUR_API_KEY")

# 1. Define the Retry Logic
@retry(
    stop=stop_after_attempt(3), 
    wait=wait_exponential(multiplier=1, min=2, max=10),
    retry=retry_if_exception_type(openai.RateLimitError)
)
def call_primary_llm(prompt):
    print("Attempting to call Primary Model (GPT-4o)...")
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}]
    )
    return response.choices[0].message.content

# 2. Define the Fallback Logic
def robust_llm_call(prompt):
    try:
        # Try the primary model first
        return call_primary_llm(prompt)
    except Exception as e:
        print(f"Primary model failed: {e}. Switching to Fallback...")
        # Fallback to a different, more available model
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": prompt}]
        )
        return response.choices[0].message.content

# Usage
result = robust_llm_call("Explain quantum physics to a five-year-old.")
print(f"Final Result: {result}")

Common Mistakes

  • Retrying on Authentication Errors: If your API key is wrong, retrying 10 times won't fix it. Only retry on "Retriable" errors like RateLimitError or ServiceUnavailableError.
  • Infinite Retries: Never set your retries to infinite. If the service is down for an hour, your program will just hang forever. Always set a stopafterattempt limit.
  • Hardcoding Keys: Never paste your API key directly into the script. Use environment variables or a .env file to keep your credentials safe.
