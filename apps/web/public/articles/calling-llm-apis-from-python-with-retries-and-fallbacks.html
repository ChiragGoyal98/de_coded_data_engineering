Calling LLM APIs from Python with retries and fallbacks

When building applications that rely on Large Language Models (LLMs), developers quickly realize that external APIs are not 100% reliable. Network hiccups, temporary server overloads, or hitting rate limits can cause your code to crash if you do not handle these interruptions gracefully. Building a resilient connection involves more than just sending a request; it requires a strategy to try again when things go wrong and a backup plan for when they stay wrong.

Why it matters

In a local development environment, an API error is a minor annoyance. In a production environment, it results in a broken user experience. Implementing retries and fallbacks is essential for several reasons:

  • Handling Rate Limits: LLM providers impose limits on how many requests you can send per minute. Retries with "backoff" logic allow your application to wait and try again once the window resets.
  • Server Stability: Even the biggest providers experience "500 Internal Server Errors" during peak traffic. A quick retry often resolves the issue.
  • Cost and Availability: If a high-end model like GPT-4 is unavailable or too slow, falling back to a faster, cheaper model like GPT-3.5 or a local model ensures your application remains functional.
  • User Trust: Users are more likely to forgive a 2-second delay caused by a retry than a complete application crash.

Step-by-step walkthrough

To handle these scenarios in Python, we generally use the openai library alongside a powerful utility called tenacity, which simplifies the logic for retrying failed functions.

1. Install necessary libraries

First, ensure you have the required packages installed in your environment.


pip install openai tenacity

2. Implementing Exponential Backoff

Exponential backoff is a strategy where the wait time between retries increases doubling each time (e.g., 1s, 2s, 4s). This prevents you from spamming an already overloaded server.


from openai import OpenAI
from tenacity import retry, stop_after_attempt, wait_random_exponential

client = OpenAI(api_key="your_api_key")

@retry(wait=wait_random_exponential(min=1, max=60), stop=stop_after_attempt(3))
def call_llm_with_retry(prompt):
    return client.chat.completions.create(
        model="gpt-4",
        messages=[{"role": "user", "content": prompt}]
    )

3. Adding Fallback Logic

A fallback is your "Plan B." If the primary model fails after all retry attempts, you catch the error and attempt the call using a different model or a pre-written canned response.


def safe_llm_call(prompt):
    try:
        # Try the primary model first
        return call_llm_with_retry(prompt)
    except Exception as e:
        print(f"Primary model failed: {e}. Switching to fallback.")
        # Fallback to a smaller, more reliable model
        return client.chat.completions.create(
            model="gpt-3.5-turbo",
            messages=[{"role": "user", "content": prompt}]
        )

Common mistakes

  • Retrying on every error: You should only retry on "retryable" errors (like 429 Rate Limit or 500 Server Error). Retrying a 401 Unauthorized error is useless because the API key won't magically become valid on the second try.
  • Infinite loops: Never set your retries to "infinite." Always define a stop_after_attempt limit to prevent your code from hanging forever.
  • Ignoring logs: If your code is silently retrying in the background, you might not realize your primary model is failing 90% of the time. Always log when a retry or fallback occurs.
  • Hardcoding timeouts: Standard API calls can sometimes hang. Always set a explicit timeout parameter in your request to ensure your code regains control.

One practice task

Create a Python script that attempts to summarize a paragraph using an LLM. Use the tenacity library to retry the request 5 times if it fails. If all 5 attempts fail, the script should return a fallback string: "Service currently unavailable, please try again later." instead of crashing.
