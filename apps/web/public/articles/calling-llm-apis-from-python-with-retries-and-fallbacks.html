Calling LLM APIs from Python with retries and fallbacks

Integrating Large Language Models (LLMs) into your Python applications opens up incredible possibilities for automation and intelligence. However, relying on external APIs means your code is subject to the unpredictability of the internet and server-side stability. If an API provider experiences a momentary surge in traffic or your local network flickers, your application might crash or return an error to the user. Learning how to build resilient code that anticipates these failures is a fundamental skill for any AI developer.

Why it matters

Building "production-ready" AI applications requires more than just a clever prompt. It requires stability. When you call an LLM API, several things can go wrong: you might hit a rate limit (too many requests in a short time), the server might be temporarily overloaded (503 Service Unavailable), or a specific model might be undergoing maintenance.

Without retries, your program stops at the first sign of trouble. Without fallbacks, your application has no "Plan B" if the primary model is completely down. Implementing these patterns ensures that your user experience remains smooth and your application appears reliable, even when the underlying infrastructure is having a bad day.

Step-by-step walkthrough

The most efficient way to handle retries in Python is using a library called tenacity. It allows you to wrap your functions with "decorators" that define exactly how and when to try again.

1. Install necessary libraries

You will need the official API client (like openai) and the retry utility.


pip install openai tenacity

2. Implementing Exponential Backoff

Instead of retrying every one second, "exponential backoff" waits longer between each attempt. This gives the API provider time to recover and prevents you from being blocked for spamming.

3. Creating a Fallback Strategy

A fallback is your safety net. If your primary model (e.g., GPT-4o) fails after all retry attempts, your code should automatically try a cheaper or faster model (e.g., GPT-3.5 or a local model) to ensure the task still gets done.

Code Example: Resilient API Call


import openai
from tenacity import retry, stop_after_attempt, wait_random_exponential

client = openai.OpenAI(api_key="your_api_key_here")

# This decorator tells the function to retry up to 3 times
# It waits exponentially longer between tries (1s, 2s, 4s...)
@retry(wait=wait_random_exponential(min=1, max=60), stop=stop_after_attempt(3))
def call_primary_llm(prompt):
    return client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}]
    )

def get_llm_response(prompt):
    try:
        # Attempt the primary call with retries
        response = call_primary_llm(prompt)
        return response.choices[0].message.content
    except Exception as e:
        print(f"Primary failed after retries: {e}. Switching to fallback.")
        # Fallback logic: Use a more stable or cheaper model
        fallback_response = client.chat.completions.create(
            model="gpt-3.5-turbo",
            messages=[{"role": "user", "content": prompt}]
        )
        return fallback_response.choices[0].message.content

Common mistakes

  • Retrying on logic errors: Do not retry if the error is a "401 Unauthorized" or "400 Bad Request." These mean your API key is wrong or your prompt is formatted incorrectly; retrying will never fix these issues.
  • Infinite retries: Never set your retry limit to infinite. If a service is down for an hour, your script will hang forever and potentially rack up unexpected costs or memory usage.
  • Hard-coding keys: Beginners often paste their API keys directly into the retry logic. Always use environment variables to keep your keys secure while your code loops through attempts.
  • Ignoring timeouts: Sometimes an API doesn't "fail," it just hangs. Always set a timeout parameter in your API call so the retry logic knows when to give up and try again.

One practice task

Create a script that attempts to summarize a paragraph of text. Wrap your API call in a tenacity retry decorator that triggers only if the error message contains the words "Rate limit reached." If the function fails after 2 attempts, have the script print "System busy, please try again later" instead of crashing.
