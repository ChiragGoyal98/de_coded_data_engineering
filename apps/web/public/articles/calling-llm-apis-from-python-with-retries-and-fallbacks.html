Calling LLM APIs from Python with retries and fallbacks

When building applications powered by Large Language Models (LLMs), developers often rely on cloud-based APIs like OpenAI, Anthropic, or Google. While these services are powerful, they are not perfect. Network glitches, rate limits, or temporary server outages can cause your Python script to crash at any moment. To build a professional application, your code needs to handle these interruptions gracefully rather than just stopping.

Why it matters

In a production environment, reliability is everything. If your AI chatbot crashes every time OpenAI hits a rate limit, users will lose trust. Implementing retries ensures that temporary "hiccups" are handled automatically by waiting a few seconds and trying again.

Fallbacks go a step further by providing a "Plan B." If your primary model (like GPT-4) is completely down, your code can automatically switch to a secondary model (like GPT-3.5 or a local model) to keep the service running. This strategy minimizes downtime and improves the overall user experience.

Step-by-step walkthrough

1. Handling Retries with Tenacity

The most efficient way to handle retries in Python is using the tenacity library. It allows you to define how many times to retry and how long to wait between attempts.

First, install the necessary libraries:


pip install openai tenacity

Next, use the @retry decorator to wrap your API call. The wait_random_exponential strategy is best for APIs because it prevents "thundering herd" problems where many clients hit a recovering server at the exact same time.


import openai
from tenacity import retry, stop_after_attempt, wait_random_exponential

@retry(wait=wait_random_exponential(min=1, max=60), stop=stop_after_attempt(3))
def call_llm_with_retry(prompt):
    client = openai.OpenAI(api_key="your_api_key")
    return client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}]
    )

2. Implementing Fallbacks

A fallback mechanism uses a try-except block. If the primary function fails after all retry attempts, the code catches the error and tries a different model or provider.


def robust_llm_call(prompt):
    try:
        # Try primary model first
        return call_llm_with_retry(prompt)
    except Exception as e:
        print(f"Primary model failed: {e}. Switching to fallback...")
        # Fallback to a cheaper/faster model
        client = openai.OpenAI(api_key="your_api_key")
        return client.chat.completions.create(
            model="gpt-3.5-turbo",
            messages=[{"role": "user", "content": prompt}]
        )

Common mistakes

  • Infinite Loops: Not setting a stop_after_attempt limit can cause your code to run forever, potentially draining your API credits or freezing your app.
  • Hammering the Server: Retrying every 0.1 seconds (fixed interval) often makes rate limits worse. Always use exponential backoff to give the server "breathing room."
  • Catching Everything: Avoid using a blanket except Exception. It is better to catch specific API errors (like openai.RateLimitError) so you don't accidentally ignore bugs in your own code logic.
  • Ignoring Context: When falling back to a different model, remember that the "Plan B" model might have a different context window or formatting style.

One practice task

Create a Python script that attempts to call an LLM API. Implement a retry logic that triggers only on "Rate Limit" errors. If the API fails three times, have the script return a pre-written "safe response" (e.g., "I'm currently over capacity, please try again later.") instead of crashing the program.
