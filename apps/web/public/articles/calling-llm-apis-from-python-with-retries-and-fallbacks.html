Calling LLM APIs from Python with retries and fallbacks

Building applications with Large Language Models (LLMs) often feels magical until the network drops or the provider hits a rate limit. When working with external APIs, you are at the mercy of their uptime and traffic. A robust application needs to handle these hiccups gracefully. Instead of letting your app crash when an API call fails, you can implement strategies to try the request again or switch to a backup model. This tutorial explains how to build a resilient Python wrapper for your LLM calls using retries and fallbacks.

Why it matters

In a production environment, reliability is just as important as the quality of the model's response. LLM providers frequently experience "Rate Limit" errors (when you send too many requests too fast) or "Overloaded" errors (when their servers are busy).

If your code doesn't account for these:

  • User experience suffers: The app crashes or returns an ugly error message to the user.
  • Data is lost: A long-running automation script might stop halfway through, losing progress.
  • Costs increase: If you don't have a fallback to a cheaper model, a high-traffic spike on an expensive model might break your budget or your service availability.

Step-by-step walkthrough

We will use the tenacity library for retries, as it is the standard for adding retry logic to Python functions. We will also use a simple try-except structure to handle fallbacks.

1. Setting up your environment

First, you need to install the necessary libraries. We will use openai as our example provider.


pip install openai tenacity

2. Implementing Retries

A "retry" tells your code: "If this fails, wait a moment and try again." We use Exponential Backoff, which means we wait longer after each failed attempt to give the API server time to recover.


from openai import OpenAI
from tenacity import retry, stop_after_attempt, wait_random_exponential

client = OpenAI(api_key="your_api_key")

@retry(wait=wait_random_exponential(min=1, max=60), stop=stop_after_attempt(3))
def call_llm_with_retry(prompt):
    return client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}]
    )

In this snippet, tenacity will attempt the call up to 3 times. If it fails, it waits a random amount of time that grows exponentially (e.g., 1s, 2s, 4s) before giving up.

3. Implementing Fallbacks

A "fallback" is your Plan B. If your primary model (like GPT-4) is down or too busy, your code should automatically switch to a secondary model (like GPT-3.5 or a local Llama model).


def call_with_fallback(prompt):
    try:
        # Plan A: Try the powerful model
        return call_llm_with_retry(prompt)
    except Exception as e:
        print(f"Primary model failed: {e}. Switching to fallback...")
        # Plan B: Try a cheaper/faster model
        return client.chat.completions.create(
            model="gpt-3.5-turbo",
            messages=[{"role": "user", "content": prompt}]
        )

Common mistakes

  • Retrying on logic errors: Do not retry if the error is a "401 Unauthorized" (wrong API key) or "400 Bad Request" (syntax error). Retrying won't fix these; it will only waste time.
  • Infinite loops: Always set a stop_after_attempt limit. Without it, a permanent API outage could cause your script to run forever, potentially costing you money or compute resources.
  • Ignoring "Jitter": If you have 100 users all retrying at exactly the same 2-second interval, you will crash the server again. wait_random_exponential adds "jitter" (randomness) to prevent this "thundering herd" problem.

One practice task

Create a Python script that attempts to summarize a paragraph using an LLM.

  • Implement a retry strategy that tries 5 times.
  • If all 5 attempts fail, the script should fall back to a simple string function that just returns the first two sentences of the paragraph as a "pseudo-summary."

This ensures that even if the internet is completely out, your function returns something instead of crashing.
